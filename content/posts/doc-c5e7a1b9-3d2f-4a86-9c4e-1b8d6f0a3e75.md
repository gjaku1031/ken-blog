고객은 가입해서 주문하고 계좌로 입금하며, 운영자는 고객과 같은 화면에서 편집 모드를 켜 가게를 관리함.

## 주문 상태

```mermaid caption="주문을 만들 때 재고가 빠지고, 취소되면 돌아옴. 전액 환불은 운영자가 재입고를 고른 경우에만 재고를 되돌림. 취소와 전액 환불에서 나가는 전이는 없음"
    state "입금 확인" as PAID
    state "제작·배송 준비" as PROCESSING
    state "완료" as COMPLETED
    state "취소" as CANCELED
    state "전액 환불" as REFUNDED
    [*] --> PENDING: 주문 생성, 재고 차감
    PENDING --> PAID: 운영자가 입금 확인
    PENDING --> CANCELED: 고객·운영자 취소, 기한 경과
    PAID --> CANCELED: 운영자 취소
    PAID --> PROCESSING
    PROCESSING --> COMPLETED
    PAID --> REFUNDED
    PROCESSING --> REFUNDED
    COMPLETED --> REFUNDED
```

| 전이 | 누가 | 재고 |
| --- | --- | --- |
| 주문 생성 | 회원, 운영자(대리 주문)[* 대리 주문은 원 주문이 있는 고객 앞으로만 넣을 수 있음. 원 주문의 결제 수단, 연락처, 배송지를 그대로 쓰고, 주문자가 탈퇴했으면 409. 결제 대기 5건 제한은 받지 않음] | 수량만큼 뺌 |
| 결제 대기 → 입금 확인 | 운영자 | 그대로 |
| 결제 대기 → 취소 | 회원, 운영자, 주기 작업 | 되돌림 |
| 입금 확인 → 취소 | 운영자 | 되돌림 |
| 입금 확인·준비·완료 → 전액 환불 | 운영자 | 재입고를 고르면 되돌림 |

## 주문에서 입금 확인까지

```mermaid caption="주문할 때 재고가 빠지고 입금 기한이 정해짐. 운영자가 기한 안에 입금을 확인하면 다음 단계로 넘어가고, 그렇지 않으면 주기 작업이 주문을 취소하고 재고를 되돌림"
sequenceDiagram
    %% legend: solid=요청·처리; dotted=응답·안내
    participant U as 고객
    participant A as API
    participant O as 운영자
    participant S as 주기 작업
    U->>A: 주문
    A-->>U: 주문 번호, 입금 계좌, 입금 기한
    alt 기한 안에 입금을 확인함
        O->>A: 통장을 보고 입금 확인
        A-->>U: 내 주문에서 입금 확인 표시
    else 기한이 지남
        S->>A: 기한이 지난 결제 대기 주문 취소(5분마다 실행)
        A-->>U: 내 주문에서 취소 표시
    end
```

고객에게 보내는 알림은 없고 만들지 않기로 했음. 가입할 때 연락처를 받지 않아 알릴 수단이 없기 때문임. 기한과 취소는 주문 완료 화면과 내 주문에서만 볼 수 있어, 운영자의 첫 화면에 "입금 확인 대기"와 마감 배지를 두어 기한 전에 확인하게 함. 운영자는 결제 대기 주문의 기한을 주문별로 늘릴 수 있음. 회원 한 명이 둘 수 있는 결제 대기 주문은 5건이고, 여섯 번째 주문은 앞의 주문이 입금되거나 취소될 때까지 거절됨. 재고와 재고 이력이 어긋난 옵션이 있으면 운영자의 첫 화면 맨 위에 나옴.

여러 개 가운데 일부만 반품받는 경우는 수량 단위의 환불을 두지 않고, 원래 주문을 전액 환불로 닫은 뒤 남길 상품만 운영자가 고객 앞으로 새 주문을 넣음.

## 편집 모드

운영자가 상단의 편집 모드를 켜면 상품, 글, 공지, FAQ에 추가와 수정 단추가 나타남. 편집 모드는 화면의 표시 상태일 뿐이고 새로고침하면 꺼짐. 운영 요청의 권한은 서버가 요청마다 확인함. 주문, 회원, 설정, 운영 기록은 내 계정에서 다룸.

## 글쓰기

- 입력이 2초 멈추면 초안을 서버에 저장함. 브라우저에도 복구용 초안을 둠
- 공개된 글의 초안을 고쳐도 독자는 마지막 발행본을 봄. 발행을 눌러야 공개 내용이 바뀜
- 다른 화면에서 먼저 고친 경우에는 자동 저장을 멈추고 지금 내용을 보관함
- 저장이나 사진 업로드가 실패한 상태로는 발행할 수 없음. 발행하지 않은 글의 사진은 방문자에게 보이지 않음

## 사진 올리기

사진은 두 단계로 올림. 먼저 형식과 크기를 신고해 30분짜리 티켓을 받고, 실제 파일을 올리면 서버가 파일의 형식과 크기를 티켓과 대조한 뒤 원본과 세 크기의 변환본을 저장함. 변환에 실패한 사진은 저장하지 않음.

재고의 설계는 [입금 안 된 주문이 재고를 놓지 않던 쇼핑몰](/ken-blog/post/post-5d0f6c1e-7b3a-4c58-9e21-3f6a1d2b8c47/)에서, 사진의 변환은 [업로드할 때 세 크기로 변환하는 이미지 최적화](/ken-blog/post/post-8c2e4a97-1d5b-4f36-a0c9-6b7e2f4d1a83/)에서 다룸.
