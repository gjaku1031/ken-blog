# P0-04: 실행 이미지·개발 환경·문서 대문

상태: **계획 초안 — 승인 전** · 선행: P0-03 완료

## 문제

현재 앱은 각 터미널에서 직접 실행하는 형태. 함께 실행할 구성과 새 구조를 설명하는 공개 문서 대문 필요.

## 포함 범위

- Spring Boot의 Buildpacks로 JVM 실행 이미지 생성. API Dockerfile 추가 없음.
- Next standalone 실행 이미지와 두 앱만 연결하는 Docker Compose 구성.
- 환경변수 예시, 서비스 간 주소, 시작·종료·로그 확인·이미지 재생성 안내.
- 실제 컨테이너 기동과 Next → Spring 요청 확인. 측정 조건과 함께 메모리 사용량 기록.
- Next·Spring·Docker·OCI 공식 아이콘을 사용한 새 아키텍처 도면. 구현된 연결과 후속 MySQL·Redis·OCI Object Storage 구분.
- 현재 구조·실행 방법·도면을 담은 임시 GitHub Pages 대문과 배포 workflow.
- 공개 파일만 담은 Pages 산출물 확인. 로컬 학습 자료·환경 파일 포함 없음.

## 제외 범위

OCI 자원 생성·변경과 운영 서비스 교체, DB·로그인·Redis·첨부파일 연동, Native Image 전환, 완성된 블로그 디자인 포함하지 않음. Pages는 정적 문서용이며 Next·Spring 서버 실행 위치가 아님.

## 완료 조건

- [ ] 두 실행 이미지를 실제 빌드하고 격리된 Compose 프로젝트로 기동.
- [ ] Next 홈의 API 연결 정상 및 API 중지 시 안내 확인.
- [ ] 환경 설정·네트워크·종료 방법 문서와 실제 동작 일치.
- [ ] 메모리 측정 조건·결과·미검증 한계 기록.
- [ ] 라이트·다크 도면과 설명의 실제 구현 상태 일치.
- [ ] GitHub Pages 배포 성공 및 공개 URL 응답 확인.
- [ ] 학습 자료·환경 파일이 Git 및 Pages 산출물에 포함되지 않음.

## 검증 방법

실행 환경의 CPU 아키텍처와 Docker·Buildpacks 지원 확인 후 이미지 생성. 기존 컨테이너와 겹치지 않는 프로젝트명·포트 사용, 작업 중 만든 컨테이너만 종료. 앱별 CI와 Compose HTTP·브라우저 확인, Pages 산출물 목록 및 공개 페이지 확인. 실패한 빌드나 아직 측정하지 않은 수치를 완료로 기록하지 않음.

세부 이미지 버전·포트·메모리 설정은 승인 후 현재 환경에서 검증해 고정. 이번 문서는 다음 작업 제안이며 구현 완료 기록이 아님.
