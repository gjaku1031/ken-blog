# P1-01: MySQL·JPA·Flyway와 게시글 저장 기반

상태: **계획 초안 — 승인 전** · 선행: P0-04 완료

## 문제

현재 API에는 DB 연결과 게시글 저장 기능 없음. 기능별 화면과 로그인에 앞서 재현 가능한 스키마와 실제 MySQL 저장·조회 검증 필요.

## 포함 범위

- Spring의 MySQL·JPA·Flyway 의존성과 환경변수 기반 연결 설정.
- 개발용 MySQL Compose 구성과 격리된 데이터 볼륨. 기존 클라우드 DB·운영 데이터 변경 없음.
- Flyway 초기 마이그레이션과 JPA 스키마 검증. 앱 시작 시 자동 스키마 수정 사용 없음.
- 게시글의 ID·제목·고유 slug·초안 본문·생성 및 수정 시각을 담는 최소 모델.
- Spring Data JPA `PostRepository : JpaRepository<PostEntity, Long>` 인터페이스와 구체 `PostService`를 통한 저장·ID 및 slug 조회. 기본 CRUD는 상속하고 slug 조회만 파생 쿼리로 선언.
- 빈 제목·slug 중복 등 저장 계약과 예외 변환 경계 정의.
- 격리된 실제 MySQL로 마이그레이션·저장·재조회·실패·롤백 검증. H2 결과로 MySQL 호환성을 대신하지 않음.
- 실행 안내와 초보자 학습 문서 작성.

## 제외 범위

인증 없는 게시글 작성 API 공개, 로그인·권한·출간 기능, 완성된 에디터 형식, Redis·첨부파일 연동, 운영 DB 생성·마이그레이션 포함하지 않음. 초안 본문은 초기 저장용이며 이후 에디터의 블록 구조를 확정하는 단계가 아님.

## 완료 조건

- [ ] 환경변수로 개발 DB 연결, 비밀값 Git 제외.
- [ ] 빈 MySQL에 마이그레이션 적용 및 재시작 시 중복 실행 없음.
- [ ] Repository의 저장·조회와 DB 제약 조건 검증.
- [ ] 트랜잭션 실패 시 부분 저장 없음.
- [ ] 테스트 전용 DB 데이터가 기존 실행 환경과 분리됨.
- [ ] Kotlin 테스트·CI·문서 검토 완료.

## 검증 방법

ARM64 환경에서 사용할 수 있는 MySQL 이미지와 테스트 도구 호환성을 먼저 확인. 테스트용 컨테이너와 별도 DB를 사용하고 실제 설정값을 로그에 출력하지 않음. 마이그레이션·스키마 검증·동일 slug 충돌·트랜잭션 롤백을 실제 MySQL에서 실행. 이번에 만든 테스트 자원만 정리.

승인 후 스키마와 오류 계약을 구체화해 구현. 이번 문서는 다음 작업 제안이며 구현 완료 기록이 아님.
