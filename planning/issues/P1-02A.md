## 변경 범위

### 1. 미완성 JWT 작업 정리

- 기준 커밋의 세션 인증 계약과 사용자 요청으로 확정한 기능별 패키지 구조 유지.
- 미커밋 JWT 설정 클래스·OAuth2 Resource Server 의존성·JWT 환경변수·CI secret 참조 제거. 세션 계약에 맞지 않는 보안 설정을 선별 복구.
- README·규칙 문서·도면·학습 자료의 JWT 설명도 최종 JDBC 구성에 맞게 수정.
- 이번 전환과 무관한 변경을 덮어쓰는 전체 작업트리 초기화 없음. 기존 변경을 파일별로 대조해 정리.

### 2. Spring Session JDBC와 Flyway

- `spring-boot-starter-session-data-redis`를 `spring-boot-starter-session-jdbc`로 교체. 계정·게시글에서 사용하는 MySQL DataSource 공유.
- 현재 사용 버전의 Spring Session 공식 MySQL SQL을 확인해 `V3__create_spring_session_tables.sql` 추가.
- `SPRING_SESSION`과 `SPRING_SESSION_ATTRIBUTES`, 세션 ID·만료 시각 관련 인덱스 및 세션 삭제 시 속성 정리 제약 포함.
- `spring.session.jdbc.initialize-schema=never`로 두고 테이블 생성은 Flyway만 담당. 기존 V1·V2 수정 없음.
- 세션 엔티티·별도 Repository 인터페이스를 직접 구현하지 않음. Spring Session의 저장소 사용.

### 3. 유지할 인증 계약

| 항목 | 유지할 동작 |
| --- | --- |
| `GET /api/v1/auth/csrf` | 익명 세션의 CSRF 토큰·헤더명 반환 |
| `POST /api/v1/auth/login` | 쿠키·CSRF 검증, 계정 인증, 세션 ID 교체, 사용자 이름·역할 반환 |
| `GET /api/v1/auth/me` | 유효한 세션의 현재 사용자·역할 반환 |
| `POST /api/v1/auth/logout` | 인증·CSRF 검증 후 세션 무효화, 204 반환 |
| 로그인 이후 CSRF | 기존 토큰 제거, 새 토큰 취득 후 상태 변경 요청 |
| 권한 경계 | 미인증 401, 역할 부족·잘못된 CSRF 403 |
| 장애 응답 | 세션 DB 연결 실패 시 인증 성공이나 메모리 세션으로 우회하지 않고 안전한 503 ProblemDetail 반환. 필터와 MVC 양쪽의 실제 응답 확인 |
| 쿠키 | `KENBLOGSESSION`, HttpOnly, SameSite=Lax, Secure 기본 true. HTTP 로컬 검증에서만 명시적으로 false |
| CORS | 공개 상태 조회와 자격 증명 인증 요청의 기존 허용 origin 구분 유지 |
| 계정 | 초기 관리자 준비·BCrypt 해시·기존 계정 보존 정책 유지 |

Redis 전용 장애 필터는 제거하거나 실제 JDBC 장애 경계에 맞게 최소 수정. 연결 장애와 다른 업무·무결성 오류를 같은 503으로 뭉뚱그리지 않으며 내부 예외·접속 정보는 응답에 노출하지 않음.

### 4. 세션 만료·정리 정책

- 비활동 만료 30분 유지. 로그인 시각부터 무조건 30분이 아니라 마지막 접근을 기준으로 판단.
- Spring Session JDBC의 만료 세션 정리 작업을 매분 실행하도록 설정을 명시. 만료 여부 판단과 DB 행의 물리적 삭제 시점은 구분.
- 세션 정리 시 속성 행도 함께 삭제. 별도 배치 시스템이나 직접 만든 정리 스케줄러 도입 없음.
- API 재시작 후에도 DB에 저장된 유효 세션 유지. 로그아웃·만료된 세션은 이전 쿠키로 인증 불가.
- API가 정지한 동안 정리 작업은 실행되지 않음. 재기동 후 정리 재개. DB 장애 중에는 정리 지연 가능하며 인증을 임의로 허용하지 않음.
- 새 프로젝트의 Redis 세션 데이터를 MySQL로 이전하는 작업은 포함하지 않음. 기존 배포본의 세션·계정·데이터는 접근하거나 변경하지 않음.

### 5. 실행 구성과 문서

- 새 프로젝트의 Redis 의존성·연결 변수·namespace·Compose 서비스·CI Redis 서비스·테스트 컨테이너 제거.
- 개발 Compose는 API와 MySQL만 유지. Buildpacks 이미지 생성 방식 유지, 공개 포트 확대 없음.
- Redis Cloud는 후속 공개 데이터 캐시로만 도면에 표시. 연결·세션 저장·캐시 구현 없음.
- 기능별 패키지, Kotlin, 구체 Service·Spring Data JPA Repository 인터페이스·Swagger Controller 계약 인터페이스, KDoc 기준 유지.
- README, `docs/authentication.md`, `docs/runtime.md`, `docs/persistence.md`, 코드 규칙과 계획 상태 정리.
- 라이트·다크 도면과 Pages용 복사본을 JDBC 구조로 갱신. MySQL의 게시글·계정·세션 역할과 미연결 공개 API 표시.
- `docs/study/P1-02A.md`와 학습 목록에 쿠키·세션·JDBC·Flyway·만료·장애 흐름·실제 코드 해설 작성. 이전 P1-02 학습 자료는 최종 구성과 과거 검증을 구분. 학습 자료는 계속 Git 제외, 공개 배포 없음.

## 검증 계획

검증 대상은 전용 프로젝트 이름·DB·볼륨·로컬 포트를 사용하는 새 환경. 기존 컨테이너를 대상으로 장애를 발생시키지 않음.

1. `./mvnw -B -ntp -DskipTests clean package`로 운영 코드와 기존 테스트 컴파일·실행 JAR 생성 확인. 실행하지 않은 테스트를 통과로 기재하지 않음.
2. 격리 MySQL에 V1~V3 적용과 세션 테이블 확인. 다시 기동할 때 중복 생성이나 재마이그레이션 없는지 확인.
3. 실제 HTTP로 CSRF 취득→로그인→세션 ID 교체→현재 사용자→새 CSRF 취득→로그아웃→이전 쿠키 401 확인. 누락·잘못된 CSRF와 권한 경계 유지 확인.
4. 유효 세션을 가진 상태에서 **검증용 API만** 재시작하고 같은 쿠키의 현재 사용자 200 확인.
5. **검증용 MySQL만** 중단해 `/csrf`·`/login`·`/me` 등 세션 접근 경로의 503 ProblemDetail 확인. DB 복구 후 동작 확인. 연결 실패·타임아웃 동안 내부 정보 노출 없음 확인.
6. 30분 설정과 만료 행의 정리 정책 확인. 필요하면 테스트용 세션의 만료 시각만 단축해 만료 거부·정리 작업을 확인하고, 자연 상태로 30분 기다린 결과와 구분해 기록.
7. 새 소스로 Buildpacks 이미지 생성·격리 Compose의 API+MySQL 최소 기동 확인. 전체 HTTP 흐름을 변경 없이 반복하는 검증은 생략.
8. 수정한 기존 검사는 기존 CI에서 실행. 로컬 빌드·수동 HTTP·원격 CI 결과를 각각 구분. 공개 Pages 홈·도면 4개도 실제 배포 결과와 대조.
9. 검증용 프로세스·컨테이너·네트워크·전용 볼륨·임시 비밀 파일만 정리하고 기존 두 컨테이너의 시작 시각·상태 유지 확인.
