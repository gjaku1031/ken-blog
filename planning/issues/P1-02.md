# P1-02: Spring Security·로그인과 Redis 세션

상태: **승인됨 — 구현 진행 중** · 선행: P1-01 완료

## 문제

현재 게시글 저장 기반에는 사용자 인증과 권한 확인 없음. 글 작성 기능을 공개하기 전에 로그인·로그아웃·세션 만료·CSRF 보호와 관리자 권한 경계 필요.

## 포함 범위

- Spring Security와 Spring Session Data Redis를 통한 서버 세션 구성.
- 개발용 Redis를 Compose 내부 네트워크에 추가. 인터넷 공개 포트 없음.
- 관리자 계정의 저장·비밀번호 해시·권한 모델과 초기 계정 준비 절차 정의. 비밀값 외부 주입, 평문 비밀번호 저장·로그 출력 없음.
- 로그인·현재 사용자·로그아웃의 최소 API와 Swagger Controller 계약. 인증·접근 거부 응답의 ProblemDetail 일관성 유지.
- 세션 고정 공격 방지·로그아웃 무효화·만료, CSRF 토큰의 발급과 변경 요청 검증.
- 익명 접근·잘못된 비밀번호·권한 거부·세션 재사용·CSRF 누락·Redis 중단의 실제 통합 검증.
- 실제 Redis·MySQL로 격리된 로컬 검증과 실행·학습 문서 작성.

## 제외 범위

공개 회원가입·소셜 로그인·비밀번호 재설정·메일 전송·게시글 편집 화면·공개 운영 계정 생성·외부 Redis Cloud 연결 포함하지 않음. 공개 도메인과 HTTPS가 없는 상태에서 운영 로그인을 게시하지 않음.

## 승인 후 확정할 사항

- 초기 사용자를 관리자 한 명으로 제한할지, 다중 사용자 저장 모델부터 둘지 결정.
- 프론트와 API의 도메인 관계에 맞는 쿠키 SameSite·Secure·CORS 정책. GitHub Pages 기본 도메인과 별도 API 도메인은 브라우저의 타사 쿠키 제한 영향을 받을 수 있어 HTTPS와 도메인 구성 검토 필요.
- 개발 환경의 쿠키 설정과 운영 설정 분리. 운영에서 HTTPS·정확한 허용 origin 없이 자격 증명을 허용하지 않음.

## 완료 조건

- [ ] 비밀번호 해시 저장과 외부 주입, 익명 사용자 권한 제한.
- [ ] 정상 로그인·실패·로그아웃·세션 만료 검증.
- [ ] CSRF 누락·잘못된 토큰으로 상태 변경 불가.
- [ ] Redis 세션 저장·삭제와 장애 동작 검증.
- [ ] 인증·권한 오류의 ProblemDetail 계약 및 Kotlin 회귀 테스트 통과.
- [ ] 로컬 자료·설정·도면·CI를 실제 구현 상태와 일치시킴.

## 검증 방법

기존 운영 컨테이너와 분리된 MySQL·Redis 사용. 세션 쿠키와 CSRF 토큰의 실제 HTTP 흐름을 검증하되 테스트 계정과 세션 값을 공개 기록에 포함하지 않음. 공개 HTTPS 환경 검증은 주소 준비 후 별도 범위로 합의.

사용자의 다음 작업 진행 요청으로 P1-02 승인 확인. 초기 계정 범위는 관리자 한 명을 기본안으로 확인 중. 공개 도메인·HTTPS는 여전히 없으며 로컬 인증 검증까지 진행.

현재 구성을 반영한 도면·실행 안내·초보자 학습 자료도 함께 갱신. 커밋은 계정 저장 기반·인증과 세션·통합 검증 등 독립적으로 검토 가능한 변경 단위로 분리하며 같은 날짜의 복수 커밋 허용.
