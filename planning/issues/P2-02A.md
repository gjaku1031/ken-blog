# P2-02A 공개 원문과 분리된 편집본 저장

## 문제와 시작 상태

2026-09-26 확인: main·origin/main `fa86abc`, P2-01 CI 36223462342·Pages 36223462339 성공. 로컬 원본의 별도 PORT 계획 보존. 현재 게시글 PUT은 출간된 글의 원문도 즉시 바꾸는 계약. 이를 글쓰기의 임시저장에 직접 연결하면 저장만 해도 공개 내용이 바뀌므로 별도 편집본 저장 필요.

## 구현 범위

- `draft/domain`, `draft/repository`, `draft/service`, `draft/controller`, `draft/dto`의 관리자 편집본 자원. Kotlin·JpaRepository·구체 Service·Swagger Controller 계약·KDoc 유지.
- Flyway V8로 `editor_drafts` 저장. nullable 원본 게시글 ID, 원본 기준 수정 시각, 편집본 revision, 제목·slug·Markdown 원문·분류 ID·정렬 태그·공개 범위·생성/저장 시각 보관. 같은 원본에는 최대 하나의 편집본, 새 글 편집본은 여러 개 허용.
- 원본 게시글 삭제 시 연결 편집본 함께 제거. 분류는 편집 스냅샷의 참조로 보관하며 분류 삭제가 편집 원문을 변경하지 않음. 저장/출간 시 현재 분류 유효성 확인, 삭제된 분류로 출간은 404와 편집본 보존.
- 임시저장은 빈 제목/slug와 미완성 slug 허용, 길이·본문 1MiB·태그 상한 유지. 출간 시 기존 PostService의 엄격한 제목/slug 검증 적용. 태그는 기존 정규화 규칙, 범위는 PUBLIC/PRIVATE.
- 관리자 상세·본문 없는 페이지 목록·수동 덮어쓰기·삭제·출간. revision으로 오래된 화면의 덮어쓰기/삭제/출간을 409로 거부. 기존 원문을 편집하는 경우 원본 updatedAt 변경도 출간 시 409로 거부해 다른 수정을 덮지 않음.
- 출간은 제목·slug·본문·분류/태그·공개 범위 반영과 편집본 제거를 하나의 트랜잭션으로 처리. 실패 시 원문과 편집본 모두 이전 상태. 최초 출간 시각과 기존 공개 캐시의 커밋 후 무효화 유지.
- 기존 게시글 DRAFT/CRUD·분류·태그·ProblemDetail·JDBC 세션 계약 유지. `editor_drafts`는 기존 게시글 DRAFT 상태와 다른 작업 중 편집 스냅샷. 기존 행의 삭제/자동 전환 없음.
- 명시된 인증 origin에만 관리자 편집본 GET/POST/PUT/DELETE의 credential CORS 허용. ADMIN 권한·쓰기 CSRF·no-store 유지. 공개 origin의 관리자 읽기 허용 없음.

## HTTP 계약

기본 경로 `/api/v1/admin/editor-drafts`.

| 메서드·경로 | 입력·반환 |
| --- | --- |
| POST | `{postId,baseUpdatedAt,title,slug,body,categoryId,tags,visibility}` → 201 상세. `postId/baseUpdatedAt` 둘 다 명시 null이면 새 글. 기존 글은 양수 postId와 관리자 상세의 UTC updatedAt 문자열 필요. 현재 원본과 다르거나 이미 편집본이 있으면 409 |
| GET | `page=0&size=10`, 선택적 양수 `postId` → 본문 없는 items/page/size/totalElements/totalPages. 저장 시각·ID 내림차순 |
| GET `/{id}` | 편집본 상세 200, 부재 404 |
| PUT `/{id}` | `{revision,title,slug,body,categoryId,tags,visibility}` → 갱신된 상세. 원본 대상과 기준 시각은 변경하지 않음 |
| DELETE `/{id}?revision=...` | 현재 revision 일치 시 204, 오래된 revision 409 |
| POST `/{id}/publish` | `{revision}` → 최종 PostDetailResponse 200. 원자적으로 출간하고 편집본 제거 |

상세 필드: `id,revision,postId,baseUpdatedAt,title,slug,body,categoryId,tags,visibility,createdAt,updatedAt`. JSON 타입은 명시적 null·필수 문자열·태그 문자열 배열·정수 revision/ID를 엄격히 구분. 원본 updatedAt은 기존 API와 같은 UTC LocalDateTime 직렬화 계약. revision은 0 이상의 정수. 없는 ID 404, 입력 오류 400, 충돌 409, DB 장애 503의 기존 ProblemDetail 계열 유지.

## 완료 조건과 검증

1. 기존 28개 검사와 빌드 통과. 새 테스트 파일 없음, 기존 Flyway 기대 버전만 필요한 부분 수정.
2. 독립 MySQL에 V7 데이터→V8 마이그레이션 후 원본/태그/분류/세션 보존 확인. 신규 DB도 기존 검사로 확인.
3. 실제 HTTP로 새 글 저장·덮어쓰기·목록 본문 제외 SQL·재시작 후 복원·삭제·출간·최초 시각 유지 확인.
4. 출간 글의 편집본 저장/삭제가 공개 원문에 영향 없음. 성공 출간은 원문+분류+태그+범위 일치와 편집본 제거, 빈/잘못된 slug·중복 slug·삭제된 분류·원본 변경 실패에서는 원문과 편집본 보존 확인.
5. 오래된 revision의 PUT/DELETE/publish, 중복 원본 편집본 생성 경합, 쓰기/출간 경합을 확인. 분류→게시글→편집본의 잠금 순서를 일관되게 구성하고 DB 경합 오류는 안전한 409로 변환.
6. guest/USER 차단·CSRF·정확한 credential CORS·no-store·Swagger JSON 계약·DB 장애/복구 확인. Redis 공개 캐시는 후속 원문 공개 전환을 우회하지 않음.
7. 문서에 계획·검증·실제 배포를 구분, 임시 검증 자원 정리, 목적별 커밋과 main 정상 push·CI·Pages 확인. author date와 실제 검증/반영 날짜 분리.
