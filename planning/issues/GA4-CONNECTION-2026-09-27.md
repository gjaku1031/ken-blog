# GA4 운영 연결

## 요청·수용 기준

- 사용자가 전달한 GA4 연결 자료로 실제 운영 대시보드 보고서와 공개 페이지 수집 활성화.
- 숫자 속성 ID·서비스 계정 인증을 운영 환경에만 적용. 인증 파일 저장소 밖 0600, 원문·토큰 로그 노출 없음.
- 첨부 검증 기록은 참고 자료로만 사용하고 실제 OAuth·기간별 보고서·현재 웹 측정 ID 재확인.
- 관리자·글쓰기·비공개 콘텐츠의 기존 수집 제외 정책 유지. 실제 빈 기간을 목업 수치로 대체하지 않음.
- 운영 콘텐츠와 기존 API 이미지 보존. 설정 반영 뒤 공인 API health·기간별 대시보드·Pages 수집 확인.

## 진행

- 첨부 `.env`, 서비스 계정 JSON, 연결 정보, 검증 요약 구조 확인. 기존 운영 미연결 상태에서 인증 설정 추가 대상.
- 저장소 밖 전용 디렉터리 0700·개별 파일 0600 저장 완료. 직접 OAuth 인증 성공 및 7·30·90일 배치 보고서 각각 HTTP 200/5개 보고서·차원/지표 일치, 각 이전 기간 HTTP 200/결과 0행 확인.
- Admin API v1beta/v1alpha 스트림 조회는 HTTP 403, machine-readable reason SERVICE_DISABLED 확인. 첨부에 웹 측정 ID가 없어 기존 공개 측정 ID와 일치 여부 사용자 확인 요청. 임의로 다른 속성의 수집 활성화 없음.
- API는 이미 `GA4_PROPERTY_ID`, `GA4_SERVICE_ACCOUNT_JSON_BASE64` 지원. Pages는 `NEXT_PUBLIC_GA_ENABLED` 빌드 변수로 공개 수집 제어.

## 운영 결과

- 전용 운영 환경 파일에서 GA 두 항목만 교체, 다른 환경 값 동일 확인. 적용 전 파일은 저장소 밖 0600 보관.
- 기존 운영 API 이미지 그대로 재생성, 공인 health UP·OOM 없음·재시작 횟수 0 확인. 게이트웨이 설정 검사·reload 완료. DB·콘텐츠 마이그레이션 및 원고 쓰기 없음.
- 운영 `/api/v1/admin/analytics` 7·30·90일 모두 READY. 각 실제 방문자 3·페이지뷰 8, 일별 4행·페이지 1행 확인. 문서 참여·비교 기간은 실측 부재를 null로 유지.
- 사용자 확인: 기존 측정 ID·ken-blog 웹 스트림·Pages 연결 URL 일치. `NEXT_PUBLIC_GA_ENABLED=true` 적용 후 Pages36326587629 동일 코드 재배포 완료.
- 실제 Pages 관리자 대시보드 7·30·90일 모두 연결됨·실측 수치 표시 확인. 기간 전환 직후 로딩 상태와 이전 응답을 혼동하지 않도록 검증 대기 보정.
- 실제 Google 수집 요청: 익명 홈 page_view와 클라이언트 Tech 이동 page_view 각각 확정 측정 ID로 HTTP 204 확인. 로그인된 편집기에는 수집 스크립트 없음, 관리자/로그인 이동 뒤 추가 전송 없음. 가짜 수치·별도 검증 이벤트 전송 없음.
- 인증 원문을 제외한 검증 요약은 저장소 외 `/tmp/ken-blog-ga4-connect/production-results.json` 보관.
