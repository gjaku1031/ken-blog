권한은 화면이 아니라 서버가 요청마다 확인하고, 응답은 기본적으로 저장되지 않게 내보냄.

## 신뢰 경계

방문자가 사이트로 들어오는 길은 Cloudflare 터널 하나임. 웹은 서버 안의 주소에만 열려 있고, API 컨테이너는 서버 안에서도 포트를 내놓지 않아 웹을 거쳐야 닿음. 배포는 SSH로 함. PostgreSQL은 서버 안의 주소에만 열려 있음.

## 인증과 세션

| 항목 | 설계 |
| --- | --- |
| 가입 | 아이디와 비밀번호, 필수 약관 동의. 이메일을 받지 않아 자동 비밀번호 찾기는 없음 |
| 비밀번호 | Argon2id로 해시해 저장 |
| 세션 | PostgreSQL에 저장(Spring Session JDBC). API를 다시 시작해도 로그인이 유지됨 |
| 세션 쿠키 | HttpOnly, SameSite=Lax, HTTPS에서는 Secure |
| 사용자 확인 | 요청마다 사용자를 DB에서 다시 읽음. 계정 삭제와 권한 변경, 댓글 제한이 다음 요청부터 적용됨 |
| 시도 제한 | 가입과 로그인을 IP 단위로, 로그인은 IP와 아이디의 조합 단위로도 제한 |

## 권한

`/api/admin` 아래의 경로는 처리하는 코드에 표시가 있든 없든 운영자만 부를 수 있음. 경로는 요청을 처리할 코드를 찾을 때와 같은 기준으로 나눠서 판단함. 주소 문자열을 그대로 비교하면 `/api/admin;x/orders`나 `/api/%61dmin/orders`처럼 처리 코드는 찾아가지만 문자열 비교는 빗나가는 요청이 검사를 피하기 때문임.

편집 모드는 화면에 단추를 보이는 상태일 뿐이고 권한과 무관함. 고객의 주문은 본인의 것인지 서버가 확인함.

## 위협별 대응

| 위협 | 대응 | 남은 위험 |
| --- | --- | --- |
| 운영 기능을 고객이 호출 | 경로 기준으로 운영자만 허용. 화면의 단추와 무관하게 서버가 확인 | — |
| 주소를 꾸며 권한 검사를 우회 | 처리 코드를 찾는 기준과 같은 경로 구간으로 판단 | — |
| 다른 사람의 주문을 조회·변경 | 주문이 요청한 회원의 것인지 확인 | — |
| 글 본문에 스크립트를 넣음 | 저장할 때마다 본문을 정제 | 글을 쓰는 사람이 운영자뿐이라는 전제 |
| 형식을 속이거나 지나치게 큰 사진 | 티켓의 신고 내용과 실제 파일의 형식·크기 대조, 5MB 제한, 변환을 별도 프로세스에서 시간 제한을 두고 실행 | 사진을 올리는 사람이 운영자라는 전제. 방문자 업로드를 만들면 픽셀 수 제한이 먼저 필요함 |
| 사진에 든 촬영 위치의 노출 | 변환본에서 메타데이터를 지우고, 원본은 내보내지 않음 | — |
| 공개 전이나 숨긴 사진의 열람 | 공개된 상품과 글에 쓰인 사진만 방문자에게 응답 | 공개 사진을 숨겨도 캐시에 최대 하루 남음 |
| CDN에 저장된 개인 정보의 노출 | 모든 응답의 기본값 `no-store`. 공개 사진만 캐시 허용 | 방어선이 원 서버 한 겹. CDN의 보호 규칙은 아직 켜지 않았음 |
| 로그인 대입 | IP 단위, IP와 아이디의 조합 단위의 시도 제한 | 여러 IP에서 한 계정을 노리는 시도는 계정 단위로 막지 못함. 횟수를 API의 메모리에 두어 다시 시작하면 초기화됨. API가 한 대라는 전제 |
| 사이트 간 요청 위조 | 세션 쿠키 SameSite=Lax. 웹과 API가 같은 출처이고 교차 출처 허용은 웹 주소 하나 | 별도의 CSRF 토큰은 아직 없음. 넣을 예정임 |
| 큰 요청 본문, 오래 걸리는 쿼리 | JSON 본문 1MB 제한. 쿼리는 잠금 대기를 포함해 5초 제한 | 본문 제한은 요청이 밝힌 길이로만 판단해, 길이를 밝히지 않고 나눠 보내는 요청은 지나감 |
| 운영자의 변경을 나중에 확인 | 성공한 운영 변경을 운영 기록에 저장 | — |
