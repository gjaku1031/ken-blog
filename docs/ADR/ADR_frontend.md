# 프론트엔드 상태·렌더링 결정

기준일: 2026-10-03. 공개 화면은 정적 HTML, 관리자 화면은 인증된 메타데이터 관리 유지. 전체 배치·배포 경계는 [인프라 ADR](ADR_infra.md), 원고·공개 범위는 [애플리케이션 ADR](ADR_application.md) 참조.

전수 리뷰 후 관리자 전체 조회·편집·배포 비교 및 스냅샷 버전은 문서 끝의 **리뷰 후 상태·접근성 계약**이 아래 초기 결정을 대체한다.

## 관리자 비동기 작업의 소유권

저장 중 창을 닫고 다른 글을 열거나, 이전·다음 페이지를 빠르게 누르면 늦은 응답이 현재 입력·목록을 덮는 문제가 배경. 저장 작업은 시작한 세션과 대화상자 본문을 기억하고, 동일한 세션·본문에만 창 닫기와 오류 표시 적용. 목록 조회는 이전 요청을 취소하고 현재 요청의 응답만 반영. 전체 상태 필터를 위해 글을 100개 단위로 수집하고 페이지 이동은 메모리 목록에서 수행. 상태 새로고침은 글·배포 비교만 재조회하며 기존 분류·태그·시리즈·기술 선택 목록 재사용. 저장 뒤에는 연결 수와 선택 목록 갱신.

저장 성공과 후속 조회 실패를 별도 결과로 처리. 생성은 성공했지만 목록 조회가 실패한 경우 화면에 저장 완료와 새로고침 실패를 함께 표시. 생성 요청 자동 재시도 없음. 모든 작업 중 화면 전체를 잠그는 대안은 다른 글 열기와 탐색을 제한하므로 제외. 서버의 트랜잭션·CSRF·세션 인증 계약 유지.

시리즈·프로젝트 종류 필터도 같은 소유권 규칙 적용. 생성 창을 닫고 다른 종류를 선택한 뒤 이전 생성 응답이 도착해도 필터를 바꾸지 않음. 원래 생성 창이 유지된 경우에만 새 항목이 보이도록 종류 전환.

## 공개 탐색 데이터와 접근성

태그는 구분 문자열 대신 JSON 배열로 전달하여 이름의 `|` 보존. 이전 slug 쿼리 주소는 빌드에서 확정한 공개 대상 표로만 이동. 존재하지 않는 주소는 해당 목록으로 복귀하며 공개 해제된 글을 추측하거나 관리자 API로 조회하지 않음.

공개 snapshot v2에 선택적 `categories` 목록 추가. 공개 글에 지정된 분류와 부모의 ID·경로·표시 이름·순서만 포함하고 빈 분류·비공개 글 전용 분류·관리자 건수 제외. 같은 일관 읽기에서 수집하고 revision 계산에 포함하여 부모 순서 변경도 재생성 검사 대상. 글별 배포 비교 지문에도 해당 글의 분류·부모 표시 이름과 순서를 포함하고, 분류 배열 자체의 순서 변경은 무시. 구 API 응답에서는 경로 기반 부모 표시를 유지하므로 API를 먼저 반영한 뒤 Pages를 발행해야 모든 표시 이름·순서가 적용됨. 인증된 전체 분류 트리를 Pages 빌드에 전달하는 대안은 공개 범위를 넓히므로 제외.

넓은 본문 표는 모든 화면 폭에서 내부 스크롤 제공. 검색 입력의 키보드 포커스는 실제 `:focus-visible`로 표시. 보조 글자 색은 두 테마의 기본·카드·입력 배경에서 일반 텍스트 대비 4.5:1 이상으로 검증. 태그 선택 개수 오류는 선택 제거 후 해제.

검색 화면의 첫 프레임 자동 포커스는 현재 포커스가 문서 본문일 때만 적용. 이미 시작한 키보드·포인터 탐색은 늦은 초기화로 덮지 않음. 검사에서도 초기 포커스 적용을 확인한 뒤 일반 Tab 순서를 검증하고, 프레임 지연 경합은 별도로 재현.

## 정적 본문과 자산의 처리 비용

첨부 다운로드 주소를 확정하기 위해 본문 전체를 두 번 렌더하던 방식을 대체. 준비 단계에서 AST·첨부·위키·목차 정보를 만들고, 같은 AST에 공개 주소를 적용하여 최종 HTML을 한 번 생성. 수식·주석·위키의 제외 영역 검사도 같은 수식 AST 재사용. 문서 경계에서 CRLF·CR을 LF로 통일하여 행 번호·제목 ID 일치. 파서별 보안 한도와 HTML 정화 경계 유지. 전역 원고 캐시는 공개 해제·입력 변경 시 무효화 부담이 있으므로 미도입.

공통 화면과 상세 본문 자산 분리. KaTeX·본문 CSS·본문 상호작용은 상세 화면에서만 로드. 글쓰기 폼 코드·CSS는 관리자 확인 후 실제 작성·수정 클릭에서 로드하며, CSS 로딩 완료 뒤 창 표시. 별도 CSS를 자동 로딩한다고 가정하지 않고 빌드 manifest와 템플릿·로더에서 주소 연결. manifest의 모든 진입 자산도 캐시 검증 대상.

검색 본문은 HTML의 카드 속성에서 내용 해시가 있는 별도 공개 JSON 색인으로 이동. 검색 화면에서 한 번 조회하고 최신 조건에 맞는 전체 결과를 DOM에 표시. 카드 HTML은 자동 이스케이프하는 기존 템플릿 출력이며 검색어를 HTML로 삽입하지 않음. 일반 목록도 조건에 맞는 전체 글을 표시. 2026-10-03 사용자 요청으로 `더 보기` 버튼과 20개 표시 제한 제거. JavaScript 비활성 시 검색 대신 전체 공개 글 링크 제공. 키 입력마다 중복 검색하지 않고 기존 180ms 입력 지연과 한글 조합 대기 적용. 외부 검색 서비스나 SPA 라우터 도입 없음.

Mermaid는 화면 240px 이내로 접근한 도식만 렌더. 테마 변경·문서 분리 시 이전 예약 취소, 반복 interval 제거. 기존 원문·SVG 검증 뒤의 결과만 테마·원문 기준 최대 16개 보관. 목차는 크기·이미지·접기·글꼴 변경 시 제목 위치를 갱신하고 스크롤 중에는 저장한 좌표 이분 탐색. PNG·JPEG 헤더에서 읽은 크기와 JPEG EXIF 방향을 정적 이미지 속성에 반영하고 테마별 대체 이미지의 크기도 보존. 이미지 전체 디코딩·변환을 수행한다는 보장은 없음.

## 정렬 입력·스크롤·아키텍처 도식의 통합

2026-10-03 재조사에서 `8f2b79f`까지 추가된 태그·기술 드래그 정렬을 공통 선택 입력에 연결. `selection-picker.ts`가 선택 상태·숨김 제출값을 관리하고 `sortable-chips.ts`는 포인터·키보드 순서 변경만 전달. 재렌더 전 진행 중인 정렬 취소, 확정한 순서를 제출값에 반영. 태그·기술마다 정렬·제출 코드를 다시 갖는 대안은 동일한 순서 보장이 두 곳으로 나뉘므로 제외. 긴 공개 탐색·편집 분류 목록의 스크롤·포커스·테마 규칙은 `category-tree.css`의 `scroll-region`으로 공유하고 높이는 각 화면에서 지정.

두 프로젝트의 고정 아키텍처 배치는 로컬 JSON과 명시적 주석으로 선택. 원고의 서비스·소속·연결 대상뿐 아니라 그룹 선언과 연결의 문구·입출력 방향도 `sourceGroups`·`sourceEdges`와 대조. 구성이 다르면 Mermaid 초기화·자동 배치 전에 중단하고 원문 유지. 알려진 원고에서만 좌표·번역 설명을 적용하여 원고 수정 뒤 예전 설명이 남는 문제 방지. 원문만 자동 배치하는 대안은 현재 단일 화면의 영역·범례·설명 배치를 보존하지 못하므로 제외. 배치나 연결 설명 변경 시 원고·JSON을 함께 갱신하는 유지보수 비용 수용. 로컬 아이콘 팩·SVG 정화·외부 자원 차단 경계는 유지. 작성 방법은 [Mermaid Architecture 작성 가이드](../guide/mermaid-architecture.md) 참조.

## 검증과 적용 상태

파서 4곳의 오프셋·행·열·이스케이프 계산은 `source-position.ts`, 공개 주소·slug·위키 비교는 `site-path.ts`로 통합. 태그·기술의 선택 순서·키보드·칩·제출값은 `selection-picker.ts`에서 공유하고 화면별 생성 허용·개수·표시 규칙은 호출부에 유지. 공통 글꼴·리셋·카드·포커스는 `base.css`, 화면별 배치는 각 화면 스타일에 유지. 사용처가 없는 CSS 클래스 82종의 규칙과 읽지 않는 주석 첫 참조·강조 토큰 글꼴·선택 인덱스 getter·위키 원문 속성 제거. 동적 프로젝트 상태·KaTeX 클래스는 유지.

최초 통합에서 타입 검사·빈 사이트 생성과 Node 검사 33개 통과. Chromium 회귀 검사 18개로 늦은 저장 응답, 로그아웃 후 지연 응답 차단·페이지 무요청 이동·상태 갱신의 선택 목록 재사용, 저장 후 조회 실패, 태그 개수 오류, 공개 태그·분류·브라우저 로캘 독립 비교, 이전 글·프로젝트·강의 주소, 표 스크롤, 검색 포커스, 검색 색인·추가 표시, 작성·현장 편집 폼 지연 로드·분류 트리 선택, Mermaid 지연·테마 전환, 접기·문서 끝 목차, 기술 선택 순서, 익명 방문, 모바일 목록·본문·관리 화면 확인. 혼합 Markdown의 재렌더 일치·HTML/이미지 경계·줄바꿈·이미지 크기 검증 포함. 당시 저장소 Markdown 38개의 HTML·목차·첨부·위키 결과가 파서 최적화 전과 일치. 재조사 통합 후 타입·미사용 선언 검사, 빈 사이트 생성, Node 38개와 Chromium 25개 통과. 추가 브라우저 검사 7개로 마우스·키보드 정렬과 취소, 정렬 후 새 편집 창 포커스, 긴 분류 자동 스크롤·사이드바 전환, 늦은 생성 응답의 필터 보존, 실제 두 원고의 라이트·다크 도식 렌더, 390px 여러 줄 칩의 터치·동작 축소 설정, 초기 검색 포커스와 키보드 탐색의 경합 검증. JVM 코드는 최초 통합 이후 변경 없으며 Gradle 검사는 기존 42개 성공 결과를 최신 입력으로 재사용.

`npm test`는 타입 검사·빈 사이트 생성·Node 회귀 검사, `npm run test:browser`는 가상 공개 데이터·모의 관리자 API의 Chromium 검사. 고정 도식은 저장소 원고 표본 사용. Pages 배포의 실제 snapshot·revision 확인은 기존 workflow에서 별도 수행. 기존 인프라 ADR의 빈 사이트 중심 검사 설명을 이 기준으로 대체.

## 리뷰 후 상태·접근성 계약 — 2026-10-03

관리자 전체 목록은 페이지를 순회하지 않고 서버의 일관 읽기 응답 한 번을 사용한다. 새로고침 작업은 진행 중인 Promise에 합류하며 선택 목록의 변경 세대와 읽은 세대를 분리한다. 저장 이후 시작된 전체 조회를 자동 상태 조회가 취소하지 않으며 조회 중 추가 저장이 있으면 최신 세대를 다시 읽는다. 목록 교체 직전 포커스가 목록 안에 있을 때만 글 ID·동작·페이지 키로 즉시 복원하고, 사라진 항목은 결과 수로 이동한다.

글 편집은 최신 상세 응답의 `editVersion`으로 열고 모든 편집 필드를 한 번 저장한다. 409에서는 입력을 유지한다. 생성 완료와 편집 화면에서 `content/posts/{slug}.md`를 표시한다. 시리즈의 별도 순서 저장 실패는 HTTP 상태를 보존하고 이미 성공한 메타데이터를 재전송하지 않고 이어서 처리한다.

배포 상태는 공개 메타데이터 비교임을 명시한다. 비교 실패는 DRAFT·PRIVATE에도 `확인 불가`로 남기고 공개 원고·이미지 바이트의 반영 완료를 뜻하지 않는다. v3 스냅샷은 그룹별 탐색 참조를 검증하고 빌더의 기존 내부 모델로 확장한다. v2 읽기도 유지한다.

수식 HTML 복원은 함수 치환으로 `$&` 등의 리터럴을 보존한다. 수식 구간은 코드·링크·raw HTML 제외 영역을 가로지르지 못한다. 세 문법의 동일한 raw HTML 제외 루프만 공유하고 문법별 AST·마스크는 분리한다. 백링크는 정규화한 대상과 출처별 한 번만 출력한다. 링크 내부 이미지는 링크 기능을 사용하며 확대 버튼을 겹치지 않는다. 모든 첨부에 비율 유지 CSS를 적용한다.

주석 팝업은 hover·focus·Escape 종료 상태를 함께 관리하고 viewport 안에서 위치·높이를 제한한다. 검색의 첫 이동은 방문 이력을 추가하고 결과 화면의 입력 갱신은 기존 replaceState를 유지한다. 검색 상태는 polite live region이다. 중복 미디어 쿼리는 실제 최종 값을 보존해 합치고 미사용 공개 로그인 CSS와 분류 개수 중복만 제거했다.

브라우저 mock은 method/path·필수 DTO·버전을 명시하고 상태에 변경을 반영한다. 미정의 요청은 501로 거부한다. 실제 HTTP·DB 계약 검사는 백엔드 및 별도의 HTTPS 런타임 검사와 결합하며 모의 API만으로 운영 인증을 검증했다고 보지 않는다.


## 프로젝트 관련 글과 관리 목록의 직접 조작 — 2026-10-03

프로젝트 읽기 화면의 오른쪽 탐색에서 소속 문서 다음에 `관련된 글`을 표시한다. 공개 snapshot의 일반 글 중 해당 프로젝트를 관련 프로젝트로 지정한 글만 최신 출간순으로 묶는다. 초안은 snapshot에 포함되지 않으며, 연결 글이 없는 프로젝트에는 빈 목록을 만들지 않는다.

시리즈·프로젝트 목록은 수정 아래에 빨간 삭제 버튼을 제공한다. 연결된 글이 남으면 서버의 거부 안내를 표시하고, 글 관리 목록에서도 삭제를 제공하여 선행 조건을 처리할 수 있다. 삭제 시 확인창을 거치며 저장 후 목록·공개 배포 상태를 다시 조회한다.

분류 관리 모달의 숫자 순서 입력을 제거한다. 각 행 오른쪽의 수정은 행 안에서 이름을 편집하고 삭제는 기존 분류 삭제 정책을 따른다. 손잡이 드래그와 위·아래 방향키/Home/End로 형제 순서를 바꾼다. 대분류 이동 시 소분류는 함께 이동하고 소분류는 같은 부모 안에서만 이동한다. 포인터 취소·Escape·목록 밖 놓기는 저장하지 않으며 서버 저장 실패 시 원래 화면 순서를 복원한다. 터치 입력과 화면 가장자리 자동 스크롤도 같은 동작을 사용한다.
