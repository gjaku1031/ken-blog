# 주소 직접 지정 기능 제거

## 요청과 범위

- 사용자 요청: 모든 주소 직접 지정·수정 기능 제거.
- Tech 글, Projects 대문·문서, Notes 과목·회차의 작성/수정 화면과 쓰기 API 대상.
- URL 이동·공개 조회 응답의 식별자 유지, 프로젝트 외부 링크·본문 링크는 기존 기능 유지.
- 기존 게시글·프로젝트·과목 주소 보존, 기존 QA 데이터 변경·정리 없음.

## 수용 기준

- 수동 주소 입력란·설정·필수 입력 안내 제거.
- 신규 주소의 서버 자동 발급, 한글·동일 제목의 독립적인 저장과 출간 가능.
- 제목·이름 수정과 재출간 시 기존 주소 유지.
- 기존 초안의 빈 주소 처리 및 출간 글 연결 초안의 원래 주소 우선.
- 구 클라이언트의 주소 필드 전달에도 직접 지정·변경 불가.
- 저장/출간 응답으로 후속 이동, 관련 프로젝트·과목 링크 정상 유지.

## 검증 계획

- 신규 테스트 코드 추가 없음. 기존 검사·타입검사·빌드 및 격리 API/브라우저 확인.
- 주소 생략 생성, 임의 주소 전달 무시, 동일 제목 동시 생성, 재저장·재출간 주소 유지 확인.
- 실제 Pages 입력란 제거와 운영 API 계약 확인, 검증용 신규 자료만 식별하여 정리.
- 실행 결과·최종 커밋·실제 push와 배포 시각의 후속 기록 예정.

## 구현과 로컬 검증

- 출간 시트 주소 입력·주소 전용 스타일·수동 입력 상태·유효성 검사·요청 필드 제거. Notes 과목의 브라우저 주소 생성과 수정 요청 제거.
- 서버의 게시 위치별 UUID 주소 발급 및 새 편집본→저장→출간 주소 유지. 기존 원본·프로젝트·과목은 엔티티 수정 메서드에서도 주소 변경 인자 제거.
- 구 요청의 최상위·중첩 주소 값 미사용. 구 편집본의 빈 주소·수동 주소는 원본 없는 경우에만 자동 발급, 원본 있는 편집본은 기존 공개 주소 우선.
- DB 마이그레이션·기존 운영 자료 일괄 변경 없음. 프로젝트 이름의 기존 고유 제약 유지.
- 웹 타입검사·기존 7개 검사·정적 20경로 빌드 통과. 최종 API `clean verify` 기존 28개 통과.
- 실제 배포 이미지에서 추출한 JAR와 격리 MySQL의 HTTP 23항목 통과: 입력 생략·직접 전달 무시·동일 제목 6건 동시 생성·빈/구주소 초안·각 게시 위치의 저장/출간·기존 주소 유지.
- 브라우저 23항목 확인: Tech 저장·재저장·출간·재출간, 프로젝트 대문·문서와 Notes 회차 출간, Notes 과목 생성/수정, 요청 주소 필드 부재, 데스크톱/390px 출간 시트. 런타임 오류 없음.
- 검증 도구의 분야명 포함 문자열 오탐·필수 분야 미선택 및 재실행 시 중복 프로젝트 이름을 정정한 뒤 해당 흐름 재확인. 제품의 주소 기능 실패 아님.
- React 검토: 삭제 필드의 props·상태·요청 직렬화 정리, 기존 저장 revision·입력 보존·출간 응답 이동 유지. 새 의존성·전역 이벤트·추가 네트워크 요청 없음.
- 비공개 검증 자료 `/tmp/ken-blog-automatic-addresses` 보관. 사용자 QA 데이터 109글·12초안·6프로젝트·10과목의 기존 주소 비교용 스냅샷 확보.
