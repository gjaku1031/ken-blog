## 구현 결정

- 대문/문서는 `posts.section=PROJECT_HOME|PROJECT_DOC`, 기존 글은 `TECH`. 본문·첨부·위키 저장과 편집본 파이프라인 재사용. `projects`에 대문 속성, Post에 project FK·문서 순서·Tech 관련 프로젝트 FK 추가.
- 대문 속성도 EditorDraft의 별도 스냅샷과 기준 수정 시각으로 보관. 새 프로젝트는 첫 대문 출간 시 원문과 함께 생성. 기존 프로젝트는 원문·메타 기준이 변경됐으면409, 정상 출간만 모두 원자 반영.
- 쓰기 잠금은 category→project→post→draft→첨부의 기존 관계와 일관되게 유지. FK 삭제 정책과 프로젝트 연쇄 삭제는 관련 초안/첨부 선언을 포함해 처리하며 OCI 객체를 임의로 연쇄 삭제하지 않음.
- 기존 Tech 피드·분류/태그는 TECH만 SQL 집계. 프로젝트와 문서는 부모 공개 범위·출간 상태를 매 읽기에 확인. Redis 본문 캐시는 기존 익명 PUBLIC TECH에만 유지.
- 일반 post 상세·위키·역링크 이동 정보에 안전한 소속 section/projectSlug 추가. LOCKED/MISSING에는 대상 ID·주소·프로젝트 정보 없음. 프로젝트명(대문)보다 기존 일반 글의 제목 일치를 먼저 선택.
- 첨부는 기존 post ID 전달 경로에서 부모 프로젝트 권한을 추가 검증. 전역 slug는 기존 ASCII 규칙 유지. 최종 DTO와 정확한 API 경로는 구현과 함께 아래에 기록.
