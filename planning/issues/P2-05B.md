# P2-05B 주석 삽입·문서 전체 편집 미리보기

## 문제와 시작 상태

P2-05A 읽기 기능은 main `2614569` 정상 push 완료. 편집기에서는 주석을 직접 입력해야 하고 블록별 미리보기는 문자로만 표시됨. 전체 문서 번호와 같은 미리보기·입력 커서 복원 필요. 이전 단계 정확한 SHA의 CI/Pages 성공 확인 후 구현 시작.

## 구현 범위

- 글쓰기 도구에 주석 삽입 버튼. 현재 편집 가능한 인라인 텍스트 블록의 선택 위치에 `[* ]` 삽입하고 닫는 괄호 앞에 커서 복원. 선택 범위는 명시적으로 대체. pointerdown/키보드 버튼 이동에서 마지막 블록 ID와 selectionStart/End를 저장하고, 문서 변경 후 stale ID/범위를 안전하게 정리.
- 인라인 편집 대상은 문단·제목·목록·할 일·인용 및 편집 가능한 한 단계 접기의 해당 자식. 코드/수식/Mermaid·원문·이미지·표 셀·접기 제목에는 삽입하지 않음. 사용할 커서가 없으면 마지막 인라인 텍스트 블록 끝, 그런 블록도 없으면 새 문단 생성. 조합 중/출간 중/업로드 중 삽입 차단. 기존 원문과 LF/CRLF 유지.
- 문서 전체의 공유 주석 모델을 에디터에서도 사용. 블록 순서·내용·이름 정의 변경 후 익명 번호·이름 참조·전방 참조·중복 정의가 저장된 전체 본문의 읽기 결과와 일치. 블록별 로컬 번호를 다시 세지 않음.
- 에디터 하단의 `주석 미리보기` 목록. 편집 미리보기의 위첨자는 설명을 읽을 수 있지만 클릭으로 읽기 페이지나 문서 바깥으로 이동하지 않음. 말풍선·키보드 접근성과 수정용 미리보기 트리거가 충돌하지 않도록 구성. 표/접기/미지원 원문에서 정확한 위치 매핑이 불가능하면 잘못된 번호를 만들지 않고 원문을 유지하며 전체 목록은 올바르게 표시.
- 동일한 문서 모델로 읽기/편집의 안전 내용·상한·첨부 ID 미수집 계약 유지. 문서/계정/경로 전환 시 커서·말풍선·미리보기 폐기. 미리보기 계산이 저장 원문이나 dirty 상태를 변경하지 않음.
- 한국어 JSDoc·README·편집/Markdown 안내·계획/전달 상태 갱신. 신규 라이브러리와 신규 저장소 테스트·학습 문서 없음.
