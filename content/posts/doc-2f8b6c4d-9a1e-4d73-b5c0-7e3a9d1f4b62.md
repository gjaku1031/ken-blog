웹, API, PostgreSQL이 서버 한 대의 Docker Compose에서 함께 돌고, 방문자가 들어오는 길은 Cloudflare 터널 하나임.

## 품질 요구사항

| 요구 | 뜻 | 핵심 문제 | 수단 |
| --- | --- | --- | --- |
| 재고 정합성 | 동시에 주문해도 재고보다 많이 팔리지 않고, 입금하지 않은 주문이 재고를 계속 잡지 않음 | P1 | 옵션 행 잠금, 입금 기한, 주기 작업의 자동 취소 |
| 가벼운 전송 | 목록과 썸네일이 화면에 필요한 크기의 사진만 받음 | P2 | 올릴 때 만드는 세 크기의 변환본, 공개 사진의 캐시 |
| 캐시 안전 | 사람에 따라 달라지는 응답이 CDN에 저장되지 않음 | P3 | 모든 응답의 기본값 `no-store` |
| 한 사람이 운영 | 구성 요소가 적고, 장애가 났을 때 볼 곳이 한 대임 | 전체 | 서버 한 대, PostgreSQL 하나, Redis와 메시지 큐 없음 |

## 인프라 구성

```mermaid caption="방문자의 요청은 Cloudflare를 거쳐 서버의 터널 프로세스로 들어오고, 웹이 /api 요청을 API로 넘김. API 컨테이너는 서버 밖으로 포트를 열지 않음. 배포는 워크플로를 수동으로 실행해 코드를 서버에 전달하고 서버에서 이미지를 빌드함"
architecture-beta
  %% layout: damdam-infrastructure
  group users[Users]
  group cf[Cloudflare]
  group deploy[Deployment]
  group server[Server]
  group compose(ken:docker)[Docker Compose] in server

  service customer(ken:user)[Customer] in users
  service operator(ken:user)[Operator] in users
  service cdn(ken:cloudflare)[Cloudflare] in cf
  service actions(ken:github-actions)[GitHub Actions] in deploy
  service tunnel(ken:vpn)[cloudflared] in server
  service web(ken:nextjs)[Next.js web] in compose
  service api(ken:spring)[Spring Boot API] in compose
  service uploads(ken:disk)[Uploads volume] in compose
  service pg(ken:postgresql)[PostgreSQL] in compose

  customer:R -[HTTPS]-> L:cdn
  operator:R -[HTTPS]-> L:cdn
  cdn:R -[Tunnel]-> L:tunnel
  tunnel:B -[HTTP]-> T:web
  web:B -[API]-> T:api
  api:R -[Files]-> L:uploads
  api:R -[SQL]-> L:pg
  actions:R -[Deploy]-> L:api{group}
```

| 구성 요소 | 하는 일 |
| --- | --- |
| Cloudflare | HTTPS를 받고 공개 사진을 캐시함. 서버로는 터널로만 연결됨 |
| 운영 서버 | VMware ESXi 위의 가상 머신 한 대(4 vCPU, 메모리 8GB, Ubuntu 24.04) |
| cloudflared | 서버에서 Cloudflare로 나가는 연결을 열어 두고, 들어온 요청을 웹으로 넘김. 웹과 API는 밖에서 직접 닿는 포트를 열지 않음 |
| 웹(Next.js) | 화면을 그리고 `/api` 요청을 API로 넘김. 서버 안의 주소에만 열려 있음 |
| API(Spring Boot) | 업무 규칙, 권한 확인, 주기 작업. 컨테이너 밖으로 포트를 열지 않음 |
| PostgreSQL | 업무 데이터와 로그인 세션 |
| 업로드 볼륨 | 사진의 원본과 변환본 |

## 요청 흐름

```mermaid caption="브라우저의 요청은 Cloudflare와 터널을 거쳐 웹에 닿고, 웹이 /api 요청을 API로 넘김. API는 요청마다 세션의 사용자를 DB에서 다시 읽어 권한을 확인함"
sequenceDiagram
    %% legend: solid=요청; dotted=응답
    participant B as Browser
    participant C as Cloudflare
    participant W as Next.js web
    participant A as Spring Boot API
    participant D as PostgreSQL
    B->>C: HTTPS 요청
    C->>W: 터널로 전달
    W->>A: /api 요청 전달
    A->>D: 세션과 사용자 조회
    A->>D: 업무 데이터 조회·변경
    D-->>A: 결과
    A-->>W: JSON 응답(Cache-Control 포함)
    W-->>C: 응답
    C-->>B: 응답
```

## 상태를 두는 곳

| 상태 | 저장 위치 | 재시작하면 |
| --- | --- | --- |
| 상품, 주문, 재고 이력, 글, 운영 기록 | PostgreSQL | 유지됨 |
| 로그인 세션 | PostgreSQL(Spring Session JDBC) | 유지됨 |
| 사진의 원본과 변환본 | 업로드 볼륨 | 유지됨 |
| 로그인·가입 시도 횟수 | API 프로세스의 메모리 | 사라짐 |

주기 작업은 API 프로세스 안에서 실행함. 기한이 지난 결제 대기 주문의 취소는 5분마다, 기한이 지난 업로드 티켓의 정리는 매시 정각에 돎.

## 일관성 보장 범위

| 대상 | 보장하는 것 | 수단 | 보장하지 않는 것 |
| --- | --- | --- | --- |
| 재고와 주문 | 재고보다 많이 팔리지 않음. 한 주문의 재고는 한 번만 돌아옴 | 옵션 행 잠금, 주문 행 잠금과 잠근 뒤의 재확인, `CHECK (stock >= 0)` | 잠금 순서와 재확인은 코드 규칙으로 지킴. 어긴 경로를 자동으로 잡지 못함 |
| 재고 수량과 이력 | 옵션마다 이력의 합이 현재 수량과 같음 | 수량을 바꾸는 경로가 같은 트랜잭션에서 이력을 남김 | 주기적인 대조는 아직 돌리지 않음 |
| 입금 기한 | 주문할 때 안내한 기한이 설정을 바꿔도 유지됨 | 기한을 주문에 저장 | 기한이 지난 뒤 취소까지 최대 5분이 걸림 |
| 사진 파일과 DB | 검증을 통과한 파일만 저장됨 | 업로드 티켓과 실제 파일의 형식·크기 대조 | 올린 뒤 글이나 상품에 붙이지 않은 파일은 볼륨에 남음 |
| 공개 여부와 캐시 | 비공개 사진은 캐시되지 않음 | 공개로 판정된 응답에만 캐시 허용 | 공개 사진을 숨겨도 받아 간 쪽에는 최대 하루 남음 |

서버와 API가 한 대뿐이라 둘 중 하나가 멈추면 사이트 전체가 멈춤. 배포할 때도 컨테이너를 바꾸는 동안 요청이 끊김. DB와 사진의 백업은 하지 않음.
