# P2-02C 표 편집과 안전한 접기 읽기

## 문제와 시작 상태

P2-02B main `814715c`에 기본 블록·별도 편집본·수동 출간 화면 반영. CI 36226398228·Pages 36226398232 해당 SHA 성공 확인. 현재 표와 중첩 접기는 원문을 보존하지만 표를 셀 단위로 고칠 수 없고 읽기 화면의 접기 동작이 없음.

## 구현 범위

- 읽기 화면에서 fence/inline code 밖의 명확한 `<details>`·`<summary>`만 접기 UI로 표시. 기본 닫힘, 같은 줄/다음 줄 summary·summary 없는 기본 제목, 안쪽 Markdown과 중첩 접기 지원. 키보드/native disclosure 의미와 라이트·다크·모바일 유지.
- HTML의 임의 속성·script·iframe·style·이벤트를 DOM에 주입하지 않음. 링크 스킴 제한·외부 이미지 자동 요청 차단·읽기 전용 할 일 유지. 잘못 닫힌 접기·지나친 중첩은 안전한 원문 대체와 본문 보존. 기존 참조 링크/정의가 접기 경계를 지나도 사라지지 않는지 확인. 코드 속 접기 예제를 실제 접기로 해석하지 않음.
- top-level GFM 표를 전용 편집 블록으로 지원. 셀은 인라인 Markdown 원문 한 줄 입력, 헤더·본문·좌/중/우 정렬. 셀의 이스케이프된 세로선과 역슬래시·코드·링크 문법 보존. 무수정은 원본 slice, 수정한 표만 직렬화. 복잡하거나 확실히 해석할 수 없는 구간은 읽기 전용 원문 보존.
- `/표` Enter와 표 추가 버튼으로 2열 헤더+본문 표 생성, 첫 셀 포커스와 마지막 표 뒤 문단 확보. 명확한 파이프 머리글 Enter도 지원하되 일반 본문은 오인식하지 않음.
- 셀 Enter는 같은 열 아래로 이동하고 마지막 행에서는 한 행 추가. 행/열 추가·삭제, 헤더+본문 최소 1행/1열 유지, 열 정렬 순환·표 삭제. 키보드 라벨·포커스 복원·Esc·한글 조합 보호. 표 내부만 가로 스크롤. 표 블록의 이동·저장/재열기 지원.
- 편집기의 중첩 접기는 이번에도 원문 단위로 유지. 원래 body를 변경하지 않고 안전한 읽기 표시와 표 편집을 확장. 기존 기본 블록·revision·CSRF·JDBC 인증·출간 계약 유지.
- 검토 중 발견한 저장 경합 보완: 저장 요청이 진행 중일 때 다른 편집본 쿼리로 이동하면 이전 응답이 현재 원고의 ID/revision을 덮지 않도록 요청 수명을 경로 전환에도 묶음. 첫 저장 자체의 URL 변경과 저장 중 추가 입력 유지 계약은 그대로 두고, 별도 수정 목적 커밋으로 기록.
- 관련 설명·실행 안내·전달 체크리스트 갱신. 신규 테스트 파일·학습 자료 추가 없음.

## 제외 범위

접기 전용 편집과 Tab/Shift+Tab의 자식 편입, 수식·Mermaid·구문 강조·주석·위키·OCI 이미지 연결, 제목 목차/검색/Projects/Notes, 실제 운영 교체·공개 HTTPS API 연결은 별도 단계. 원본 프로토타입의 비표준 인라인 문법 전체 도입 없음. 현재 CommonMark/GFM 기반을 유지하고 별도 방언은 해당 기능 계획에서 확정.

## 완료 조건과 검증

1. 타입 검사·기존 웹 검사 7개·Next 정적 출력 통과. 백엔드 변경이 없으면 같은 API 검사를 반복하지 않고 기존 격리 JAR 활용.
2. 기존 16개·300개 원문 보존 자료와 표의 정렬/불균등 행/이스케이프·CRLF·빈 셀·코드/링크 자료로 무수정 정확 보존과 수정 후 고정점 확인. 임시 검증 도구는 저장소 밖 보관.
3. 격리 실제 API와 브라우저로 표 생성→셀 수정→행/열/정렬→이동→수동 저장→재열기→출간→읽기, 기존 표 다른 블록만 수정 시 원문 불변 확인.
4. 실제 저장 응답 지연 중 다른 편집본으로 이동한 뒤 이전 ID/revision/저장 상태·주소가 되살아나지 않음을 확인. 중첩 details 기본 닫힘/열기/키보드·다른 글 이동 시 상태 경계, summary/미닫힘/코드/악성 HTML·URL·이미지·참조 링크 확인. 의도하지 않은 외부 요청과 script 실행 없음.
5. 좁은 화면/라이트·다크의 표 내부 스크롤·초점·폼과 페이지 가로 넘침 확인. 실제 OS IME와 합성 이벤트 구분.
6. 기존 배포 자원 보존, 검증 자원 정리·기록 후 목적별 커밋·main 정상 push·정확한 CI/Pages SHA 확인. author date와 실제 push 일시 구분.
