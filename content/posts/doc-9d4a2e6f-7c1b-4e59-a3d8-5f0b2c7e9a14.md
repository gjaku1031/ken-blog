주문 항목은 재고를 가진 옵션을 가리키고, 옵션의 재고가 바뀔 때마다 이력이 한 줄 남음.

## 주문과 재고

```mermaid caption="주문 항목은 옵션을 가리키면서 상품명과 단가를 복사해 둠. 옵션의 재고가 바뀔 때마다 재고 이력에 변화량과 사유가 한 줄 남음"
erDiagram
    %% legend: dotted=비식별 관계; zero=없을 수 있음; many=여러 개
    direction TB
    orders {
        uuid id PK
        varchar orderNo UK
        varchar status
        timestamptz paymentDueAt
        uuid userId FK
        int finalPaymentAmount
    }
    order_items {
        uuid id PK
        uuid orderId FK
        uuid variantId FK
```

| 테이블 | 맡은 일 | 규칙 |
| --- | --- | --- |
| `orders` | 주문 한 건. 주문자와 배송지, 금액, 상태, 입금 기한 | 주문 번호는 고유함. 입금 기한은 주문할 때 계산해 저장하고 설정을 바꿔도 그대로임 |
| `order_items` | 주문에 담긴 옵션과 수량 | 상품명, 옵션명, 썸네일, 단가를 복사해 둠. 상품을 고치거나 지워도 주문 내역이 바뀌지 않음 |
| `order_status_histories` | 상태가 바뀐 기록 | 이전 상태, 새 상태, 사유를 남김. 주기 작업의 자동 취소도 여기에 남음 |
| `product_variants` | 옵션의 가격과 현재 재고 | 재고는 0 이상(`CHECK`). 한 상품 안에서 옵션 이름은 고유함 |
| `inventory_adjustments` | 재고가 바뀐 기록 | 변화량과 사유. 옵션마다 변화량의 합이 현재 재고와 같음. 주기 작업이 바꾼 기록은 행위자가 비어 있음 |

## 규칙을 지키는 곳

| 규칙 | 지키는 곳 |
| --- | --- |
| 재고는 음수가 될 수 없음 | DB의 `CHECK`와 애플리케이션의 검증 |
| 주문 번호는 고유함, 한 상품 안에서 옵션 이름은 고유함 | DB의 고유 제약 |
| 기한이 지난 결제 대기 주문을 빠르게 찾음 | 결제 대기 주문에만 거는 부분 인덱스 |
| 주문 상태는 정해진 전이만 허용함 | 애플리케이션의 전이 표 |
| 재고를 바꾸면 같은 트랜잭션에서 이력을 남김 | 애플리케이션의 코드 규칙 |
| 주문과 주문 항목의 외래 키는 반드시 채움 | 애플리케이션. DB의 열은 비어 있을 수 있음 |
