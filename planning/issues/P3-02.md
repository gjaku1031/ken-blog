## 문제와 선행 조건

Notes는 준비 화면이며 과목·회차 저장/조회가 없음. P3-01의 섹션·소속별 Post/편집본 흐름이 main·CI·Pages에 반영된 후 구현. HANDOFF §5.4, §5.6, §6.7~6.8, §9.16 기준. 샘플 과목/회차 시드 없음.

## 구현 범위

- Course 식별자·주소·분야·이름·한 줄 설명·진행 중/완결 상태. Post의 Notes 섹션·course FK·회차 순서를 기존 편집본/출간과 연결. Notes에는 Tech 분류·태그·관련 프로젝트를 허용하지 않음.
- ADMIN 과목 생성/수정/삭제와 회차 추가/수정/출간. 과목 삭제 시 소속 회차·편집본·관계 정리, OCI 원본 객체 자동 연쇄 삭제 없음. 빈 필드/잘못된 소속/순서 충돌은 ProblemDetail.
- `/notes/` 분야별 3/2/1열 과목 카드, 권한별 회차 수·최신 날짜·빈 과목. 기존/새 분야 선택과 생성 후 소개로 이동.
- `/course/`의 정적 쿼리 주소, 고정 사이드바와 오른쪽 과목 소개/회차. 인라인 수정 Enter/Esc, 삭제 범위 확인, 회차 이전/다음·목차·주석·위키/역링크·첨부 재사용. 직접 주소/새로고침·소속별 링크 이동.
- 익명은 비공개 회차를 목록/개수/날짜/이전다음/검색 후보에서 제외. 직접 URL은 기존 비공개 글 잠금 계약 유지. USER/ADMIN에서만 비공개 본문·첨부·이동 정보 제공.
- 과목 내 표시 순서와 현재 n/N은 같은 권한 필터 기준. 긴 사이드바는 내부 스크롤하며 모바일에서 가로 넘침 없음. 삭제/순서 변경 뒤 표시 번호 일치.

## 회차 번호와 삭제 기준

회차의 저장 순서는 과목 안에서 정렬하는 값으로 사용하고, 공개 화면의 번호와 `n/N`은 현재 권한으로 읽을 수 있는 회차 목록에서 계산. 사이드바·메타·이전/다음·혼합 피드가 같은 표시 번호를 사용해 숨겨진 회차의 순서·건수를 노출하지 않음. 삭제 뒤 남은 회차의 정렬 순서는 유지하며 표시 번호만 다시 계산. 과목 삭제 후 남은 편집본이 과목을 되살리거나 다른 과목으로 자동 출간되지 않도록 소속 기준을 재검증.

기존 검사·빌드와 격리 HTTP에서 마이그레이션·과목 CRUD·회차 편집본/출간·권한별 개수·삭제/소속/순서·첨부 우회 확인. 브라우저의 생성→다음 회차→저장→출간→목록/소개/회차 이동·인라인 키보드·모바일 확인. 변경 영역 밖 전체 회귀 반복 없음. 문서·계획·수용 표 갱신 후 기능별 커밋·main 정상 push·정확한 SHA CI/Pages 확인.
