# 홈 소개 이메일·저장 오류 수정

## 요청과 수용 기준

- 홈 소개 연락처를 공개 이메일로 전환, 홈 카드와 미리보기의 전화 아이콘을 메일 아이콘으로 교체.
- 이메일 입력 후 저장 실패 원인 확인과 정상 저장·재조회 검증. 기존 소개·사진 유지, 전화번호 공개 제거.
- 인증 계정·SMTP 변경 없음. 최신 사용자 요청의 공개 연락용 이메일만 대상.

## 조사·검증 계획

- 기존 폼은 전화번호 필드에 이메일 전송, 서버는 숫자 전화번호 정규식으로 입력 거절. HTTP 400을 공통 응답 오류로 표시하는 구조 확인.
- 이메일 DTO·저장 필드·형식 검증·빈 값·안내를 일치시키고 새 Flyway로 기존 DB 이력 보존.
- 기존 검사·격리 HTTP 및 브라우저로 텍스트·사진·이메일 저장, 잘못된 입력과 미저장 데이터 보존 확인. 운영 배포 후 공개 API·Pages 동일 변경 확인.
- 사용자 미저장 소개를 임의 게시하지 않으며 운영 원고·QA 자료·기술 목록 변경 없음.

## 구현과 검증

- 운영의 기존 멀티파트 요청에서 HTTP 400과 입력 안내 ProblemDetail 재현, 요청 전후 공개 프로필 불변 확인. 전화번호 정규식과 이메일 입력 불일치가 원인.
- 공개·관리 DTO와 저장 필드의 `email` 전환, V23 신규 마이그레이션으로 전화번호 컬럼 제거와 빈 이메일 컬럼 추가. 이름·소개·GitHub·사진 보존. 기존 전화번호의 이메일 자동 이관 없음.
- 이메일 입력·메일 아이콘·인코딩한 mailto 링크, 선택적 빈 값 숨김, 254자 길이와 모바일 줄바꿈 적용. 이름 필수·필드 길이·400 입력 안내 보완.
- API 최종 clean verify 기존 28개, 웹 타입·기존 7개·정적 17경로 빌드 통과. 최초 API 검사의 이전 V22 기대값 실패 뒤 기존 검사 V23 참조 수정, 최종 새 빌드 통과와 구별.
- 격리 V22→V23 기존 소개 보존·전화번호 비공개화 확인. 멀티파트 및 JSON 저장·재조회, 플러스 주소·최대 길이·빈 값·앞뒤 공백, 잘못된 주소·제어문자·구 phone 요청 거부 확인.
- 격리 사진 업로드·유지·삭제와 실패 시 소개/사진 불변, 브라우저 저장·새로 조회·되돌리기·입력 보존·홈 링크·모바일 라이트/다크 확인. 가로 넘침·런타임 오류 없음.
- 브라우저 검증 도구의 이미지 경로 접근과 빈 문자열 입력 차이를 각각 접근 가능한 파일 경로·실제 키 입력으로 보정 후 최종 통과. 제품 오류와 구별.
- 운영 V22 스키마의 적용 전 백업과 프로필 스냅샷을 저장소 밖 비공개 파일로 보관. 운영 V23·이메일 API 반영 후 기존 소개·사진 응답, MFA 세션, 환경 파일 불변과 공인 health UP 확인. 동일 SHA Pages 최종 확인 대상.
