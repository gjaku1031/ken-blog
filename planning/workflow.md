# 작업과 기록 기준

계획 작성 → 구현·검증 → 작은 커밋 → `main` 직접 push → 다음 계획.

2026-09-26 진행 방식 변경: 남은 로드맵을 자율 진행하며 단계별 계획·검증 기록 유지. 신규 학습 자료 작성 중단, 기존 로컬 자료 보존.

- PR 생성 없음. 단계별 추가 승인 대기 없이 범위·제외 항목과 검증 근거를 기록하며 진행.
- 커밋은 영어 Conventional Commits. 문서·주석은 한국어, 문서는 명사형 종결.
- 계획별 문제·포함 및 제외 범위·완료 조건·실행한 검증을 기록.
- 실행하지 않은 테스트나 구현하지 않은 기능의 완료 표시 없음.
- 커밋은 변경 목적과 검토 가능한 크기로 구분. 하루 한 커밋 제한 없음. 같은 날 설정·기능·테스트 등 여러 커밋 가능하며, 큰 기능은 빌드 가능한 중간 단계로 분리. 커밋 수를 늘리기 위한 의미 없는 분할 없음.
- author date는 2026년 5월부터 이어서 배치하되 같은 날짜의 여러 커밋과 0~2일 작업 간격 허용. 실제 작업 시점은 committer date와 검증 기록으로 구분.
- 완료 보고에는 커밋별 author date와 실제 push 날짜를 구분해 표기. GitHub의 push 시각은 소급 변경되지 않음.
- 비밀 설정은 저장소 밖에서 관리. `docs/study/`는 Git에서 제외하는 로컬 학습 자료.
- 공개 문서는 변경 이유·동작·검증 중심으로 작성.

- 단순 기능에는 신규 테스트 코드 추가 없음. 기존 테스트는 유지하며 구조 변경에 필요한 참조만 정리. 검증은 변경에 맞는 빌드·기존 검사·실제 HTTP 확인 중심으로 수행.

## 검토·반영 단위

사용 가능한 기능 단위로 계획과 반영을 묶음. 작은 수정마다 전체 DB·전체 화면·모든 폭의 검증을 반복하지 않음. 기존 자동 검사와 변경된 권한·저장·실패 흐름을 우선하며, 변화 없는 영역의 확대 검증은 회귀 근거가 있을 때 수행. CI·Pages 결과는 전달 단위의 최종 SHA에서 확인하고 확인 대기 중 다음 범위의 조사·계획 작성 가능.
