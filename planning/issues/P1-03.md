# P1-03: OCI Object Storage 이미지 첨부 기반

상태: **계획 초안 — 승인 전** · 선행: P1-02A 완료

## 문제

게시글에 사용할 이미지의 실제 파일 저장소와 메타데이터·접근 권한 계약 없음. 이미지 바이트는 OCI Object Storage에 보관하고 Spring이 업로드 권한과 파일 검증을 담당할 기반 필요.

## 포함 범위

- OCI Object Storage 연결 설정과 파일 저장·조회·삭제를 담당하는 구체 서비스 구성. SDK와 인증 방식은 실제 사용할 버킷의 접근 방식 확인 후 결정.
- 파일 이름과 별개인 서버 생성 object key, 크기·허용 이미지 형식 검증, DB의 첨부파일 메타데이터와 업로드 사용자 기록.
- 관리자 업로드·삭제와 세션 인증·권한·CSRF 검증, Swagger Controller 계약 및 안전한 ProblemDetail 응답.
- 원본 파일의 비공개 저장을 기본안으로 검토. 초안·출간 상태에 따른 다운로드 공개 여부와 URL 제공 방식은 구현 전에 확정.
- 업로드 실패, 메타데이터 저장 실패, 삭제 재시도에서 DB와 Object Storage의 불일치 처리 정의.
- 기존 운영 데이터와 분리한 테스트 객체로 업로드·조회·삭제 검증. 실행·학습 자료·도면 갱신.

## 제외 범위

완성된 에디터 이미지 블록·자동 리사이즈·CDN·동영상·임의 확장자 첨부·기존 버킷 전체 정리 포함하지 않음. 공개 버킷 전환·새 유료 자원 생성·기존 객체 일괄 삭제 없음.

## 승인 후 확인할 사항

- 사용할 OCI 리전·namespace·버킷과 인증 수단. 실제 비밀값은 저장소 외부 관리.
- 최초 허용 형식과 최대 크기. 기본안은 JPEG·PNG·WebP 이미지, 파일당 10 MiB 이하이며 SVG 등 실행 가능한 형식 제외.
- 글 공개 상태가 아직 없는 현재 단계의 다운로드 권한. 관리자 전용 검증 경로부터 만들지, 공개된 첨부를 구분하는 메타데이터를 함께 둘지 결정.
- 실제 OCI 검증에 사용할 전용 object key 접두사와 접근 권한. 접속 정보가 없으면 실제 연결 검증을 완료로 기록하지 않음.

## 완료 조건

- [ ] 비밀값 외부 주입과 명시적인 저장소 설정.
- [ ] 관리자 업로드·삭제와 세션 인증·권한·CSRF 검증.
- [ ] 허용 형식·크기·object key 검증 및 메타데이터 저장.
- [ ] 저장소 또는 DB 실패 시 고아 객체·불완전 메타데이터 처리 검증.
- [ ] 실제 파일 업로드·다운로드·삭제의 결과 기록.
- [ ] 기존 기능 회귀·CI·실행 안내·학습 문서 갱신.

## 검증 방법

격리된 MySQL과 테스트용 객체 이름 사용. 운영 버킷 정책이나 기존 객체를 바꾸지 않고 이번에 만든 객체만 정리. 외부 저장소 장애를 재현한 확인과 실제 OCI 연결 결과는 구분해 기록. 신규 테스트 코드는 추가하지 않고 기존 검사·빌드·격리 HTTP 요청으로 검증. 인증 정보나 다운로드 권한 토큰을 로그에 남기지 않음.

다음 작업 제안이며 P1-02A 승인으로 첨부파일 구현까지 승인된 상태는 아님.
