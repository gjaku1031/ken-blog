# P0-02: API 오류 응답과 Swagger 계약

상태: **승인됨 — 구현 진행 중** · 선행: P0-01 완료

## 문제

초기 앱은 기동 확인만 제공. 다음 기능에서 사용할 API 명세와 오류 응답 규칙 필요.

## 포함 범위

- API 문서화 도구의 호환 버전 확인과 Swagger UI·OpenAPI 구성.
- 작은 상태 조회 API를 명세용 Controller 인터페이스와 구현체로 작성.
- Spring ProblemDetail 기본 처리와 필요한 앱 예외 변환 경계 결정. 불필요한 전역 핸들러 추가 없음.
- 잘못된 입력·요청 형식·예상하지 못한 오류의 안전한 응답 검증.
- Kotlin 클래스·함수 KDoc과 초보자 학습 문서 보완.

## 제외 범위

MySQL·JPA, 로그인·Redis, 첨부파일, Next 화면 연결, 운영 배포 포함하지 않음.

## 완료 조건

- [ ] 명세 인터페이스와 실제 응답 일치.
- [ ] 오류 응답의 상태·Content-Type·공개 가능한 본문 검증.
- [ ] Spring 기본 프로토콜 헤더 보존 여부 확인.
- [ ] 앱별 빌드·CI 통과와 변경 범위 검토.

## 구현·검증 기준

- `GET /api/v1/status`: `{"status":"UP"}` 반환. 프로세스 응답 확인용이며 DB·외부 서비스 상태를 의미하지 않음.
- Swagger 명세 전용 인터페이스와 실제 Controller 분리. springdoc 3.x의 배포 버전과 Spring Boot 4 호환성 확인 후 버전 고정.
- 오류 형식은 RFC 9457 ProblemDetail. Spring 기본 예외 처리의 상태·헤더 유지, 예상하지 못한 예외는 공개 가능한 고정 500 응답으로 변환.
- 입력 오류 검증용 Controller는 테스트 소스에만 작성. 운영 API에 오류 유발 경로 추가 없음.
- HTTP 검증: 정상 상태, 잘못된 입력·JSON·메서드·미디어 타입·없는 경로, 예상하지 못한 오류, 405 Allow 헤더, OpenAPI 응답 계약과 Swagger UI.
- 테스트는 Kotlin으로 작성. Maven verify 및 GitHub CI 결과 기록.
- 커밋 지정 날짜와 실제 푸시 날짜를 완료 보고에서 구분.

## 근거

- [Spring Error Responses](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-ann-rest-exceptions.html): ProblemDetail과 ResponseEntityExceptionHandler.
- [springdoc 공식 문서](https://springdoc.org/): Spring Boot 4와 springdoc 3.x 호환성.
