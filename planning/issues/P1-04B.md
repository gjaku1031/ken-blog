# P1-04B: 출간 상태와 권한별 게시글 조회

상태: 구현·격리 검증 완료 — main·CI 반영 진행. 2026-09-26 전체 잔여 작업 자율 진행 지시 적용.

## 목적과 근거

초안 CRUD 다음에 공개 방문자·로그인 열람자가 실제 출간된 글을 조회할 경계 마련. Redis 캐시는 공개 데이터 판정이 확정된 뒤 별도 단계에서 연결. 핸드오프 4장의 공개/비공개 규칙과 5.2의 최초 출간일 보존을 반영하며 기존 Kotlin·JDBC 인증·Next 정적 Pages 구성을 유지.

## 범위

- Flyway V5로 posts에 DRAFT/PUBLISHED 상태, PUBLIC/PRIVATE 공개 범위, nullable published_at 추가. 기존 글은 모두 DRAFT·PRIVATE로 시작해 자동 노출 방지. 최초 출간 시각은 UTC로 저장하고 화면용 출간일은 Asia/Seoul 기준 제공.
- 관리자 상세·목록 DTO에 상태·공개 범위·출간 시각 추가. 기존 title/slug/body 필수 입력과 1 MiB 본문 계약 유지. 기존 생성은 초안 상태 유지.
- POST `/api/v1/admin/posts/{id}/publish`에 visibility 필수. 출간 또는 재출간, 최초 published_at 유지. POST `/api/v1/admin/posts/{id}/unpublish`로 초안 전환. PATCH `/api/v1/admin/posts/{id}/visibility`로 범위만 변경. ADMIN·CSRF 필요, 성공 200 상세 DTO/no-store.
- 상태 전환과 기존 본문 수정은 같은 행 잠금을 사용해 서로의 필드를 오래된 값으로 덮어쓰지 않도록 처리. 같은 상태로 반복 요청해도 최초 출간 시각을 바꾸지 않음. 없는 양수 ID404, 잘못된 ID·본문400, DB연결503, 기존 ProblemDetail 유지.
- GET `/api/v1/posts?page=0&size=10`은 출간된 글만. 익명은 PUBLIC, USER·ADMIN은 PUBLIC/PRIVATE 조회. 본문 없는 DTO 생성자 쿼리, published_at DESC/id DESC, size1~100 및 JPAoffset범위 검증. 권한 필터를 DB 조회/건수 계산 양쪽에 적용.
- GET `/api/v1/posts/{slug}`는 출간된 글 상세. 존재하지 않거나 DRAFT면404. 공개 글 또는 로그인 사용자는 본문 포함. 익명으로 비공개 slug 직접 진입 시 핸드오프4.2의 잠금 화면용 최소 메타데이터(id·slug·title·출간일·locked=true)만 반환하고 body는null. 본문·요약·관련 글·첨부 정보는 반환하지 않음. 이 제목 공개 예외는 직접slug조회에만 적용하며 목록에는 비공개 글이 없음.
- 익명 판정은 AnonymousAuthenticationToken의 isAuthenticated 값을 신뢰하지 않고 ROLE_USER/ROLE_ADMIN으로 읽기 권한 구분. 공개/인증 경로 응답은 우선 모두 no-store, Redis와 CDN 캐시 없음.
- 지정 공개 origin의 GET CORS만 신규 공개 게시글 경로에 추가. 자격 증명 CORS는 기존 명시적 인증 origin에서만 선택적으로 허용. 공개 HTTPS 주소 연결·기존 VM 교체 없음.
- 게시글 수정은 기존 관리자 직접 PUT 계약 유지. 에디터의 출간본과 분리된 임시저장 사본은 후속 에디터 단계에서 추가하며, 이번 출간 상태 기능을 그 기능까지 완료한 것으로 표시하지 않음.

## 제외 및 후속

공개 화면·분류·태그·시리즈·검색·프로젝트·과목·위키 링크·리비전 초안·첨부 연결·Redis 캐시·GA·기존 배포 교체 제외. 전체 목표에서 제외하는 항목이 아니라 다음 계획에서 구현할 항목. 학습 문서 추가/갱신 없음.

## 검증

- 기존 테스트의 Flyway 기대 버전만 필요한 만큼 변경, 신규 테스트 파일 없음. 빌드·기존 테스트·격리 HTTP 실제 실행.
- 초안은 익명/USER 공개목록과 직접slug조회에서 제외. PUBLIC출간 후 목록/상세, PRIVATE전환 후 익명목록·건수 제외/직접잠금본문null, USER본문허용 검증.
- 관리자만 상태 변경, CSRF 누락403/익명401 구분. 출간/철회/재출간과 반복 요청에서 최초published_at 보존, KST출간일 확인.
- 페이지 정렬·입력오류·전체건수 권한 일치. 공개조회 응답에 엔티티·세션정보·private본문 누출 없음.
- 기존 초안 CRUD·첨부 관리자 권한·JDBC세션·ProblemDetail 유지. Buildpacks·격리 Compose 대표흐름, DB장애503/복구, 생성자원정리.
- 기능별 Conventional Commits로 main 직접push 후 CI/Pages 확인. 실제 작업·검증일과 개발기록용 author date 구분. 기존배포및PORT작업보존.

## 검증 중 발견 및 정정 — 2026-09-26 UTC

- 첫 빌드에서 멤버 확장 함수 참조 컴파일 오류 발견, 람다 호출로 정정. 이후 기존 API 검사 28개 실패·오류·건너뜀 0 및 패키징 성공.
