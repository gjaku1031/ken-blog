# P1-01: MySQL·JPA·Flyway와 게시글 저장 기반

상태: **완료** · 선행: P0-04 완료

## 문제

현재 API에는 DB 연결과 게시글 저장 기능 없음. 기능별 화면과 로그인에 앞서 재현 가능한 스키마와 실제 MySQL 저장·조회 검증 필요.

## 포함 범위

- Spring의 MySQL·JPA·Flyway 의존성과 환경변수 기반 연결 설정.
- 개발용 MySQL Compose 구성과 격리된 데이터 볼륨. 기존 클라우드 DB·운영 데이터 변경 없음.
- Flyway 초기 마이그레이션과 JPA 스키마 검증. 앱 시작 시 자동 스키마 수정 사용 없음.
- 게시글의 ID·제목·고유 slug·초안 본문·생성 및 수정 시각을 담는 최소 모델.
- Spring Data JPA `PostRepository : JpaRepository<PostEntity, Long>` 인터페이스와 구체 `PostService`를 통한 저장·ID 및 slug 조회. 기본 CRUD는 상속하고 slug 조회만 파생 쿼리로 선언.
- 빈 제목·slug 중복 등 저장 계약과 예외 변환 경계 정의.
- 격리된 실제 MySQL로 마이그레이션·저장·재조회·실패·롤백 검증. H2 결과로 MySQL 호환성을 대신하지 않음.
- 실행 안내와 초보자 학습 문서 작성.

## 제외 범위

인증 없는 게시글 작성 API 공개, 로그인·권한·출간 기능, 완성된 에디터 형식, Redis·첨부파일 연동, 운영 DB 생성·마이그레이션 포함하지 않음. 초안 본문은 초기 저장용이며 이후 에디터의 블록 구조를 확정하는 단계가 아님.

## 완료 조건

- [x] 환경변수로 개발 DB 연결, 비밀값 Git 제외.
- [x] 빈 MySQL에 마이그레이션 적용 및 재시작 시 중복 실행 없음.
- [x] Repository의 저장·조회와 DB 제약 조건 검증.
- [x] 트랜잭션 실패 시 부분 저장 없음.

## 검증 방법

ARM64 환경에서 사용할 수 있는 MySQL 이미지와 테스트 도구 호환성을 먼저 확인. 테스트용 컨테이너와 별도 DB를 사용하고 실제 설정값을 로그에 출력하지 않음. 마이그레이션·스키마 검증·동일 slug 충돌·트랜잭션 롤백을 실제 MySQL에서 실행. 이번에 만든 테스트 자원만 정리.

사용자의 다음 진행 요청으로 P1-01 승인 확인. 아래 완료 조건은 실제 검증 결과로 갱신.

구현에 따른 README·런타임 안내·대문의 아키텍처 도면도 현재 상태에 맞춰 갱신. 공개 HTTPS API 연결은 이번 범위에 포함하지 않음.

## 구현 계약

- `posts`: 자동 증가 ID, 제목, 고유 slug, 초안 본문, UTC 생성·수정 시각.
- 제목은 앞뒤 공백 제거 후 Unicode 코드 포인트 1~200자. slug는 앞뒤 공백 제거·지역 설정과 무관한 소문자 변환 후 ASCII 영숫자와 단일 하이픈, 최대 160자.
- 본문은 원문 유지, UTF-8 기준 최대 1 MiB. 수정 기능은 아직 없어 최초 수정 시각은 생성 시각과 동일.
- 서비스 입력 오류는 `InvalidPostDraftException`, DB의 이름 있는 slug 고유 제약 위반은 `DuplicatePostSlugException`으로 전달. 예외를 정상 반환으로 삼키지 않고 트랜잭션 롤백.
- 새 초안 저장은 `saveAndFlush`로 제약 검사 시점을 유지. flush는 커밋이 아니며, 같은 외부 트랜잭션의 앞선 저장까지 롤백하는 계약 유지.
- ID 조회는 상속 `findById`의 `Optional`을 `findByIdOrNull`로 바꾸고 slug는 `findBySlug` 파생 쿼리 사용. 조회 결과가 없으면 `null`. 공개 게시글 HTTP API가 없으므로 이번 전용 예외에 대한 새 HTTP 계약도 없음.
- MySQL 8.4.11, Flyway V1, JPA `ddl-auto=validate`. 테스트 DB와 개발용 Compose 볼륨은 분리.

## 검증 기록

실제 작업·검증일: 2026-09-25.

- ARM64·Docker 29.8.1·MySQL 8.4.11·Testcontainers 2.0.5에서 `./mvnw -B -ntp clean verify` 통과.
- 기존 MVC 15개와 영속화 6개, 총 21개 테스트. 실패·오류·건너뜀 0.
- 제목 200개 이모지·본문 정확히 1 MiB의 저장과 재조회, 한도 초과·빈 입력 거부 검증.
- 정규화된 slug 고유 충돌 시 전용 예외, 외부 트랜잭션의 앞선 저장까지 롤백 확인.
- 빈 DB의 Flyway V1 적용과 Hibernate 스키마 검증, 같은 DB의 후속 migrate 적용 건수 0 확인.
- [원격 CI](https://github.com/gjaku1031/ken-blog/actions/runs/36137705283)의 API·Web 성공. CI는 실제 MySQL 테스트와 패키징한 jar의 DB 연결·HTTP health 포함.
- [Pages 배포](https://github.com/gjaku1031/ken-blog/actions/runs/36137705417) 성공. 공개 홈 200·API 미설정 안내 유지, 도면 4개 HTTP 200 및 소스 산출물과 바이트 일치 확인.
- 라이트·다크 PNG 시각 점검, SVG 아이콘 내장·외부 이미지 참조 없음 확인. 이번 프론트 코드 변경 없음.

- 현재 소스 Buildpacks JVM 이미지 생성 성공, 전용 Compose의 API health `UP` 확인.
- 확인 행 1개 저장 후 Compose down/up에서 행 1개·Flyway 성공 이력 1개 유지. 재기동 시 추가 마이그레이션 없음·JPA 초기화·정상 health 확인.
- 전용 검증 컨테이너·네트워크·볼륨·임시 환경 파일 정리. 기존 앱·Redis 유지.
- 새 DB 구성의 전체 4GB 메모리 예산, 공개 HTTPS API 및 작성 화면은 이번 검증 범위에 포함하지 않음.
