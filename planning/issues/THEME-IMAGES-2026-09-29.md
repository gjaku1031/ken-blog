# 아키텍처 이미지 테마 자동 전환

## 문제와 범위

- 다크 화면에서 라이트 도면과 별도 다크 접기를 중복 표시한 구성의 부자연스러움 수정 요청
- 내부 이미지 한 블록에 선택적 다크 첨부 연결, 사이트 테마에 맞는 본문·확대 이미지 자동 선택
- 기존 첨부 권한·일반 이미지·Markdown 원문·편집 캡션/폭/정렬·전체 첨부 선언 보존
- 아키텍처 문서 208의 접기/중복 이미지 제거 및 기존 첨부 52~55 재사용
- 신규 테스트·마이그레이션·이미지 재업로드 없음

## 수용 기준

- 기본 이미지와 다크 이미지의 파싱·직렬화·참조 집계·MCP 선언 검사 일치
- 단일 이미지에서 라이트/다크 전환, 확대 보기와 편집 미리보기의 동일 이미지 표시
- 일반 이미지 유지, 잘못된 ID/원격 주소 차단, 다크 첨부 실패의 기본 이미지 대체
- 권한·문서 변경/빠른 테마 왕복의 이전 이미지 노출·누수 방지
- 원고의 나머지 설명·시퀀스·메타데이터 보존
- 기존 검사·정적 빌드·격리 HTTP/브라우저·운영 문서와 Pages 검증

## 진행

- 현재 이미지 렌더러의 단일 attachmentId 처리 및 Mermaid의 data-theme 구독 확인
- 이미지 Markdown에 선택적 `dark=<ID>` 연결 추가 및 두 첨부의 파싱·편집 직렬화·전체 참조 집계 반영
- 권한별 두 첨부 병렬 준비, 현재 테마 이미지 한 장 표시, 확대 창의 src·크기 동기화, 요청 종료의 blob 해제 구현
- MCP 기본·다크 ID 집계와 안전 정수 상한 검사, 작성 계약 반영
- 웹 타입 검사·기존 검사 7개·정적 빌드 통과
- 저장소 밖 계약 점검에서 기존 이미지·참조 이미지·잘못된/중복 dark·범위 초과·코드/HTML 제외·편집 후 연결 보존 확인
- 격리 읽기 전용 브라우저에서 실제 PNG SHA-256으로 두 도면의 양 테마 일치, 열린 확대 창 전환, 빠른 12회 왕복의 추가 요청 없음, 다크 새로고침, 다크 404 대체와 일반 이미지 유지 확인
- 라이트/다크 스크린샷 시각 확인, API 기존 검사 28개 및 Docker 이미지 빌드 통과, 운영 API/Pages 및 문서 교체 검증 진행
- 병행 작업 `621dae8`의 본문 입력 안정화 변경 보존, 통합된 소스에서 최종 타입·정적 빌드 재확인
