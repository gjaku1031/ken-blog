# 공개 본문 정적 생성과 검색 메타데이터

## 문제와 범위

- GitHub Pages 초기 HTML에 글 본문 없이 브라우저 요청 전 안내만 포함되는 상태 확인
- 공개 API·일반 HTTP 정상 응답과 별개인 외부 웹 열람 도구의 접근 실패 원인 미확정
- 공개 Tech·프로젝트 대문/문서·Notes 소개/회차의 본문을 포함한 정적 주소 추가, 기존 쿼리 주소 호환 유지
- 공개 목록·홈 소개 초기 렌더링, 글별 제목·설명·canonical·공유 메타데이터와 사이트맵 추가
- GitHub Pages·기존 디자인·관리자 인증·편집기 유지, API와 DB 구조 변경 제외

## 갱신 방식과 경계

- 로그인 없는 공개 API 응답만 빌드 입력으로 수집, 비공개·잠금·미출간 데이터 제외
- 공개 데이터 수집 오류 시 불완전한 새 산출물 배포 중단
- GitHub Actions 15분 간격 확인 후 콘텐츠 변경 시 재생성·배포, 기존 push/수동 실행 유지
- 조회수 변화는 재배포 판정에서 제외, 본문·공개 범위·순서 등 변경 반영
- 새 글은 정적 주소 생성 전 기존 주소로 접근 가능, 비공개 전환·삭제의 정적 사본 제거는 다음 성공 배포 시 반영
- 예약 작업 지연과 기존 브라우저·검색 서비스 캐시의 즉시 삭제 보장 불가
- 외부 열람 도구의 네트워크 접근 오류 해결 보장 제외

## 수용 기준

- JavaScript 없이 공개 글 제목과 본문 확인
- 공개 주소의 canonical·사이트맵 일치 및 basePath 적용
- 기존 주소·로그인 상태·프로젝트 문서/Notes 회차 탐색 유지
- 비공개 자료의 정적 HTML·RSC·전역 스크립트 혼입 없음
- 빌드 입력 장애·삭제·비공개·새 글의 동작을 격리 검증으로 확인
- 기존 웹 검사·타입 검사·정적 빌드·브라우저 확인 통과
- 동일 전달 SHA의 CI·Pages 및 실제 공개 URL 확인

- 익명 공개 API 스냅샷 수집·내용 지문 비교·빌드 전후 동일성 검사와 변경 시 Pages 배포 구현
- 본문과 분리된 주소 목록을 이용해 생성 완료한 공개 경로로 연결, 신규·비공개 자료의 기존 쿼리 경로 유지
- 기존 읽기 화면에 초기 본문 전달, 세션별 재조회 실패·잠금·삭제 시 이전 본문 제거
- 홈페이지·목록의 초기 공개 내용, 글별 검색·공유 메타데이터, 공개 사이트맵과 관리/작성/검색 색인 제외 구현
- Next 정적 내보내기의 빈 동적 주소 제약에 대해 내부 예약 주소의 notFound 처리 후 산출물 제거 적용

- 초기 HTML·RSC·공통 스크립트·사이트맵의 비공개 검증 문자열 제외, 공통 스크립트에 전체 원문 미포함 확인
