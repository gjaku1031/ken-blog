## 구현 범위와 계약

### 이미지 연결

- Flyway V9로 `post_attachments`와 `editor_draft_attachments` 관계 관리. 부모·첨부 FK, 부모/첨부 쌍 고유 제약, 첨부별 역조회 인덱스. 글/편집본 삭제 시 해당 연결만 제거하고 OCI 객체는 자동 삭제하지 않음.
- 관리자 게시글 생성/전체 수정과 편집본 생성/수정 DTO에 선택적 `attachmentIds` 추가. 관리자 상세 응답에 연결 ID 목록 제공하고 기존 본문 없는 목록 계약 유지.
- 새 글은 생략/null이면 빈 연결. 기존 글을 바탕으로 편집본을 만들 때 생략/null이면 현재 원본 연결 상속. 수정 시 생략/null은 기존 연결 유지, 명시적 `[]`는 해제. 기존 화면이 아직 이 필드를 보내지 않아도 원문 이미지를 실수로 분리하지 않는 호환 경계.
- 목록은 양수 ID 최대 100개, 중복은 제거하고 정렬. 원소 null·0·음수·상한 초과는 안전한 400. 없는 ID는 404, READY 이외는 409. 원문 입력/분류/revision/고유 slug 오류와 같은 DB 트랜잭션에서 연결 변경도 롤백.
- `attachmentIds`는 관리자가 해당 글에 연결을 허용하는 명시적 데이터. 본문 정규식으로 권한을 추정하거나 서버에 별도의 Markdown 방언 파서를 추가하지 않음. 후속 편집기는 이미지 블록에서 목록을 만들어 명시적으로 전체 교체. 코드 예제나 일반 본문에 ID를 적는 것만으로 연결/열람 권한이 생기지 않음. 반대로 생략 호환 요청이 본문 표기만 지우면 기존 연결은 유지되므로 글별 URL 열람 권한도 남음. 연결을 철회하려면 `attachmentIds`에서 명시적으로 제외해야 하며 후속 화면은 이를 함께 수행.
- canonical 본문 이미지 주소는 후속 화면에서 `attachment:<양수 ID>` 사용. OCI endpoint·bucket·key·서명 URL은 본문에 저장하지 않음. 실제 화면 표시 구현은 P2-03B.
- 편집본 출간은 글 내용·분류/태그·공개 상태·이미지 연결 반영과 편집본/연결 제거를 한 트랜잭션으로 처리. 저장 중 공개 원본의 이미지 연결은 유지.

### 권한별 이미지 읽기와 삭제

- `GET /api/v1/posts/{postId}/attachments/{id}/content`: 현재 DB에서 출간 여부·열람 권한·글과 이미지 연결·READY 상태를 확인한 뒤 Spring이 OCI 입력 스트림을 열어 이미지 반환. PUBLIC은 익명 열람, PRIVATE는 기존 USER/ADMIN 규칙. 초안·없는 글/첨부·미연결·비허용 읽기는 404로 통일. 관리자 미리보기는 기존 관리자 content 경로 유지.
- 공개 범위/출간 상태는 요청마다 DB에서 판단. 이미지 권한을 Redis나 body 문자열로 판단하지 않음. 공개/비공개 모두 `private, no-store`, `inline`, 판별 MIME·길이·nosniff 적용. 공개 응답에 업로드 계정·내부 key·원본 파일명 메타데이터 불필요 노출 없음.
- OCI 스트림은 헤더 확정 전에 열어 503 ProblemDetail을 유지하고 DB 트랜잭션 밖에서 전송. 이미 시작한 전송을 공개 범위 변경 뒤 소급 취소하는 계약은 아님.
- 게시글/편집본 어디든 연결된 첨부는 관리자 DELETE에서 409. 참조 여부 검사와 DELETING 전환을 첨부 행 잠금 안에서 처리. 링크 생성/교체는 첨부를 ID 순서로 잠그고 READY 재확인하여 삭제와 경합해도 깨진 연결이 확정되지 않게 구성. 기존 PENDING 유예·보상 삭제·DELETING 재시도 유지.
- 기존 잠금 순서(분류→게시글→편집본) 뒤에 첨부 ID 오름차순 잠금을 배치. 참조 삭제는 부모 연결만 제거하고 첨부에서 부모 잠금을 거꾸로 얻지 않음. 실패한 출간/링크 변경은 모두 롤백.

### 보안·문서

- 새 읽기 GET만 공개 Security 경로에 추가. 관리자 첨부 CORS는 명시된 인증 origin에 한해 GET/POST/DELETE, credentials·CSRF 헤더 허용. 공개 전용 origin에는 관리자 첨부 권한 없음. 기존 로그인·JDBC 세션·ProblemDetail·캐시 경계 유지.
- Kotlin·기능별 패키지·JpaRepository·구체 Service·Swagger Controller 계약·KDoc 유지. 새 Repository 공통 추상화 없음.
- README·첨부/게시글/편집본/실행 안내·아키텍처 도면을 현재 상태에 맞게 갱신. 기존 도면의 누락된 V7/V8·프론트 로그인 화면 상태도 정정. 학습 문서 추가 없음.

## 제외 범위와 배포 경계

브라우저 업로드/붙여넣기/드롭·캡션/크기/정렬·blob 미리보기·이미지 본문 렌더링은 P2-03B. 공개 버킷·presigned URL·외부 이미지 자동 요청·Redis 이미지 캐시·자동 orphan 삭제/리사이즈 없음. 기존 운영 앱·DB·Redis·버킷 정책을 변경하지 않음. 실제 OCI 검증은 새로운 실행별 정확한 접두사의 작은 객체만 사용하고 종료 시 해당 객체만 정리.

공개 API 도메인/HTTPS 미정. 현재 세션 쿠키 SameSite=Lax는 로컬 같은 site 포트 간 검증과 교차 site Pages 운영 연결이 다름. 쿠키 정책·실도메인 연결은 별도 후속 범위이며 이번 HTTP 검증으로 공개 로그인/비공개 이미지 완료를 주장하지 않음.

1. Maven 빌드·기존 API 검사, 기존 웹 검사/정적 출력 호환 확인. 신규 저장소 테스트 없음. 필요한 기존 DTO 기대값만 최소 수정.

3. 실제 OCI PNG/JPEG 업로드 후 관계 설정. 관리자·USER·익명의 PUBLIC/PRIVATE·초안·없는/미연결 이미지 HTTP 상태와 바이트/MIME/no-store/nosniff·저장소 오류 ProblemDetail 확인. 범위 변경/출간 철회/본문에만 ID 기록/직접 ID 조회로 우회 불가 확인.
4. 편집본 저장은 공개 연결 불변, 출간 성공 시 연결 전환/편집본 제거, 실패 시 두 연결 유지. 사용 중 삭제409·해제 후 삭제204·객체HEAD404 확인. 연결/삭제 경합은 별도 연결의 잠금과 실제 동시 HTTP로 확인.
5. 정확한 CORS preflight·인증/CSRF, DB 장애시 권한 판정 우회 없음·복구, 자체자원 정리·기존 배포 동일성·검증 접두사 잔여없음 확인.
