학부모는 계정 없이 공개 경로로 들어오므로, 권한은 로그인 대신 연락처 소유 증명과 일회용 증명으로 판단하고, 그 과정에서 연락처·QR 원문이 남는 곳을 최소화함(P2). 관리자와 현장 iPad는 같은 출처의 서버 세션으로 구분함. 배포 경계는 [아키텍처](/ken-blog/post/doc-71ac4b10-9f99-4251-893d-a57dd46ad334/)에서 정의함.

## 배포 구조가 만든 보안 설계

### 공개 진입점과 수신 포트

공개 HTTPS는 GCP VM의 Caddy 한 곳에서만 종료되고, 운영 VM으로는 WireGuard 터널로만 들어감. 운영 VM에서 loopback 밖으로 열린 포트는 WireGuard 상대만 접근하는 upstream 소켓 하나이고, 웹·API·PostgreSQL·Redis는 loopback에만 열림. 배포 스크립트는 전환 뒤 수신 포트가 정확히 이 목록인지 확인하고, 다르면 배포를 실패로 처리함.[* [운영 배포 절차의 공개 HTTPS 절](https://github.com/gjaku1031/npr-seminar/blob/2876cd9/ops/pve-release/README.md) · [Caddy 인입 정적 검사](https://github.com/gjaku1031/npr-seminar/blob/2876cd9/ops/pve-release/tests/caddy-ingress-static.sh)]

Caddy는 접근 로그를 남기지 않음. 개인 접근 토큰은 URL fragment(`#token=…`)로 전달되고 요청 본문으로 제출되므로 서버가 보는 경로·쿼리에 나타나지 않음.

### 같은 출처 API

화면과 API가 같은 공개 출처를 쓰고, 브라우저는 `/api/v1`만 호출함. 교차 출처 쿠키나 CORS 허용 목록이 필요 없고, 세션 쿠키는 `SameSite=Lax`로 둠. API는 설정한 공개 주소와 요청의 `Origin`, 그리고 신뢰한 프록시가 전달한 실제 출처가 모두 같을 때만 변경 요청을 받음.[* [CSRF 가드](https://github.com/gjaku1031/npr-seminar/blob/2876cd9/apps/api/src/common/auth/csrf.guard.ts) · [출처 판별](https://github.com/gjaku1031/npr-seminar/blob/2876cd9/apps/api/src/common/http/effective-origin.ts)]

### 프로세스와 DB 역할 분리

| 주체 | 권한 |
| --- | --- |
| API(`npr_app`) | 도메인 테이블 읽기·쓰기. 감사 테이블 삭제 권한 없음. Google 인증 파일을 받으면 기동 거부 |
| worker(`npr_worker`) | outbox·시도 기록 쓰기, 시트 투영에 필요한 예약·학생·회차 읽기만. HTTP 수신 없음 |
| 마이그레이션(`npr_migrator`) | 스키마 소유. 런타임에 쓰지 않음 |
| 운영 조회(`npr_readonly`) | 읽기 전용 |
| Redis 애플리케이션 계정 | `npr:*` 키와 사용하는 명령만. 기본 사용자 비활성 |

worker가 탈취되어도 예약·학생 원장을 바꿀 수 없고, API가 탈취되어도 Google 인증 파일과 문자 공급자 키는 없음. systemd 단위는 프로세스마다 다른 OS 계정과 읽기 전용 파일 시스템 보호를 씀.[* [worker 운영 절차](https://github.com/gjaku1031/npr-seminar/blob/2876cd9/apps/api/docs/worker-runbook.md) · [Redis ACL 정적 검사](https://github.com/gjaku1031/npr-seminar/blob/2876cd9/ops/pve-release/tests/redis-acl-static.sh)]

## 관리자와 스캐너 세션

관리자 계정은 운영자가 명령으로 만들며, 비밀번호는 명령행 인자가 아니라 보호된 파일 디스크립터로만 받음. 로그인은 Argon2id 해시로 확인하고, 없는 계정에도 같은 비용의 더미 해시를 검증해 응답 시간으로 계정 존재를 알 수 없게 함. 로그인에 성공하면 세션 ID를 새로 만들고 절대 만료 시각을 기록함.[* [관리자 인증](https://github.com/gjaku1031/npr-seminar/blob/2876cd9/apps/api/src/modules/admin-auth/admin-auth.service.ts)]

현장 iPad는 관리자 비밀번호를 입력하지 않음. 관리자가 5분 동안 한 번만 쓸 수 있는 페어링 코드를 만들면 iPad가 코드를 입력해 `SCANNER` 세션을 받음. 스캐너 세션은 요청마다 기기가 활성인지 DB에서 확인하고, 스캐너 경로만 쓸 수 있음.

| 항목 | 계약 |
| --- | --- |
| 저장소 | Redis(`connect-redis`). 유실되면 재로그인·재페어링 |
| 쿠키 | `HttpOnly`, 운영에서 `Secure`, `SameSite=Lax`, 경로 `/` |
| 만료 | 비활동 만료와 로그인 시각 기준 절대 만료를 함께 적용 |

| 로그아웃 | 세션 삭제와 감사 기록 |
| 스캐너 해제 | 관리자 또는 iPad에서 해제하면 세션·접속 상태·회차 잠금 즉시 삭제, 입장 기록은 유지 |

## 공개 예약의 본인 확인

| 단계 | 쓰는 비밀값 | 저장 |
| --- | --- | --- |
| 문자 인증 요청 | 인증번호(문자로만 전달) | 다이제스트, 시도 횟수, 만료 |
| 인증 통과 | 예약 증명(256비트, 한 번 응답) | 다이제스트, 연락처 다이제스트, 용도, 만료 |
| 예약 생성·변경·취소 | 예약 증명(`X-Booking-Proof`) | 같은 트랜잭션에서 소비 처리 |
| 예약 링크 열람 | 링크의 예약 ID와 연락처 | 읽기 세션 다이제스트 |
| QR 표시·입장 | QR 원문 | 다이제스트와 API 전용 키 암호문 |

예약 증명은 화면 메모리에만 두고 표시하거나 저장하지 않음. QR 원문은 URL·브라우저 저장소·쿠키·로그·클립보드에 쓰지 않고, 사용자가 다운로드를 누를 때만 식별자 없는 파일명의 PNG로 내보냄.[* [웹 안내의 시크릿 취급](https://github.com/gjaku1031/npr-seminar/blob/2876cd9/apps/web/README.md)] 비밀값을 담은 응답은 `Cache-Control: private, no-store`와 `Pragma: no-cache`를 붙임.
