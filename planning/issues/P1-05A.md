# P1-05A: Tech 분류·태그와 권한별 탐색 API

상태: 구현·격리 검증 완료, main 반영 진행. 2026-09-26 전체 잔여 작업 자율 진행 지시 적용. 선행 P1-04는 main `2ca2169` 정상 push, CI·Pages 성공.

## 문제

출간 글 API에는 제목·slug·본문만 있어 핸드오프의 Tech 분류 트리·태그 사이드바·필터를 구현할 정보가 없음. 먼저 DB 관계와 권한별 조회 계약을 추가해 화면에서 비공개 개수나 태그를 별도 필터링하지 않도록 구성.

설계 근거: 인수인계 `HANDOFF.md` §5.2/5.5/5.12, §8.8/8.10, §9.1/9.4/9.5. 프로토타입의 문자열 경로는 입력에만 사용하고 관계는 FK로 저장. 샘플 데이터 이식 없음.

## 포함 범위와 계약

### 분류

- V7에 `categories`: ID·parent_id FK·정규화된 고유 path·표시 이름·depth(1~3). `posts.category_id` nullable FK와 인덱스 추가. 기존 글은 분류 없음. 빈 폴더도 독립 레코드로 보존.
- 관리자 `POST /api/v1/admin/categories`의 `path`로 최대 3단계 경로 생성. 중간 기존 경로는 재사용, 최종 경로가 이미 있으면 409. 중간 생성도 한 트랜잭션, 오류 시 전부 롤백. `path`는 단계별 trim·소문자(Locale.ROOT)·연속 공백을 하이픈으로 정규화. 단계 이름은 1~60 Unicode 문자, 경로 최대 3단계. 빈 단계·4단계·제어 문자·허용하지 않은 기호는 400. 한글·영숫자·하이픈 허용. 표시 이름은 생성 시 입력 단계의 공백 정리값을 보존, 정규화 path와 분리. 이름 변경·이동 없음.
- 관리자 `GET /api/v1/admin/categories`에서 전체 트리와 직접/하위 전체 글 수(초안 포함) 조회. 공개 `GET /api/v1/categories`는 PUBLISHED·현재 열람 권한으로 계산한 directCount/totalCount 제공. 분류 폴더 자체는 공개 탐색 메타데이터이며 빈 폴더와 0건 표시 가능; PRIVATE 글의 존재·제목·태그·개수는 포함하지 않음.
- 관리자 `DELETE /api/v1/admin/categories/{id}`: 해당 분류 및 하위 분류에 속한 모든 글(초안 포함)을 삭제 대상의 부모로 이동, 대분류 삭제면 null. 하위부터 분류 삭제, 게시글 본문·상태·출간일 유지. 원자적 처리. 동시 참조/경로 생성 충돌은 409 또는 존재하지 않음 404로 처리하며 부분 이동·고아 FK·500 없음. 삭제가 글을 삭제하는 경로 없음.

### 게시글 분류·태그

- `post_tags`에 게시글 FK·순서·태그명 저장, 한 글당 최대 16개, 각 1~40 Unicode 문자. trim·소문자(Locale.ROOT) 정규화, 빈 값·제어 문자 거부, 정규화 중복 제거, 입력 순서 보존. 별도 Tag 서비스 인터페이스나 불필요한 태그 관리 CRUD 없음.
- 관리자 `PATCH /api/v1/admin/posts/{id}/taxonomy`에서 `{categoryId: number|null, tags: string[]}` 전체 교체. 누락/null tags는 400, categoryId는 명시 null로 해제 가능. 양수 categoryId가 없으면 404, 잘못된 입력 400, 중복/참조 경합 409. 기존 글 행 잠금과 트랜잭션 경계 유지.
- 기존 title/slug/body CRUD 입력 계약은 유지. 관리자 상세 및 공개 목록/열람 가능 상세에 category(없으면 null)·tags 배열 추가. 익명 PRIVATE 잠금 상세에는 category null·tags 빈 배열 유지, 숨겨진 본문뿐 아니라 메타데이터도 제외.
- 관리자 목록은 현재 기본 계약 유지하면서 taxonomy 확인에 필요한 추가 필드만 제공. 게시글 삭제 시 태그 FK 행 함께 정리. 본문 캐시에는 분류·태그 저장 없음, 매번 DB 현재 메타데이터 사용. taxonomy 수정으로 본문 해시·최초 출간일 변경 없음.

### 공개 필터와 태그

- `GET /api/v1/posts`에 선택적 `categoryId`, `tag` 추가. 분류 필터는 자기 노드와 모든 하위, 태그는 정규화된 정확 일치, 두 조건은 AND. 기존 페이지·크기·정렬·권한 필터를 SELECT와 COUNT 양쪽에 동일 적용. 존재하지 않는 양수 categoryId는 빈 목록, 잘못된 입력은 400. 본문 제외 SQL 유지.
- 공개 `GET /api/v1/tags`에 읽을 수 있는 PUBLISHED 글 기준 이름·사용 글 수를 사용량 내림차순/이름 오름차순으로 제공. 관리자 `GET /api/v1/admin/tags`는 초안 포함 모든 글 기준 자동완성용. 미사용/PRIVATE 전용 태그를 익명에게 노출하지 않음.
- 목록의 분류·태그 추가로 본문 전체를 로딩하거나 행별 N+1 조회하지 않음. 페이지 ID 일괄 조회·DTO 투영 등 필요한 방식 사용. 쿼리 인터페이스는 JpaRepository만 사용하고 Custom Repository/Service 인터페이스 추가 없음.
- 새 공개 GET 경로의 Spring Security·CORS 범위를 명시적으로 허용. 인증·권한·CSRF·세션 교체·ProblemDetail·JDBC 세션은 기존 계약 유지. 공개/회원 응답 모두 no-store 유지.
