프로젝트 문서와 일반 글을 작성·분류·발행하고, 프로젝트·시리즈·검색을 통해 다시 읽는 기능. 본문 편집은 Git, 글 정보 관리는 웹, 공개 반영은 Pages 배포로 구분.

## 역할과 기능

| 역할 | 기능 | 동작·완료 조건 |
| --- | --- | --- |
| 독자 | Posts 탐색 | 공개 일반 글을 분류·태그·검색으로 조회 |
| 독자 | Projects 탐색 | 프로젝트 개요·상태·기간·기술과 소속 문서 조회 |
| 독자 | 프로젝트 관련 글 탐색 | 프로젝트에 연결한 일반 글을 관련 Posts 목록에서 조회 |
| 독자 | 연속 읽기 | 같은 시리즈의 문서와 이전·다음 글로 이동 |
| 독자 | 본문 탐색 | 목차·위키 링크·역링크·주석, 이미지·도식 확대 보기(드래그 이동·휠/핀치 확대) |
| 작성자 | 원고 작성 | slug에 대응하는 Markdown 작성·Git 반영 |
| 관리자 | 글 정보 편집 | 제목·요약·분류·태그·소속·순서·관련 프로젝트 저장 |
| 관리자 | 발행 관리 | DB의 발행 상태 변경. 공개 화면은 재배포 후 반영 |
| 관리자 | 분류 관리 | 최대 두 단계의 분류 생성·이름 변경·정렬·삭제 |
| 관리자 | 시리즈·프로젝트 관리 | 묶음 정보·정렬, 프로젝트 상태·기간·기술 관리 |
| 관리자 | 첨부·위키 선언 관리 | 글별 선언 목록 전체 교체. 파일·원고 자체는 수정하지 않음 |
| 운영자 | 이미지·배포 관리 | 파일과 DB 정보 준비, 사이트·API 배포 및 복구 |

작성자·관리자·운영자는 작업 역할. 웹 권한은 설정된 관리자 계정의 `ADMIN`으로 검사. 저장소·서버·DB 접근 권한은 웹 세션과 별도.

## 프로젝트 문서와 관련 Posts

| 구분 | 소속 | 프로젝트 연결 | 탐색 위치 |
| --- | --- | --- | --- |
| 대문·아키텍처·기능·ERD·API·설계 요약·운영·보안 | `seriesId = ken-blog PROJECT ID` | 소속으로 표현 | 프로젝트의 순차 문서 목록 |
| 실험·문제 해결·독립 ADR | 시리즈 없음 또는 TECH 시리즈 | `relatedSeriesId = ken-blog PROJECT ID` | Posts와 프로젝트의 관련 글 목록 |

일반 글의 프로젝트 연결은 소속 이동과 별개. 관련 프로젝트만 지정해도 일반 글의 `section=TECH` 유지. 본인의 글 분류·일반 시리즈와 프로젝트 관계를 함께 사용 가능.

## 공개·순서·삭제 정책

| 항목 | 규칙 |
| --- | --- |
| 공개 대상 | `PUBLISHED + PUBLIC`, 소속 시리즈 공개 조건과 내부 호환 조건을 만족한 글 |
| 미발행 | `DRAFT`는 다음 공개 조회·빌드에서 제외 |
| 최초 발행 시각 | 발행 취소 후에도 보존 |
| 대문 | 소속 공개 글을 순서 → 최초 발행 시각 → ID로 정렬한 첫 문서. 미지정 순서는 마지막 |
| 빈 프로젝트 | 공개 문서가 없으면 공개 프로젝트 목록에서 제외 |
| 자동 읽기 목록 | 명시 시리즈가 없고 소분류에 속한 일반 글은 같은 소분류의 공개 글로 구성 |
| 글 편집 충돌 | `baseVersion`과 현재 `editVersion`이 다르면 409 |
| 시리즈 편집 충돌 | 조회한 `updatedAt`과 요청의 `baseUpdatedAt` 비교 |
| 첨부·위키 선언 | 버전 비교 없이 각각 전체 교체. 마지막 저장 적용 |
| 분류 삭제 | 하위 분류도 삭제하고 글은 삭제 대상의 부모로 이동. 최상위 삭제 시 미분류 |
| 시리즈 삭제 | 초안·비공개를 포함한 소속 글 또는 관련 프로젝트 참조가 남으면 거부 |
| 글 삭제 | DB 메타데이터·종속 연결 정리. Git 원고와 이미지 파일은 유지 |

DB 공개 상태와 Pages 배포 상태는 별개. 공개 저장소의 원고 파일도 사이트 발행 상태와 무관하게 저장소에서 접근 가능.

## 독자의 프로젝트 문서 탐색

1. Projects 목록에서 프로젝트 선택. 소속 공개 문서 중 첫 문서인 대문으로 이동.
2. 대문의 문서 목록에서 아키텍처·ERD 등 상세 문서를 순서대로 열람. 각 문서에서 이전·다음 문서로 이동.
3. 프로젝트 문서 화면의 관련 Posts 목록에서 문제 해결·ADR·실험 글로 이동. 일반 글에는 연결된 프로젝트로 돌아가는 링크 표시.
4. 본문에서는 목차·위키 링크·역링크로 다른 글로 이동하고, 이미지·도식은 확대 보기로 확인.

목록·문서 순서·이전·다음·관련 Posts·역링크는 빌드 시 HTML에 포함. 탐색과 본문 열람에 API 요청 없음. 관리자 메뉴 표시를 위한 로그인 상태 확인만 별도 요청.

## 새 프로젝트 문서 발행

사전 조건: 프로젝트 등록, 관리자 로그인, 원고 편집·Pages 실행 권한.

1. 프로젝트 소속과 문서 순서를 지정해 미발행 글 등록.
2. 발급받은 slug로 `content/posts/{slug}.md` 작성.
3. 이미지 원본·DB 행·글별 첨부 연결 준비, 위키 대상과 도식 확인.
4. Git 원고 반영 후 DB 발행 상태 변경.
5. Pages 빌드·배포 실행.
6. 프로젝트 목록의 문서 순서와 실제 본문 확인.

원고 누락·이미지 오류·revision 변경 시 빌드 실패. 입력 상태를 맞춘 뒤 다시 빌드. 완료 조건은 DB 발행과 실제 공개 페이지 반영 모두 확인.

## 두 화면의 동시 편집

두 화면이 `editVersion=7`을 조회한 상황. 첫 화면이 `baseVersion=7`로 저장하면 버전 증가. 두 번째 화면의 같은 기준 버전 요청은 409로 거부.

충돌 화면의 입력을 보존하고 최신 값을 다시 조회해 비교. 최신 버전 숫자만 바꾼 자동 재전송은 사용하지 않음. 세션 만료 시 재로그인 후 입력·최신 상태 재확인.

## 공개 취소

관리자가 `published=false`로 변경하면 DB는 `DRAFT`로 전환. 이후 공개 API와 해당 글을 통한 첨부 조회에서 제외. Pages를 다시 배포해 기존 글 주소·목록·프로젝트 대문의 변경 확인.

재배포 실패 시 이전 공개 파일이 남을 수 있음. 저장소 원고·이력과 독자가 내려받은 복사본은 발행 취소로 회수되지 않음.
