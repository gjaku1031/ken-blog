# 위키 링크와 제목 조회 API

`[[글 제목]]`의 조회·읽기 계약과 관리자 연결 선언·역링크의 정본. 아래 예시는 형식 설명이며 실제 운영 데이터가 아님. P2-06A 제목 조회와 P2-06B 읽기 링크는 main 반영 완료. P2-06C API·격리 재색인·선택기·역링크 화면·목차의 통합 검증 완료, main 반영 확인 전. 공개 HTTPS API 연결과 기존 운영 배포는 변경하지 않음.

## 요청과 결과

`GET /api/v1/wiki-links/resolve`에 `title` 쿼리를 반복해 1~20개 전달. 같은 제목을 반복해도 입력 순서와 중복을 유지하며 각 값마다 결과 한 개를 `items` 배열에 반환할 계약. 쉼표는 제목의 일부이므로 `title=A%2CB&title=다른%20제목`처럼 각각 별도 쿼리로 인코딩. `requestedTitle`은 요청 값의 앞뒤 공백을 제거한 문자열. 결과 상태와 필드는 다음과 같음.

| 상태 | 의미와 반환 필드 |
| --- | --- |
| `READABLE` | 읽을 수 있는 출간 Tech 글. `requestedTitle`, `status`, 이동에 필요한 `id`, `title`, `slug`만 반환 |
| `LOCKED` | 익명에게 비공개인 출간 Tech 글. `requestedTitle`, `status`만 반환 |
| `MISSING` | 대상이 없거나 초안. `requestedTitle`, `status`만 반환 |

응답 형태 예시. 실제 저장된 글이나 지금 조회 가능한 운영 API의 결과를 뜻하지 않음.

```json
{
  "items": [
    { "requestedTitle": "공개 글", "status": "READABLE", "id": 1, "title": "공개 글", "slug": "public-post" },
    { "requestedTitle": "비공개 글", "status": "LOCKED" },
    { "requestedTitle": "없는 글", "status": "MISSING" }
  ]
}
```

익명은 PUBLIC만 읽을 수 있고 PRIVATE의 존재 여부는 `LOCKED`로만 표시. USER·ADMIN 세션에는 현재 읽기 권한이 있는 PRIVATE의 이동 필드 제공. `LOCKED`와 `MISSING`에는 대상의 ID·제목·slug 필드 자체가 없으며 본문·분류·태그·첨부 메타데이터도 반환하지 않음. 이 API는 PRIVATE 글 목록이나 본문 탐색을 추가하지 않음. 응답을 읽을 수 있는 경우에도 본문 열을 조회하지 않는 경계.

## 제목 비교와 입력 제한

요청 제목은 앞뒤 공백을 제거한 뒤 비교하고 대소문자는 구분하지 않음. 악센트가 다른 글자는 같은 제목으로 간주하지 않음. MySQL 소문자 변환 결과를 이진 비교하는 방식으로 일관성 유지. 동일 제목의 출간 글이 여러 개면 최초 출간 시각 오름차순, 이어서 ID 오름차순으로 한 개 선택. 제목 중복을 새로 금지하거나 기존 글을 수정하지 않음. 제목·출간 상태가 바뀌거나 글이 삭제되면 이후 조회 결과도 바뀔 수 있음.

요청은 `title` 1~20개, 각 값은 공백 제거 후 1~200 Unicode codepoints. 디코딩된 원 입력값들의 UTF-8 바이트 합계는 1,500바이트 이하이고 URL 인코딩된 쿼리 문자열은 UTF-8 6,144바이트 이하. 빈 값·제어 문자·개행·알 수 없는 쿼리 이름·개수/길이/합계 초과는 기존 `ProblemDetail` 400 대상. 쉼표나 SQL 모양 문자열은 분리자나 쿼리로 실행하지 않고 제목 값으로 처리. 입력값은 바인딩된 조회에 사용하며, 제목 수에 상한을 두어 요청 하나의 조회 비용 제한.

## 인증·CORS·캐시 경계

익명 GET을 허용하되 PRIVATE 이동 정보는 명시적 USER·ADMIN 세션에서만 제공할 계약. JDBC 세션·권한 판별과 기존 오류 흐름 유지. 성공 응답은 `Cache-Control: no-store`. 공개 GET origin은 `APP_CORS_ALLOWED_ORIGINS`에 적힌 정확한 주소만 허용하며 자격 증명 CORS 응답은 허용하지 않음. 쿠키가 필요한 GET은 `APP_AUTH_CORS_ALLOWED_ORIGINS`의 정확한 주소에만 자격 증명 CORS 허용. 공개 origin의 자격 증명 미허용은 브라우저의 CORS 응답 접근 규칙이며 서버가 전달된 쿠키를 별도로 무시한다는 뜻은 아님. POST 등의 다른 메서드나 CSRF 예외는 추가하지 않음. DB 장애는 기존 내부 정보 없는 503 `ProblemDetail` 경계.

P2-06A는 API와 데이터 조회만 변경. 공개 Pages에는 API HTTPS 주소가 여전히 설정되지 않았으며, P2-06A 당시 실제 `[[...]]` 클릭·잠금·없는 링크 화면은 없었음.

## P2-06B 읽기 링크 — main 반영 완료

읽기 화면에서 `[[제목]]`과 `[[제목|표시명]]`을 안전한 인라인 위키 링크로 해석하는 작업. 제목 앞뒤 공백을 제거하고 1~200 Unicode codepoints만 허용하며 제어 문자·개행·대괄호·세로줄이 든 제목은 위키 노드로 승격하지 않음. 유효한 표시명은 비어 있지 않은 한 줄 일반 텍스트이며 HTML·Markdown으로 다시 실행하지 않음. 잘못 닫힘·중첩·이스케이프·과대 입력도 저장 원문을 변경하지 않고 위키 링크로 승격하지 않음. 화면 대체 표시는 기존 Markdown 규칙을 따르므로 모든 잘못된 구문이 문자 그대로 보인다는 뜻은 아님. 예를 들어 `[[a|[link](https://x)]]` 안의 일반 링크는 위키 링크가 아닌 기존 Markdown 링크로, `[[a|<b>]]`의 raw HTML은 기존 차단 규칙으로 처리. 일반 텍스트·제목·목록·인용·표·안전 접기 본문과 주석 내용에 같은 위키 문법 적용. 코드·수식·Mermaid·이미지와 대체 문자·기존 Markdown 링크의 라벨/주소·raw HTML 속 표기는 위키 링크로 해석하지 않음. 주석 말풍선은 설명만 표시하고 위키 이동을 허용하지 않으며 하단 주석 목록에는 허용된 링크를 표시.

본문 최대 UTF-8 1 MiB, 각 원문 파싱 구간에서 검사할 위키 후보 시도 최대 512개, 문서에서 조회할 고유 제목 최대 128개. 후보 512개는 본문과 모든 주석에 걸친 단일 전역 시도 횟수가 아님. 기존 API 요청은 한 번에 제목 20개·디코딩 값 합계 UTF-8 1,500바이트·인코딩 쿼리 6,144바이트를 지키고 최대 2개만 동시 처리. 같은 제목의 중복 표기는 문서 안에서 묶어 조회. 상한을 넘은 표기는 위키 링크로 승격하지 않거나 미확인 상태로 남기고, 없는 대상이라는 `MISSING`으로 오인하지 않음. 본문·세션·첨부 메타데이터를 제목 조회 요청에 싣지 않음.

`READABLE` 결과는 검증된 `slug`로 기존 정적 `/post/?slug=...`에 연결. `LOCKED`는 회색 점선, `MISSING`은 빨간 점선으로 표시하며 둘 다 일반 사용자의 이동 링크가 아님. 조회 중·API 주소 미설정·네트워크/서버/응답 오류는 별도 미확인 상태로 안내하고 명시적 재시도 제공. 오류를 무한히 자동 재요청하지 않음. 문서·경로·로그인 상태가 바뀌면 이전 요청과 결과를 폐기하고, PRIVATE 이동 정보를 로그아웃 뒤 남기지 않음. 브라우저 영구 저장소나 별도 캐시 없음.

## P2-06C 선언된 연결·역링크·목차 — 격리 API·브라우저 검증 완료

관리자 제목 부분 검색은 `GET /api/v1/admin/posts/title-search?q=...`로 출간 글 최대 7개와 정확한 제목의 현재 권한별 해석 결과를 제공. 관리자 편집기의 `글 링크` 선택기는 기존 커서·선택 범위를 보존해 `[[제목]]`을 삽입하고, 없는 유효 제목은 새 글 초안으로 이어질 수 있게 구성. 검색·쓰기 모두 ADMIN 세션과 인증 origin 경계를 유지하며, 브라우저 글쓰기는 여전히 공개 Pages API 주소 미설정 상태.

새 글·기존 글·편집본의 본문 저장은 최대 128개의 명시적 `wikiTargets`를 함께 전달할 계약. 이 배열은 웹 공유 파서가 원문에서 추출한 제목 선언이며 서버가 Markdown을 다시 파싱했다는 뜻이 아님. 새 글에서 생략/null은 빈 목록, 기존 글에서 본문이 바뀌었는데 생략/null이면 예전 연결 제거, 동일 본문이면 기존 연결 유지. 편집본은 원본 공개 글의 연결과 분리하고 출간 때 원본 글 연결을 같은 트랜잭션에서 교체. 본문·제목·공개 범위 변경과 삭제는 현재 읽기 권한과 canonical 대상에 따라 역링크 결과에 반영될 예정.

보정 API `PUT /api/v1/admin/posts/{id}/wiki-links`는 필수 `expectedBodySha256`과 `wikiTargets` 전체 배열을 받아 현재 본문의 UTF-8 SHA-256이 일치할 때 연결만 교체할 계약. 본문·`updatedAt`은 변경하지 않으며, 다른 저장으로 본문이 달라지면 `409`를 반환. ADMIN 세션·CSRF 필요. 기존 글을 자동 보정했다고 가정하지 않으며, 격리 DB에서만 사용할 [일회성 재색인 도구](../ops/wiki-links/README.md)는 관리자 목록·상세를 읽어 웹과 동일한 파서로 계산하고 기본 dry-run, 명시적 `--apply`에서만 보정 요청. 충돌 글은 ID만 기록해 재실행 대상에 남김.

읽기 글의 `GET /api/v1/posts/{slug}/backlinks?page=0`은 현재 읽을 수 있는 출간 출처만 한 페이지 10개씩 반환하고, 읽을 수 없는 출처·자기 자신·비공개 건수와 본문은 노출하지 않을 계약. 같은 제목이 여러 글에 있을 때 현재 canonical 대상이 아닌 글의 역링크는 빈 결과. 하단 역링크 목록은 실패·재시도·더 보기와 세션/글 전환 시 결과 폐기를 구분. h2/h3 목차는 접기 내부를 제외한 안전 파싱 결과에서 만들고, 중복 제목의 앵커 접미사·키보드 이동·모바일 배치를 처리할 예정. 화면의 격리 브라우저 검증·main 반영은 아직 완료로 기록하지 않음.

2026-09-26 기존 API 검사 28개와 격리 JAR·MySQL의 V9→V10 전환 확인. 기존 게시글은 전환 직후 연결 선언이 비어 있었으며, ADMIN 검색의 정규 대상·대소문자/악센트·리터럴 `%`·`_`·7개 상한, USER `403`·익명 `401`·입력 오류 `400` 확인. 보정의 잘못된 선언 `400`과 본문 SHA 불일치 `409`에서 본문·수정 시각·연결이 그대로였음. 도구는 기존 글 22개 중 변경 예정 14개를 보정했고 재실행에서 변경 대상 0개; 본문·`updatedAt` 불변 확인. 격리 데이터의 역링크는 익명 12개와 USER/ADMIN 13개를 페이지로 확인했고 PRIVATE·초안·코드 안 가짜 참조와 중복 제목의 canonical 대상 경계도 확인. 본문이 그대로인 저장에서는 생략 선언 유지, 본문 변경에서는 생략 선언 제거, 잘못된 선언은 전체 롤백. 편집본 연결은 원본과 분리되고 성공 출간에서만 이전하며, 오래된 출간 요청 `409`는 원본을 유지. 출처 철회·삭제와 대상 제목 변경·복원의 즉시 반영, 본문 열을 읽지 않는 역링크 SQL, 최종 JAR OpenAPI의 새 DTO 필수 필드 확인. 이 결과는 격리 API 검증이며 브라우저·운영 DB·공개 Pages의 실제 연결 검증은 아님.
