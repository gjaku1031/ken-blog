# 작업과 기록 기준

현재 계약 확인 → 범위에 따른 구현 → 통합 리뷰·검증 → 전달 가능한 변경 묶음 커밋 → `main` 직접 push.

- 단계별 승인 반복 없이 승인된 범위 진행. 기능·디자인의 임의 확대 없음.
- PR·강제 push·공유 이력 재작성 없음. 영어 Conventional Commits, 한국어 계획·검증 기록 사용.
- 실행하지 않은 검사나 배포를 완료로 표시하지 않음. author date와 실제 검증·push 시각 구별.
- 사용자용 README·학습 문서 추가 없음. 현재 작업 규칙·계약·필요한 검증·로컬 인계만 유지, 완료된 구 단계의 중복 기록은 Git 이력 활용.
- 운영 원고·첨부·계정·환경·복구 자료와 별도 작업 변경 보존. 비밀값의 저장소·로그·문서 노출 금지.
- 신규 저장소 테스트 추가 없음. 변경에 맞는 빌드·기존 검사·격리 HTTP/브라우저 검증 수행.
- 소스만 바뀐 전달과 운영 API 이미지 교체, 공개 Pages 배포를 구별. 동작 변경이 없는 문서 정리에 불필요한 운영 API 재시작 없음.
- 공개 변경은 최종 Pages 실행·배포 표식·종료 상태 확인. 실패·미검증·환경 제약은 결과에 명시.
