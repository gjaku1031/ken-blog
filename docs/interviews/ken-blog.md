# ken-blog: 인터뷰 요약

문서를 쓰며 확인한 사실과 판단의 이유를 정리한 기록. 블로그에는 게시하지 않음. 마지막 정리 2026-10-24.

## 개발 형태

- 개인 프로젝트(1인)

## 직접 정한 것

2026-10-08에 확인한 목록.

- Redis를 쓰지 않음
- Next.js 대신 정적 페이지로 열람 화면을 만듦
- 글을 posts·projects·series로 나눈 구조
- OCI 인프라 구조
- 웹 편집기에서 Git 원고 관리로 전환
- Native 이미지 대신 일반 JVM으로 실행
- 관리자 계정은 DB에 직접 등록
- 분류를 2단계로 줄임
- 업로드 기능을 없앰
- 배포 버튼 방식
- 정적 생성의 효과를 실측으로 확인하기로 함

## 판단의 이유

- **Git 원고 관리로 전환**: 원고의 변경을 diff로 검토하고 이력을 추적하기 위함
- **정적 생성**: 전환 전에는 문서를 불러올 때 API 왕복이 많아 느렸고, 전환한 뒤 체감 개선이 컸음. 그래서 측정으로 확인하기로 했음
- **핵심 문제 P1~P3의 대안**: 모두 직접 비교했음. 대안을 제외한 이유 가운데 "DB 이력 테이블은 diff 화면과 되돌리기를 따로 만들어야 함", "쓰기 잠금은 빌드 동안 관리 기능이 멈추고 잠금 해제를 보장해야 함"은 구조에서 도출한 설명을 확인받은 것
- **jOOQ와 QueryDSL 비교에서 Criteria API를 뺀 이유**: 코드가 복잡해지고 유지보수가 어려움
- **대문의 기술 표에서 Java·Spring Boot·JPA 행을 뺀 이유**: 주력 스택이라 따로 고른 이유가 없음
- **문제 해결 글의 공통 응답 수정**: 수정 범위는 직접 승인했음

## 문서 방향으로 정한 것

- 대문 링크는 GitHub만 둠
- 헤더의 기술 배지는 Spring Boot, MySQL, Oracle Cloud 3개
- 일본 리전을 쓴다는 사실은 적음
- 통과 기준 없이 한 번 잰 JVM 부하 측정은 실험이 아니라 결정의 검증 근거로 서술함

## 근거 보완에서 정한 것(2026-10-13)

- 열람 지연은 운영 환경에서 다시 재지 않음. 지금 측정의 조건을 밝힌 채로 둠
- P1의 검증에 넣을 되돌리기 사례를 원고 이력에서 찾았으나, 원고를 되돌린 커밋이 없었음. 없는 사례를 만들어 넣지 않고 지금의 구조 근거만 둠

## 글 상태와 검수 흐름에서 정한 것(2026-10-13, 2026-10-23 철회)

- 글 상태를 미검수·비공개·공개로 나누고, 글을 블로그 화면에서 읽으며 검수한 뒤 공개로 넘기기로 했음
- 공개하지 않은 글의 본문은 운영 DB에 둠. 저장소가 공개라 원고를 커밋하면 화면에서 숨겨도 읽히기 때문임
- 검수 버튼은 완료 표시만 남기고, 원고를 저장소로 옮겨 공개하는 일은 따로 진행함. 버튼 하나로 공개까지 가는 방식은 구현 범위가 커서 고르지 않았음
- Projects의 문서는 공개로 두고, Posts의 글은 한 편씩 다시 읽고 공개하기로 함
- 내린 글을 가리키던 링크는 원고를 고치지 않고 빌드가 글자로 낮추게 함. 다시 공개하면 링크가 돌아옴
- 공부하며 정리한 노트는 비공개 글로 두고, 관련 글에 본인에게만 보이는 연결로 붙이기로 함

## 검수 흐름 철회(2026-10-23)

- 미검수·비공개 상태와 검수 화면을 없애고, 저장소 원고가 곧 공개 글인 이전 방식으로 되돌렸음
- 숨겨 두었던 글 가운데 사내 ERP의 권한·모듈 구조를 다룬 4편과 공부 노트와 겹치는 Vowser 글 1편은 지우고, 공부 노트를 포함한 나머지 12편은 모두 공개했음

## 글 정리(2026-10-24)

- 예시용으로 쓴 Posts 4편(jOOQ 타입 생성, 목록 조회의 jOOQ 전환, 정적 생성 열람 지연 측정, 동시 편집 버전 비교)을 지웠음. 다시 검토해야 하던 글만 지우고, 완성한 프로젝트 문서 8편과 Posts 3편(성능 측정 목록, 이미지 응답의 헤더 경합, JVM 부하·메모리 측정)은 유지함
- 정적 생성 측정의 상세는 지운 글 대신 저장소의 실험 기록(`docs/experiments/2026-10-07-static-vs-csr/`)으로 연결함. 이 측정을 다시 읽으며 공부하기로 한 항목도 글을 지우면서 끝냄

## 글 정리(2026-10-30)

- 남겨 둔 Posts 3편 가운데 성능 측정 목록과 이미지 응답의 헤더 경합 글을 지웠음. 측정 목록은 다른 글을 요약한 목차와 테스트 기준 표뿐이라 혼자 읽을 가치가 낮았음. 헤더 경합 글은 원인을 재현하지 못했고, 수정 전후의 실패율이 통계적으로 구분되지 않았음
- ken-blog의 Posts는 JVM 부하·메모리 측정 1편만 남음. 프로젝트 문서 8편은 그대로 유지함
