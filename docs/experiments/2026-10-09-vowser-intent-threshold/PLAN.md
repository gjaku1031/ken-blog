# Vowser 의도 검색 임계값 확증 실험 계획서

- 분류: 확증 실험
- 작성일: 2026-10-09 (실행 전)
- 관련 문제: Vowser P2 의도 임베딩 검색과 낮은 유사도의 재검색
- 고정: 이 파일과 입력·실행기·분석 스크립트를 실행 전에 커밋함. 해시는 `freeze_manifest.json`
- 선행 기록: 2026-10-09 탐색적 평가(원본 서버, 질의 96개, `exploratory_queries.jsonl`·`exploratory_reference.jsonl`)

## 배경

Vowser는 요청 문장을 임베딩해 등록된 작업 의도와의 최고 유사도를 구하고, 0.43 이상이면 벡터 검색 결과를 그대로 순위화하고(이하 **순위화 분기**), 0.43 미만이면 LLM이 뽑은 키워드로 다시 검색함(이하 **재검색 분기**). LLM 의도 분석은 유사도와 상관없이 병렬로 항상 실행됨.

탐색적 평가에서 순위화 분기로 처리된 요청은 63건 중 41건, 재검색 분기로 처리된 요청은 17건 중 5건이 1위 정답이었음. 그러나 두 집단은 서로 다른 요청이고, 유사도가 낮은 요청은 원래 어려운 요청일 수 있어 분기의 효과와 요청의 난이도가 섞여 있음. 이 실험은 **같은 요청에서 두 분기를 모두 실행해** 그 혼동을 없애고, 가설을 만든 자료와 **다른 새 질의**로 확인함.

## 1. 연구 질문

- RQ1: 같은 요청에서 재검색 분기는 순위화 분기보다 정확한가
- RQ2: 임계값을 바꾸면 1위 정답률은 어떻게 달라지는가. 0.43은 적절한가
- RQ3: 최고 유사도로 등록되지 않은 작업 요청을 가려낼 수 있는가(임계값을 '모르는 작업' 판정에 쓸 수 있는가)

## 2. 가설과 기각 기준

| 번호 | 가설 | 근거 | 판정 |
| --- | --- | --- | --- |
| H1 | 정답이 있는 요청 80개에서 순위화 분기의 1위 정답이 재검색 분기보다 많다 | 탐색적 평가 41/63 대 5/17(서로 다른 요청이라 혼동 있음) | 순위화만 맞은 쌍 > 재검색만 맞은 쌍이고, 짝지은 정확 McNemar 검정 p < 0.05면 지지. 아니면 지지하지 못함 |
| H2 | 재검색을 끈 경우(임계값 0)의 1위 정답이 0.43 이상이고, 임계값 0.60의 1위 정답은 0.43 이하이다 | H1과 같은 근거. 임계값을 올리면 재검색 분기로 가는 요청이 늘어남 | 두 부등식이 모두 성립하면 지지, 하나라도 어기면 기각 |
| H3 | 최고 유사도로는 미등록 요청 16개와 정답이 있는 요청 80개를 잘 가르지 못한다 | 탐색적 평가에서 미등록 요청 "주민등록증 재발급"의 최고 유사도 0.78 | 최고 유사도의 ROC AUC < 0.80이면 지지, 0.80 이상이면 기각 |

- 유의수준은 가설마다 0.05. 세 가설은 서로 다른 질문이라 다중 비교 보정은 하지 않고, p값을 그대로 보고함.

| 구분 | 항목 | 수준·정의 |
| --- | --- | --- |

| 통제 | 코드 | 원본 agent 서버 커밋 d94eaf5, 함수를 고치지 않고 불러옴(`harness.py`) |
| 통제 | 모델 | text-embedding-3-small, gpt-4o-mini(원본 설정, temperature 0) |
| 통제 | 등록 자료 | 탐색적 평가와 같은 합성 작업 16개(7개 사이트), 빈 Neo4j에 새로 등록 |
| 통제 | 검색 조건 | 상위 3개, 도메인 힌트 없음, 재시도 없음, 가중치 증가 없음(검색 후 가중치를 올리는 원본 서버의 후처리는 실행기에서 부르지 않아 순서 효과를 없앰) |
| 통제 | 환경 | Neo4j 5.26.0 Community + APOC, Python 3.12.11 평가 이미지, 같은 VM |

## 4. 비교 기준과 설계

- 비교 기준: 현재 값 0.43. 극단 비교로 0(재검색 없음)과 1.01(항상 재검색)
- 설계: 요청 내 짝지은 설계. 요청마다 분석 단계를 한 번 실행하고, 그 상태를 복사해 두 분기를 각각 실행함. 임계값은 분기 선택에만 쓰이므로 임계값별 결과는 기록에서 계산함(원본 그래프의 분기 조건 `max_similarity >= threshold`와 같음)
- 표본: 새로 작성한 질의 104개(`confirmatory_queries.jsonl`). 정답형 80개(작업 16개 × 직접 1·바꿔 말하기 2·간접 1·배제 표현 1), 다의 8개, 미등록 16개(가까운 영역 8·먼 영역 8). 탐색적 평가와 같은 유형 구성이며, 탐색적 질의와 같은 문장은 없음
- 표본 크기의 이유: 탐색적 평가와 비교할 수 있게 정답형 80개를 유지하고, H3의 음성 표본을 늘리려고 미등록을 8개에서 16개로 늘림. 검정력 분석은 하지 않음
- 순서: 정답형·다의·미등록을 파일 순서대로 한 번씩. 각 요청은 독립 실행
- 재현 점검: 탐색적 질의 96개도 같은 실행기로 실행해, 임계값 0.43으로 계산한 1위가 탐색적 평가의 원본 서버 1위와 90% 이상 일치하는지 확인함. 미달하면 실행기가 원본을 충실히 재현하지 못한 것으로 보고 결과 해석에 그 사실을 함께 씀. 이 자료는 가설 판정에 쓰지 않음

## 5. 사전 고정

- 고정 파일: `PLAN.md`, `confirmatory_queries.jsonl`, `registered_paths.jsonl`, `exploratory_queries.jsonl`, `exploratory_reference.jsonl`, `harness.py`, `analyze.py`. SHA-256은 `freeze_manifest.json`
- 결과를 본 뒤 바꾸지 않을 것: 질의·정답, 임계값 목록, 가설·판정 기준, 분석 스크립트
- 실행은 한 번. 환경 문제로 실패하면 실패 기록을 보존하고 원인을 고쳐 다시 실행하며, 그 사실을 '계획 변경 기록'에 남김

## 6. 타당성 위협

| 분류 | 위협 | 막는 방법 | 남는 위협 |
| --- | --- | --- | --- |
| 내적 | 요청 난이도가 분기와 섞임(탐색적 평가의 문제) | 같은 요청에서 두 분기를 모두 실행 | 없음 |
| 내적 | LLM 응답이 실행마다 달라짐 | 요청마다 LLM을 한 번만 부르고 두 분기가 같은 결과를 씀. temperature 0 | 같은 요청을 다시 실행하면 다를 수 있음 |
| 내적 | 실행기가 원본 서버와 다르게 동작 | 원본 함수를 그대로 부름. 탐색 자료로 재현 점검 | 가중치 후처리를 부르지 않음(의도된 차이) |
| 외적 | 합성 질의·합성 작업 16개 | 유형별로 나눠 보고 | 실제 사용자 발화·음성 인식 오류·작업 수천 개 규모로 일반화하지 않음 |
| 구성 | 1위 정답이 사용자 경험을 대표하는가 | 앱이 1위만 실행하므로 1위 정답을 주 지표로 둠 | 3위 안 정답은 참고 |
| 구성 | 질의를 실험자(에이전트)가 작성. 탐색 결과를 본 뒤 작성함 | 탐색 자료와 같은 유형 구성·같은 작성 규칙을 따르고 실행 전 고정 | 작성자가 어려운·쉬운 문장 쪽으로 기울었을 가능성 |
| 통계적 | 정답형 80개, 미등록 16개 | 비율에 Wilson 95% 신뢰구간, AUC에 부트스트랩 95% 구간 | 작은 차이는 구분하지 못함 |

## 7. 분석 계획

`analyze.py`가 아래를 그대로 계산함.

| 지표 | 요약 | 불확실성 |
| --- | --- | --- |
| H1 분기별 1위 정답 | 분기별 개수, 불일치 쌍(순위화만·재검색만) | 정확 McNemar 양측 p |
| 임계값별 1위·3위 안 정답 | 개수/80 | Wilson 95% |
| H2 | 임계값 0·0.43·0.60의 1위 정답, 0과 0.43의 불일치 쌍 | McNemar p(참고) |
| H3 최고 유사도 판별력 | ROC AUC(정답형 = 양성, 미등록 = 음성) | 부트스트랩 2,000회 95% 구간(시드 20261009) |
| 지연 | 임계값 0·0.43·1.01에서 중앙값·p95 | 표본 수 |
| 다의 질의 | 허용 후보 1위 개수 | 참고 |

## 8. 실행 환경과 비용

- 환경: 같은 VM의 Docker. Neo4j 5.26.0 Community + APOC(원본이 쓰던 Neo4j Cloud와 같이 APOC 필요), 평가 이미지 Python 3.12.11(`requirements-eval.txt` 고정 버전)
- 외부 API: 정답형·다의·미등록 104개 + 재현 점검 96개 = 200개 요청. 요청마다 임베딩 2~4회와 LLM 1회. 예상 비용 1달러 미만
- 키: 실험 전용, 1일 만료, Chat completions·Embeddings 권한만. 실행 후 파일 삭제
