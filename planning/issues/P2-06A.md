# P2-06A 위키 링크 대상 조회 API

## 문제와 시작 상태

`[[글 제목]]` 링크를 읽기 화면에 연결하려면 제목으로 대상과 열람 상태를 판별하는 API 필요. 현재 출간 목록은 권한별 필터, 직접 PRIVATE 상세는 최소 메타데이터와 잠금 상태를 제공함. 주석 편집 단계 main `6dc3988` 정상 push 완료. 그 SHA CI/Pages 성공 확인 후 이번 구현 시작.

## 구현 범위

- 별도 GET `/api/v1/wiki-links/resolve`에서 반복 `title` 쿼리로 요청한 대상의 상태를 입력 순서로 반환. 1~20개, 제목별 앞뒤 공백 제거 후 1~200 codepoints, 요청 합계 UTF-8 1500bytes 상한. 제어 문자/개행·빈 값·알 수 없는 쿼리·초과 입력은 기존 ProblemDetail 400. 쉼표가 든 제목은 하나의 값으로 보존. 실제 URL 인코딩 길이도 HTTP 경계 검증.
- 현재 대상은 출간 Tech 글. 앞뒤 공백과 대소문자를 무시하되 악센트가 다른 제목을 같은 대상으로 취급하지 않음. 비교는 MySQL 소문자 변환 후 이진 비교로 일관되게 수행. 같은 제목의 출간 글은 최초 출간일 오름차순·ID 오름차순으로 한 개 선택. 제목 중복을 새로 금지하거나 기존 글을 변경하지 않음.
- 결과는 읽기 가능·잠금·없음의 명시적 상태. PUBLIC은 익명 포함 조회 가능, PRIVATE는 명시적 USER/ADMIN 세션에만 읽기 가능. 익명 PRIVATE에는 잠금 상태만 반환하고 본문·분류·태그·첨부·slug/ID 등 대상 메타데이터 없음. 이는 기존 직접 조회의 잠금 표시와 일관된 최소 응답이며 새 PRIVATE 목록 탐색을 추가하지 않음. 초안/미존재는 모두 없음.
- 읽을 수 있는 결과에도 이동에 필요한 ID·제목·slug만 제공하고 본문 열 조회 없음. 반환과 로그에 세션/비밀값 없음. `Cache-Control: no-store`, 현행 공개/인증 origin별 GET CORS와 역할 판별/JDBC 세션/ProblemDetail 흐름 유지. POST 등 다른 메서드를 새로 허용하거나 CSRF 예외를 추가하지 않음.
- JpaRepository 인터페이스의 필요한 조회와 구체 Service, Swagger Controller 계약/구현체, Kotlin KDoc·기능별 패키지 유지. 별도 범용 Repository·서비스 인터페이스 없음. 쿼리는 바인딩하고 요청 수만큼 비용이 무한히 늘지 않도록 상한을 적용. DB 마이그레이션이나 기존 제목의 변경 없이 조회로 구현.
- README·API/위키 링크 안내·계획 상태 갱신. 프론트 파싱·표시·선택기는 다음 단계에서 이 계약을 소비함.
