| 항목 | 내용 |
| --- | --- |
| 소개 | 저장된 웹 작업을 음성으로 찾아 사용자 PC의 브라우저에서 대신 실행하는 데스크톱 앱 |
| 목적 | 손으로 마우스·키보드를 여러 번 조작하기 어려운 사람이 예매·민원서류 조회처럼 여러 화면을 거치는 웹 작업을 수행하게 함 |
| 개발 형태 | 팀 프로젝트(4명: 프론트엔드 1·백엔드 2·AI 1), 팀 리더. 2025 오픈소스 개발자대회 본선 진출 |
| 담당 범위 | 기획, 인증·회원 백엔드, 인프라, AI 검색 프로토타입 |
| 주요 기능 | 음성 작업 검색, 브라우저 자동 실행, 인증 단계의 사용자 개입, 작업 기록·공유 |
| 링크 | [![GitHub\|dark=61\|w=20\|a=center](attachment:60) GitHub](https://github.com/Vovvser) |

사용자가 "오늘 날씨 어때?"처럼 말하면 서버가 등록된 웹 작업 경로 중 의도가 가장 가까운 것을 찾아 돌려주고, 사용자 PC의 Playwright가 그 경로대로 이동·클릭·입력을 수행함. 로그인·본인 인증처럼 사용자가 직접 해야 하는 단계에서는 실행을 멈추고 기다림. 경로는 사용자가 직접 수행한 웹 작업을 기록해 등록하므로, 개발자가 코드를 고치지 않아도 지원 작업이 늘어남.

## 담당 범위

- **기획**: 서비스 아이디어 제안과 기획, 대회 발표
- **백엔드**: OAuth2 소셜 로그인과 자동 가입, JWT 인증과 보안 설정, 회원 도메인
- **인프라**: 평소에는 Proxmox, 부하가 몰리면 AWS로 넘기는 실행 환경
- **AI 검색**: Colab에서 LangGraph로 경로 검색 프로토타입

## 개발 배경과 핵심 문제

손을 쓰기 어려운 가족이 컴퓨터를 쓸 수 있도록, 자주 쓰는 Bash 명령을 음성으로 실행하는 스크립트 도구를 먼저 만들었음. 실제 사용에는 도움이 되었지만 새 기능이 필요할 때마다 직접 스크립트를 추가해야 했음. 이 경험을 팀원들과 논의해 명령 몇 개를 대신 입력하는 도구에서, 여러 단계의 웹 작업을 기록하고 찾아 재사용하는 앱으로 범위를 넓혔음.

다음 제약 안에서 설계함.

- **사용자**: 마우스·키보드 조작을 여러 번 반복하기 어려움. 입력은 음성과 최소한의 선택으로 끝나야 함.
- **대상 사이트**: 예매·민원 사이트는 외부 서비스라 구조를 바꿀 수 없고, 로그인·본인 인증·결제 단계가 있음.
- **운영 비용**: 클라우드 서버를 상시 운영할 비용을 줄여야 하지만, 명절 열차 예매처럼 접속이 특정 시점에 몰리는 상황도 가정함.

이 제약에서 다음 네 문제를 핵심 문제로 정의함.

- **P1 작업 확장성**: 지원할 웹 작업을 늘릴 때 개발자의 코드 수정 없이, 사용자가 기록한 작업을 다른 사용자가 재사용할 수 있어야 함.
- **P2 의도 검색**: 등록할 때와 다른 표현으로 요청해도 같은 작업의 경로를 찾아야 함.
- **P3 실행 통제**: 로그인·본인 인증·결제는 사용자가 직접 하고, 비밀번호 같은 입력값이 경로에 저장·공유되지 않아야 함.
- **P4 비용 대비 확장**: 평소에는 클라우드 상시 비용 없이 운영하고, 접속이 몰리면 서버 처리 용량을 늘릴 수 있어야 함.

### 주요 흐름

사용자의 음성은 Spring Boot에서 텍스트로 바뀌고, 경로 검색은 Spring Boot를 거쳐 FastAPI 에이전트가 Neo4j에서 찾음. 찾은 경로의 실행은 사용자 PC의 Playwright가 하므로 서버는 대상 사이트에 접근하지 않음. 부하가 몰리면 같은 서버 이미지를 AWS Fargate로 띄워 DNS를 넘김. 흐름별 경로와 실패 시 동작은 [아키텍처](/ken-blog/post/doc-fd568125-2806-4210-a0b2-e4bf2d1b509e/)에서 다룸.

## 핵심 문제별 설계와 검증

검토한 대안 표와 검증 상세는 [주요 기술적 의사결정](/ken-blog/post/doc-d8735f2c-c9bf-45fa-bcac-a692eb4dc739/)에 있음.

### P1. 사용자 기록을 단계 연결 경로로 저장

- **문제**: 개발자가 준비한 작업만 실행할 수 있어, 지원 작업을 늘릴 때마다 개발자가 경로를 등록해야 했음
- **결정**: 사용자의 클릭·입력·이동을 단계로 기록해 Neo4j 경로로 저장하고, 다음 검색부터 후보로 씀[* [경로 저장·검색 코드](https://github.com/Vovvser/vowser-agent-server/blob/d94eaf5/app/services/neo4j_service.py)]
- **대가**: 같은 화면의 단계도 기록마다 따로 저장되고, 저장이 단계마다 나뉘어 커밋되어 중간에 실패하면 일부만 남음
- **재평가**: 2026년 사후 실험에서 저장소를 MySQL과 다시 비교함. 등록 지연은 DB 종류보다 트랜잭션 경계의 영향이 컸음[* 2026-09-29, 합성 경로 3만 개·읽기:쓰기 90:10(위 행)과 경로 1천 개(아래 행). DB 컨테이너 1 CPU·3GiB, Python 워커 1 CPU·1GiB, tmpfs 저장, 임베딩 생성 제외]

| 측정 항목(신규 경로 등록, 중앙값, 괄호 안 p95) | 비교 A | 비교 B |
| --- | ---: | ---: |
| DB 종류: MySQL / Neo4j | 7.14 (13.03)ms | 26.50 (83.83)ms |
| Neo4j 트랜잭션 경계: 단계별 커밋 / 배치 한 번 | 164.34 (211.60)ms | 10.35 (61.06)ms |

### P2. 의도 임베딩 검색과 낮은 유사도의 재검색

- **문제**: 같은 작업을 사람마다 다르게 말해, 등록 문장과 요청 문장이 글자로 일치하지 않음
- **결정**: 요청과 작업 의도를 임베딩 유사도로 찾고, 유사도가 낮으면 LLM으로 의도·키워드를 뽑아 다시 찾음[* [LangGraph 검색 흐름](https://github.com/Vovvser/vowser-agent-server/blob/d94eaf5/app/services/langgraph_service.py)]
- **대가**: 요청마다 외부 임베딩·LLM 호출이 붙고, 등록되지 않은 작업을 요청해도 가장 가까운 다른 작업을 돌려줌
- **검증**: 합성 한국어 요청 80개의 1위 정답은 46개(57.5%)였고, 사전 등록한 확증 실험에서 낮은 유사도의 LLM 재검색은 같은 요청에서 바로 순위화하는 것보다 정확하다는 근거가 없었음(52 대 45/80, p = 0.265)[* 2026-10-09, 원본 서버·모델, 작업 16개 등록, 요청 문장은 실제 사용자 발화가 아닌 합성 자료. 상세는 [Vowser 의도 검색 정확도와 재검색 임계값](/ken-blog/post/post-ccb0e7cb-986a-4f7d-832e-ba4fd69e49e1/)]

### P3. 실행은 사용자 PC에서, 인증은 사용자 손에

- **문제**: 예매·민원 작업의 로그인·본인 인증·결제는 서버가 대신할 수 없고, 비밀 입력값을 서버에 두면 위험함
- **결정**: 서버는 경로만 돌려주고 Playwright 실행기를 사용자 PC에 둠. 인증 단계에서는 사용자 입력을 기다림[* [경로 실행기](https://github.com/Vovvser/vowser-client/blob/8065803/shared/src/commonMain/kotlin/com/vowser/client/api/PathExecutor.kt)]
- **대가**: 사이트 구조가 바뀌면 저장된 선택자가 맞지 않고, 입력 칸 분류가 속성에 의존해 일부 개인정보가 경로에 저장될 수 있음
- **검증**: 실제 사이트 시연에서 KTX 예매는 중간 로그인을 기다린 뒤 결제 직전까지, 주민등록등본 조회는 인증 후 문서 표시까지 도달함

> 서버는 경로를 찾아 돌려줄 뿐이고, 로그인·본인 인증·결제는 사용자 PC의 브라우저에서 사용자가 직접 끝냄.

### P4. Proxmox 기본 실행과 AWS 확장

- **문제**: 평소 요청은 적어 클라우드 상시 비용이 부담이지만, 명절 예매처럼 잠깐 접속이 몰릴 때도 멈추면 안 됨
- **결정**: 평소에는 Proxmox에서 실행하고, 부하 경보가 울리면 같은 이미지를 AWS Fargate로 띄워 DNS를 넘김
- **대가**: 두 환경의 이미지·설정을 함께 관리하고, DNS 캐시가 남는 동안 요청이 두 환경으로 나뉨
- **검증**: 경보부터 Fargate 기동·DNS 변경까지 구현해 실습함. 워크플로·태스크 정의·Lambda 코드는 남아 있지 않아 근거는 구성한 본인의 설명이고, 전환 시간과 비용 절감률은 측정하지 않음
