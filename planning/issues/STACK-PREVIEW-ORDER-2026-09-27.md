# 기술 스택 로고·선택 순서·프로젝트 배치

## 요청과 범위

- 프로젝트 대문 출간·저장 창의 가짜 약자 아이콘을 등록된 실제 로고로 통일.
- Neo4j·Oracle Cloud·Proxmox 실제 로고 뱃지를 재사용 카탈로그에 추가. 기존 Google Cloud는 GCP 검색 별칭 지원, 중복 생성 없음. 기존 기술·사용자 프로젝트·원고·선택 연결 보존.
- 글쓰기에서 선택한 기술 스택을 드래그로 정렬, 저장 창·저장 후 프로젝트 목록/상세에서도 순서 유지.

## 수용 기준

- 기존 등록 로고 URL 공유, 로드 실패·미등록 이름은 잘못된 아이콘 없이 이름 유지.
- 마우스·터치 정렬과 키보드 조작, 검색·선택·제거·즉석 등록 유지. 같은 위치 놓기·취소는 원래 순서 보존.
- 격리 저장·재조회로 이름 배열과 DB sort_order·응답 순서 확인. 운영 사용자 프로젝트의 임의 수정 없음.
- 신규 로고 출처·원본·PNG 해시 보관 및 중복 생성 방지.
- 관리자 프로젝트 배치 편집·드래그·저장/취소, 공개 목록까지 저장 순서 반영. 전체 순열 검증·동시 수정 409·기존 순서 유지 V24 이관. 운영 사용자 프로젝트 재정렬 검증은 미수행, 격리 데이터에서 확인.
- 타입·기존 검사·정적 빌드, 밝고 어두운 테마·데스크톱·모바일 브라우저 검증. 신규 저장소 테스트 없음.

## 진행

- 선택기에서는 실제 로고를 조회하지만 확인 창은 이름 약자와 임의 색상으로 별도 렌더링하는 경로 확인.
- 서버는 요청 이름 배열 순서로 sort_order 저장, 조회도 해당 순서 정렬 확인. 기존 계약 유지.

- 추가 요청의 프로젝트 배치와 Oracle Cloud·GCP·Proxmox 반영 완료. 기존 생성일 역순을 새 순서 열로 보존한 뒤 사용자 지정 허용.

## 구현·검증 결과

- 확인 창의 등록 카탈로그 공유·실제 로고 표시, 로고 실패 시 이름 유지. 선택 칩 손잡이와 제거 버튼 분리, 마우스·터치·Alt+방향키 순서 이동, Escape·창 이탈 취소.
- Projects 관리자 `순서 편집` 모드에서 전체 경량 목록 정렬·저장·취소. 전체 순열과 조회 기준을 함께 전송, 동시 변경 409에서 다시 불러오기. 방문자·관리자 카드 모두 저장 순서 적용.
- V24 기존 순서 이관, 새 프로젝트 맨 앞, 정렬만 변경할 때 본문·수정 시각 보존. 관리 세션과 CSRF 검증 유지.
- API clean verify 28개·웹 기존 7개·타입·정적 17경로·diff 검사 통과. 새 저장소 테스트 추가 없음.
- 격리 HTTP: V23→V24 전체 프로젝트 응답 보존, 잘못된 순열 400, 인증/CSRF, 저장·공개/비공개 필터·수정 시각 보존, 오래된 요청 409, 동시 저장 204/409, 신규 맨 앞 및 생성·삭제 이후 충돌 확인.
- 자체 브라우저: 실제 로고 6개와 저장 순서, 마우스·키보드·390px 실제 터치·Escape, 원고 저장·출간·재조회, 프로젝트 저장/취소·충돌 다시 불러오기·밝은/어두운 테마·런타임 오류 없음 확인.
- 모바일 프로젝트 목록의 내부 가로 넘침으로 손잡이가 가려진 문제 발견 후 grid 열 최소 폭 보정. 내부 scrollWidth와 손잡이 노출 및 실제 터치 재검증 통과.
