API는 호출 주체에 따라 공개(학부모), 관리자, 스캐너 세 경로로 나뉘고, 상태를 바꾸는 요청은 모두 멱등 키를 받아 재전송돼도 한 번만 반영됨(P1). 비밀값은 경로·쿼리에 싣지 않음(P2). 전체 경로와 필드 계약의 원본은 OpenAPI 문서임.[* [OpenAPI 계약](https://github.com/gjaku1031/npr-seminar/blob/92598e6/packages/contracts/openapi.yaml) · [예약 컨트롤러](https://github.com/gjaku1031/npr-seminar/blob/92598e6/apps/api/src/modules/family-bookings/family-bookings.controller.ts) · [입장 컨트롤러](https://github.com/gjaku1031/npr-seminar/blob/92598e6/apps/api/src/modules/check-ins/check-ins.controller.ts)]

## 설계 원칙

| 결정 | 내용 | 이유·대가 |
| --- | --- | --- |
| 계약 우선 | 화면과 API가 공유하는 것은 OpenAPI 3.1 문서 하나. 화면은 API 내부 타입을 import하지 않고 계약을 보고 타입을 다시 선언함. 계약 검증기와 컨트롤러 경로 대조 스크립트가 둘의 차이를 잡음 | 백엔드 DB 모델이 화면에 새지 않음. 대가는 타입을 두 번 선언하는 것[* [계약 검증기](https://github.com/gjaku1031/npr-seminar/blob/92598e6/packages/contracts/scripts/validate_openapi.py) · [컨트롤러 경로 대조](https://github.com/gjaku1031/npr-seminar/blob/92598e6/packages/contracts/scripts/audit_controller_routes.py)] |
| 주체별 경로 | `/api/v1/public/*`(인증 없음 또는 예약 증명), `/api/v1/admin/*`(`ADMIN` 세션), `/api/v1/scanner/*`(`SCANNER` 세션) | 경로만 보고 어떤 가드가 걸리는지 알 수 있음. 스캐너 세션으로는 관리 경로에 접근할 수 없음 |
| 멱등 키 필수 | 상태를 바꾸는 요청은 `Idempotency-Key`가 없으면 400. 서버는 키와 요청 본문의 다이제스트를 결과와 함께 24시간 저장함 | 모바일·현장 네트워크의 재전송을 서버가 흡수함. 대가는 요청마다 멱등 기록 한 행 |
| 비밀값은 헤더와 본문으로 | 예약 증명은 `X-Booking-Proof` 헤더, QR 원문은 요청 본문이나 `X-QR-Token` 헤더로만 오감. 비밀값을 담은 응답은 `Cache-Control: private, no-store` | 경로·쿼리는 접근 로그와 브라우저 기록에 남음(P2). 링크로 공유할 수 있는 주소에는 예약 ID만 들어감 |
| 낙관적 버전 | 예약·설명회·회차 수정은 조회한 `expectedVersion`을 보내고, 현재 버전과 다르면 409 | 학부모와 관리자가 같은 예약을 동시에 고칠 때 앞선 변경을 덮어쓰지 않음 |
| 업무 결과와 HTTP 오류 분리 | 입장 요청은 판정이 거절이어도 200과 결과 코드로 응답하고, 입력·인증·키 오류만 4xx | 스캐너 화면은 결과 코드로 안내 문구를 고르고, 거절도 감사 사건으로 남음 |
| 표준 오류 형식 | `application/problem+json`(RFC 9457)의 `title`·`status`·`detail`에 업무 오류 코드 `code`와 추적용 `traceId`를 더함. 5xx는 고정 문구만 응답하고 원인은 서버 로그에 남김 | 화면은 `code`로 분기함. 5xx 로그에는 요청 본문·헤더·쿼리를 싣지 않음[* [오류 필터](https://github.com/gjaku1031/npr-seminar/blob/92598e6/apps/api/src/common/errors/problem-details.filter.ts)] |

> 화면이 같은 요청을 몇 번 보내든 서버 상태는 한 번 보낸 것과 같고, 두 번째 응답은 첫 결과의 재생임.

## 입장 계약

```json
{
  "qrToken": "<QR 원문>",
  "attendedCount": 2
}
```

`POST /api/v1/scanner/check-ins/qr`의 본문. `Idempotency-Key` 헤더와 스캐너 세션 쿠키, CSRF 토큰이 함께 가야 함. 서버는 멱등 키 다이제스트로 advisory lock을 잡은 뒤 스캐너 → 회차 → 예약 → QR 순서로 행을 잠그고 판정함.

| 결과 코드 | 예약 변경 | 의미 |
| --- | --- | --- |
| `CHECKED_IN` | `CHECKED_IN`으로 바꾸고 인원 기록 | 입장 성공 |
| `PARTY_SELECTION_REQUIRED` | 없음 | `attendedCount`가 없음. 스캐너가 인원을 물은 뒤 새 키로 다시 보냄 |
| `ALREADY_CHECKED_IN` | 없음 | 이미 입장함. 처음 기록한 인원을 함께 돌려줌 |
| `SESSION_MISMATCH` | 없음 | 스캐너가 잠근 회차와 예약 회차가 다름 |
| `CANCELLED`, `REVOKED_QR`, `EXPIRED_QR`, `INVALID_QR` | 없음 | 취소된 예약, 폐기·만료·형식 오류 QR |

`attendedCount`는 요청 다이제스트에 들어감. 같은 키로 인원만 바꿔 다시 보내면 재시도가 아니라 다른 요청이므로, 조용히 이전 결과를 재생하지 않고 `IDEMPOTENCY_KEY_REUSED`(409)로 거절함.[* [입장 서비스](https://github.com/gjaku1031/npr-seminar/blob/92598e6/apps/api/src/modules/check-ins/check-ins.service.ts)] 경합에서 진 요청은 아무것도 기록하지 않고 `ALREADY_CHECKED_IN`이 됨.

## 예약 생성 계약

공개 예약 생성(`POST /api/v1/public/family-bookings`)은 문자 인증으로 받은 예약 증명을 `X-Booking-Proof`로 보냄. 서버는 회차 행을 잠근 상태에서 증명을 소비하고, 증명의 연락처 다이제스트와 일치하는 학생만 예약함. 요청 본문의 학생 ID를 믿지 않으므로, 학생 ID를 알거나 추측해도 남의 자녀를 예약할 수 없음.[* [결정 기록의 공개 예약 소유 절](https://github.com/gjaku1031/npr-seminar/blob/92598e6/docs/specs/nestjs-implementation-decisions-20260717.md)]

| 응답 | 내용 |
| --- | --- |
| 첫 응답 | 예약 정보, `qrToken`(QR 원문), `qrExpiresAt`, `replayed: false` |
| 같은 키·같은 본문 재전송 | 예약 정보와 `replayed: true`. QR 원문 없음 |
| 같은 키·다른 본문 | 409 `IDEMPOTENCY_KEY_REUSED` |
| 이미 활성 예약이 있는 연락처 | 409 `ACTIVE_FAMILY_BOOKING_EXISTS` |

멱등 기록에 QR 원문을 저장하지 않기 때문에 재생 응답에는 QR이 없음. 화면은 없는 값을 지어내지 않고, 예약 조회(연락처 확인 후 `GET .../{id}/qr`)로 현재 활성 QR을 다시 받게 안내함.

## 문자 일괄 발송 계약

관리자 일괄 발송은 미리보기와 발송 두 단계임. 미리보기(`POST /api/v1/admin/sms/targets/preview`)는 대상 선택, 변수 치환, SMS·LMS 판정을 계산하고 대상 집합에서 만든 `previewToken`과 표본 최대 10건을 돌려줌. 발송 요청은 이 토큰을 함께 보내고, 서버는 같은 트랜잭션에서 대상을 다시 계산해 토큰이 일치할 때만 outbox 행을 기록함(`POST /api/v1/admin/sms/sends`).[* [문자 관리 서비스](https://github.com/gjaku1031/npr-seminar/blob/92598e6/apps/api/src/modules/sms/sms-admin.service.ts)]

미리보기와 발송 사이에 새 예약이나 취소가 생기면 토큰이 달라져 409 `SMS_PREVIEW_TOKEN_CHANGED`로 거절됨. 관리자가 확인한 수신자 목록과 실제 수신자 목록이 다른 채로 문자가 나가지 않게 하기 위함. 발송 시각을 지정하면 outbox 행의 `next_attempt_at`이 그 시각이 되고, 실제 전송은 worker가 함.

인증 순서와 세션 쿠키 속성은 [보안 설계](/ken-blog/post/doc-9ba607d2-b6e2-4a63-8e79-c974564acf11/)에서 다룸.
