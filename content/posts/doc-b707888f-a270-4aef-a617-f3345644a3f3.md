관리자 변경 권한, 세션 수명, 공개 자료 선별과 이미지·Markdown 전달 경계. 공개 화면은 Pages, 실제 권한 검사는 API에서 수행.

## 신뢰 경계

| 경계 | 보호 대상 | 처리 |
| --- | --- | --- |
| 브라우저 → API | 글·분류·프로젝트 변경 | 서버 세션·ADMIN·CSRF |
| Pages origin → API | 쿠키 동반 교차 출처 요청 | 명시 origin CORS·쿠키 설정 |
| Caddy → API | 로그인 출처 판정 | 전달 헤더 덮어쓰기·공유 키 |
| 공개 API → DB | 미발행·비공개 자료 | 공개 조건·글과 첨부 연결 검사 |
| API → 디스크 | 루트 밖 파일·잘못된 객체 | 키·경로·심볼릭 링크·크기 검사 |
| Markdown → HTML·SVG | 독자 브라우저 실행 경계 | HTML 정화·URL 제한·Mermaid 결과 검사 |
| 운영 설정 → 애플리케이션 | 비밀번호·프록시 키·DB 자격 증명 | 저장소 밖 설정·제한된 오류 기록 |

## 관리자 인증과 세션

운영자가 준비한 활성 ADMIN 계정으로 로그인. 계정명은 서버 설정으로 고정하며 입력 비밀번호를 저장된 해시와 비교. 비밀번호의 앞뒤 공백은 보존하고 빈 값·72 UTF-8 바이트 초과는 거부.

인증 성공 시 세션 ID 교체, 기존 CSRF 토큰 폐기, 인증 컨텍스트 저장. HTTP Basic·폼 로그인은 비활성화. 로그인·계정 등록은 별도 책임이며 회원가입 API는 제공하지 않음.

| 항목 | 계약 |
| --- | --- |
| 세션 저장 | Spring Session JDBC, MySQL |
| 일반 로그인 | 비활동 한도 8시간 |
| 로그인 유지 | 비활동 한도 30일, 쿠키 수명 30일 |
| 요청별 재검증 | 계정 존재·활성·권한, 인증 증명·설정 버전 비교 |
| 로그아웃 | 세션·인증 컨텍스트·CSRF 폐기 |
| 인증 상태 누락 | 기존 세션 거부·로그인 중단 |
| JDBC 장애 | 응답 확정 전이면 공개 가능한 503으로 변환 |

비밀번호·권한·활성 상태·관리자 설정이 바뀌면 이전 세션을 계속 신뢰하지 않음. DB 장애 시 메모리 세션으로 우회하지 않음.

## CSRF·CORS·쿠키

로그인 전 CSRF 발급, 로그인 후 새 토큰 재발급. 관리자 변경과 로그아웃도 세션 쿠키·토큰 헤더 필요.

| 대상 | 설정 |
| --- | --- |
| 공개 조회 | 허용 origin의 GET·HEAD, 쿠키 없는 공개 CORS |
| 인증·관리 요청 | 별도로 허용한 origin의 credentials와 필요한 메서드·CSRF 헤더 |
| 운영 세션 쿠키 | HttpOnly·Secure·SameSite=None·Partitioned |
| 운영 origin | `https://gjaku1031.github.io` |
| 관리자 권한 | CORS와 별도로 ADMIN 검사 |

CORS 통과만으로 인증을 부여하지 않음. 사이트 간 쿠키 수용 여부는 브라우저 설정에도 의존. 로컬 HTTP 설정과 운영 HTTPS 쿠키를 구분.

## 로그인 반복 시도와 출처

`admin_auth_state` 단일 행 잠금 안에서 전체 연산 예산과 출처별 실패 상태 갱신.

| 제한 | 동작 |
| --- | --- |
| 출처별 실패 | 첫 실패부터 60초 창 안에 5회 실패하면 제한 |
| 제한 중 요청 | 해당 창 만료 시각을 연장하지 않음 |
| 전체 검증 예산 | 60초당 비밀번호 검증 30회 |
| 출처 보관 수 | 최대 4,096개 |
| 출처 저장 | 주소 원문 대신 해시, IPv6는 /64 단위로 묶음 |

Caddy는 기존 전달 헤더를 제거·덮어쓰고 공유 키와 클라이언트 주소 전달. API는 키가 일치할 때만 전용 IP 헤더를 신뢰하며 그 외에는 직접 연결 주소 사용. 공유 키는 최소 32자.

API 호스트 포트는 loopback에 제한. 전체 예산 소진 시 정상 관리자도 일시 거부될 수 있는 비용 수용.

## 공개 글·첨부 권한

공개 글은 `PUBLISHED + PUBLIC`, 내부 호환 `section=TECH`, 소속 시리즈 공개 여부 확인. 첨부는 글과의 연결과 READY 상태 추가 검사. 관리자 세션이 있어도 공개 전달 경로에서 이 조건을 생략하지 않음.

미존재·접근 불가는 동일한 404. PNG/JPEG 메타데이터와 1바이트~10MiB 크기 허용. 안전한 파일 열기 후 실제 파일 크기 대조. 저장소 문제는 503.

권한·파일 검사를 마친 뒤 MIME·길이·nosniff·캐시 헤더를 설정하고 같은 요청 스레드에서 전송. 입력 스트림은 종료 시 닫음. 첨부는 private/no-store, 기술 아이콘은 public/max-age=300.

이미 시작한 전송을 이후 발행 취소로 소급 중단하지 않음. Pages의 정적 복사본도 재배포 전까지 남을 수 있음.

## 파일과 렌더링

전용 절대경로 루트 안의 제한된 객체 키만 읽음. 경로 이탈·심볼릭 링크·불안전한 디렉터리 쓰기 권한 거부. API의 파일 마운트는 읽기 전용. 파일 준비와 실제 내용의 적합성은 운영자 책임.

Markdown은 허용 요소·속성·프로토콜 기준으로 HTML 정화. 외부 링크는 주소 검사와 `noopener noreferrer` 적용. 본문 이미지는 `attachment:ID`와 빌더가 검증한 자산 주소 사용. 수식은 KaTeX `trust=false`.

Mermaid는 strict 모드·입력 한도·HTML 라벨 제한 적용. 생성 SVG에도 외부 참조·요소·속성 검사. 빌더는 지정 API origin·경로를 검사하고 이미지 다운로드 리다이렉트 거부.

## 운영 설정과 오류 기록

DB·프록시 비밀값은 저장소 밖 환경 파일 관리. JDBC 예시는 서버 신원 검증 TLS 사용. 공개 오류는 내부 경로·SQL·비밀번호·예외 원문 대신 제한된 설명 제공.

예상하지 못한 장애는 eventId와 제한된 원인 타입·애플리케이션 프레임을 기록하고 응답과 연결. 인프라 전체 로그의 자동 비밀값 검사를 보장하는 범위는 아님.

## 회귀 검증 범위

| 검사 | 계약 |
| --- | --- |
| AuthHttpIntegrationTest | 세션 교체·만료·권한·동시 로그인 제한·인증 상태 누락 |
| SecurityFailureTest | JDBC 장애·쿠키 속성·신뢰하지 않는 전달 헤더 |
| LocalAssetStorageTest | 경로 이탈·심볼릭 링크 거부 |
| AttachmentDeliveryTest | MIME·크기·실제 파일 불일치 거부 |
| Markdown·Mermaid 검사 | 원시 스크립트·위험 URL·외부 참조·허용되지 않은 설정 거부 |
| 사이트 간 인증 검사 | 별도 HTTPS 사이트의 로그인·변경·로그아웃 |

공개 Git 원고와 배포된 파일의 회수, 호스트 운영자의 파일 변경, 브라우저 쿠키 정책은 API 권한 검사만으로 해결되지 않는 범위.
