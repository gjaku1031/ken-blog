# P0-04: 정적 프론트 Pages 배포와 Spring 실행 이미지

상태: **완료** · 선행: P0-03 완료

## 문제

원래 배포 구상은 GitHub Pages의 정적 프론트와 VM의 Spring API. P0-03의 Next 서버 호출과 초기 P0-04의 Web 컨테이너 구성은 이 구상과 불일치. Next를 정적으로 출력하고 브라우저에서 API를 호출하도록 수정 필요.

## 포함 범위

- Next 정적 출력과 `/ken-blog` 프로젝트 경로 지원. Next 서버·Web Docker 제거.
- 브라우저에서 공개 API 주소로 상태 조회. 공개용 환경변수는 빌드 시 반영됨을 문서화.
- 정상·미설정·오류·시간 초과의 안내와 응답 검증 유지. API 비밀값을 공개 변수에 넣지 않음.
- Spring은 Buildpacks JVM 이미지로 생성. VM의 API 단독 Compose, 로컬 접근 포트와 메모리 제한 구성.
- Spring CORS는 지정한 프론트 origin의 공개 GET 요청만 허용. 현재 인증 정보 전달 없음.
- 현재 구현과 후속 MySQL·Redis·OCI Object Storage를 구분한 공식 아이콘 기반 라이트·다크 도면.
- Next의 정적 산출물을 GitHub Pages에 배포하고 홈에 임시 아키텍처 표시.
- 실제 이미지·CORS·로컬 두 origin의 브라우저 요청·Pages 공개 응답·메모리 검증.

## 제외 범위와 남은 연결

현재 공개 API 도메인·HTTPS 주소 없음. 이번에는 도메인 구매·임의 터널 공개·인증서 발급·기존 운영 서비스 교체 없음. Pages는 API 미설정 안내로 배포하고 공개 HTTPS API 주소 연결은 후속 작업으로 남김.

DB·로그인·Redis·첨부파일 연동, Native Image 전환, 완성된 블로그 디자인 포함하지 않음. 로그인 쿠키·세션 정책은 실제 프론트와 API 도메인 확정 후 인증 단계에서 설계.

## 검증 방법

ARM64·24GB VM에서 API 단독 컨테이너를 기존 포트 8080과 분리해 실행. 빌드·테스트·허용/거부 origin의 CORS·실제 브라우저 교차 출처 요청 확인. 공개 배포 전 API 주소 없는 정적 산출물로 재빌드. 생성한 컨테이너만 종료하고 기존 서비스·데이터 유지.

컨테이너 제한과 유휴·가벼운 부하의 실측 결과 기록. DB 등을 포함한 전체 블로그의 4GB 운영 적합성은 후속 검증 대상.

## 로컬 검증 결과

실제 검증일: 2026-09-25.

- Kotlin API 통합 테스트 15개, Web 테스트 7개·타입 검사·정적 export 통과.
- Buildpacks의 ARM64 JVM 이미지 재생성 성공. API 단독 Compose의 1 GiB 제한에서 기동·상태 응답 확인.
- Pages·로컬 origin의 GET 응답은 허용 헤더 포함. 다른 origin과 POST 사전 요청은 403 확인. CORS는 API 인증을 대체하지 않음.
- 로컬 정적 페이지의 `/ken-blog/`와 브라우저 → API 요청 확인. API 중지 시 화면 유지·연결 실패 안내, 예상된 연결 거부 1건 외 처리되지 않은 페이지 오류 없음.
- API 주소 미설정 정적 빌드에서 API 요청 0건·미설정 안내·페이지 오류 없음 확인.
- 유휴 API 메모리 185.1~185.2 MiB. 상태 GET 400회·동시 작업자 4개·약 10.5초 중 표본 188.2~192.2 MiB, 400회 성공. 세부 조건은 [런타임 안내](../../docs/runtime.md)에 기록.
- 검증용 API 컨테이너 정리. 기존 앱·Redis 서비스 유지.
- 공개 HTTPS API 연결은 주소 미확정으로 수행하지 않음. 공개 프론트의 실제 API 연결은 후속 항목.

- 실제 Chromium의 밝은·어두운 화면에서 해당 SVG 선택·JS 6개 로드 확인. API 요청·페이지 오류·콘솔 오류·실패 요청 각각 0건. 브라우저 종료.
- 공개 홈의 제목과 API 미설정 안내 확인. 공개 HTTPS API 연결은 이번 완료 범위에 포함하지 않음.
