이 글은 목록·코드 블록·시리즈 탐색을 확인하기 위한 QA용 예시입니다.

## 먼저 정할 문제

정렬된 배열에서 찾는 값보다 작은 원소와 크거나 같은 원소의 경계를 찾는다. 탐색 구간을 반열린 구간으로 표현하면 빈 구간과 배열 끝 위치를 같은 규칙으로 다루기 쉽다.

한 번에 큰 기능을 만들기보다 입력, 처리 규칙, 출력을 나누어 작은 예제로 확인한다. 정상 입력에서의 결과를 적은 다음 빈 입력과 경계값을 넣어 규칙이 일관적인지 살펴본다.

## 실행 가능한 작은 예제

```python
def lower_bound(values, target):
    left, right = 0, len(values)
    while left < right:
        middle = (left + right) // 2
        if values[middle] < target:
            left = middle + 1
        else:
            right = middle
    return left

print(lower_bound([1, 3, 3, 7], 3))  # 1
```

코드를 읽을 때는 각 변수에 어떤 값이 들어 있는지 직접 적어 보는 편이 좋다. 반복문이 있다면 첫 번째 반복, 중간 반복, 마지막 반복을 따로 따라가면서 상태가 언제 바뀌는지 확인한다.

## 입력과 출력의 경계

| 점검 대상 | 확인할 내용 | 기록 방법 |
| --- | --- | --- |
| 빈 입력 | 결과를 만들 수 있는가 | 빈 배열 또는 빈 문자열 |
| 원소 하나 | 첫 값과 마지막 값이 겹치는가 | 가장 작은 정상 입력 |
| 반복된 값 | 같은 값의 순서가 중요한가 | 중복을 포함한 입력 |
| 경계 위치 | 마지막 원소 다음 위치가 가능한가 | 범위를 벗어나기 직전 |

### 정상 입력부터 추적하기

주석에 적힌 출력은 위 예제의 입력에 대한 결과다. 입력을 하나씩 바꾸면서 결과가 달라지는 이유를 설명할 수 있어야 한다. 출력만 맞는지 확인하는 대신 중간 상태도 함께 관찰하면 잘못된 가정을 찾기 쉽다.

## 자주 놓치는 조건

결과는 값 자체가 아니라 삽입할 수 있는 위치다. 모든 값보다 큰 대상을 찾으면 배열 길이가 반환되므로 바로 인덱싱하지 않는다.

### 책임을 작게 나누기

이 글의 코드는 자료구조와 제어 흐름을 보여 주기 위한 작은 예제다. 저장, 인증, 여러 요청 사이의 동시 실행은 별도 설계가 필요하다. 예제에 없는 조건을 암묵적으로 보장한다고 가정하지 않는다.
