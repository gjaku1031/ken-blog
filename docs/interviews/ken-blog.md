# ken-blog: 인터뷰 요약

문서를 쓰며 확인한 사실과 판단의 이유를 정리한 기록. 블로그에는 게시하지 않음. 마지막 정리 2026-10-11.

## 개발 형태

- 개인 프로젝트(1인)

## 직접 정한 것

2026-10-08에 확인한 목록.

- Redis를 쓰지 않음
- Next.js 대신 정적 페이지로 열람 화면을 만듦
- 글을 posts·projects·series로 나눈 구조
- OCI 인프라 구조
- 웹 편집기에서 Git 원고 관리로 전환
- Native 이미지 대신 일반 JVM으로 실행
- 관리자 계정은 DB에 직접 등록
- 분류를 2단계로 줄임
- 업로드 기능을 없앰
- 배포 버튼 방식
- 정적 생성의 효과를 실측으로 확인하기로 함

## 판단의 이유

- **Git 원고 관리로 전환**: 원고의 변경을 diff로 검토하고 이력을 추적하기 위함
- **정적 생성**: 전환 전에는 문서를 불러올 때 API 왕복이 많아 느렸고, 전환한 뒤 체감 개선이 컸음. 그래서 측정으로 확인하기로 했음
- **핵심 문제 P1~P3의 대안**: 모두 직접 비교했음. 대안을 제외한 이유 가운데 "DB 이력 테이블은 diff 화면과 되돌리기를 따로 만들어야 함", "쓰기 잠금은 빌드 동안 관리 기능이 멈추고 잠금 해제를 보장해야 함"은 구조에서 도출한 설명을 확인받은 것
- **jOOQ와 QueryDSL 비교에서 Criteria API를 뺀 이유**: 코드가 복잡해지고 유지보수가 어려움
- **대문의 기술 표에서 Java·Spring Boot·JPA 행을 뺀 이유**: 주력 스택이라 따로 고른 이유가 없음
- **문제 해결 글의 공통 응답 수정**: 수정 범위는 직접 승인했음

## 문서 방향으로 정한 것

- 대문 링크는 GitHub만 둠
- 헤더의 기술 배지는 Spring Boot, MySQL, Oracle Cloud 3개
- 일본 리전을 쓴다는 사실은 적음
- 통과 기준 없이 한 번 잰 JVM 부하 측정은 실험이 아니라 결정의 검증 근거로 서술함
