# P3-01 API/DTO contract draft (2026-09-27; implementation pending)

## Storage and routing
- `posts.section`: `TECH | PROJECT_HOME | PROJECT_DOC` (legacy default TECH). `posts.project_id` for HOME/DOC; `posts.related_project_id` optional TECH; `posts.document_order` for DOC.
- `projects`: published metadata `{id,slug,name,status:PLAN|DEV|MAINT|DONE,startPeriod,endPeriod,overview,visibility:PUBLIC|PRIVATE,homePostId,createdAt,updatedAt}`. New project exists only after the HOME editor draft publishes. The cover Post title/slug are kept equal to project name/slug by one publish transaction. A project with an unpublished HOME is absent from public navigation.
- Browser routes: `/projects/` list; `/project/?slug=<projectSlug>` cover; `/project/?slug=<projectSlug>&doc=<documentSlug>` document. Existing `/post/?slug=` TECH remains. Direct `/api/v1/posts/{slug}` for HOME/DOC returns `section`/`projectSlug`, allowing browser redirection to the project route; project visibility is checked first.

## Public reads
- `GET /api/v1/projects?page=0&size=12` (size 1..100): `{items:ProjectSummary[],page,size,totalElements,totalPages}`. Summary `{id,slug,name,status,startPeriod,endPeriod,overview,documentCount,relatedTechCount}`. SQL filters HOME PUBLISHED and project visibility before counts; guest never receives PRIVATE projects/counts.
- `GET /api/v1/projects/{slug}`: `{locked,project,home,documents,relatedTech,relatedTechCount}`. Readable project has `project:{id,slug,name,status,startPeriod,endPeriod,overview,visibility}`, `home:{id,title,slug,body,publishedDate,attachmentIds? no}`, `documents:[{id,title,slug,order,publishedDate,locked}]`, `relatedTech` first 5 body-free summaries and total readable count. Guest PRIVATE project returns a minimal locked response (name/slug only; no overview, document/title/list, Tech relation, body, attachment IDs). If guest opens a DOC under PRIVATE parent through `/api/v1/posts/{slug}`, return 404; PUBLIC parent + PRIVATE DOC may return existing minimal locked post DTO.
- `GET /api/v1/posts/{slug}` gains `section`, `projectSlug` nullable and `documentOrder` nullable. For PROJECT_DOC/HOME, both project and post must permit body access; PROJECT body bypasses Redis. Existing Tech feed/filter/count and `/post/` stay TECH-only.
- Existing `GET /api/v1/posts/{postId}/attachments/{attachmentId}/content` checks HOME/DOC project visibility + published HOME before object read. No public bucket or presigned URL.
- Wiki READABLE gains `section` and `projectSlug?`; old `id/title/slug` stay. TECH and PROJECT_DOC candidates precede PROJECT_HOME candidates; within tier first publishedAt/id. `LOCKED/MISSING` still omit destination metadata. For HOME route use projectSlug; DOC route use projectSlug + document slug. Title-search and backlinks use same canonical/permission logic and return section/projectSlug on readable items. PROJECT source backlinks require parent visibility. All source/target queries select no body.

## Administrator writes and editor snapshots
- Existing `/api/v1/admin/posts` POST/PUT/publish/unpublish/delete remain TECH-only; raw operations on HOME/DOC return 409. Project content uses `/api/v1/admin/editor-drafts` create/update/publish/delete with existing revision and post/body-baseUpdatedAt rules. `section` is immutable after draft creation.
- Draft create/update detail gets `section`, `projectId?` (HOME/DOC parent; null for new HOME), `relatedProjectId?` (TECH), `documentOrder?` (DOC), and `projectMetadata?` (HOME only: status,startPeriod,endPeriod,overview,visibility,baseProjectUpdatedAt?); title/slug for HOME mean project name/slug. TECH `categoryId/tags` retain existing behavior; HOME/DOC use null/[]; all retain body, attachmentIds, wikiTargets.
- New HOME draft has `postId:null`, `baseUpdatedAt:null`, `projectId:null`, complete projectMetadata. Publish creates Project + HOME Post and attachment/wiki declarations atomically. Existing HOME draft has both post baseUpdatedAt and projectMetadata.baseProjectUpdatedAt; publish locks project->post->draft, checks both versions, then changes cover body and metadata in one transaction. Draft updates never mutate published cover/metadata.
- New DOC draft selects an existing projectId and gets next document order; edit DOC keeps its projectId/order unless explicitly reordered by a dedicated route. Publish requires parent HOME PUBLISHED and valid project, locks project->post->draft; source DOC remains independently PUBLIC/PRIVATE under parent visibility. Deleting a project or parent unpublishing must not expose child DOC via direct post/wiki/attachment endpoints.
- TECH draft gains optional relatedProjectId snapshot; publish writes relatedProjectId with the body. Direct project links in Tech public responses appear only when the related project is readable; PRIVATE project name/slug/count are omitted for guest while TECH body remains readable.

## Errors and access
- ADMIN write endpoints require existing session/CSRF/origin and no-store. Public project/post/wiki reads follow existing guest vs USER/ADMIN role checks. Invalid section/IDs/period/status 400, absent project/post 404, stale base/revision/duplicate project slug/order/parent conflict 409, DB 503 ProblemDetail.
- Period accepts `YYYY` or `YYYY.MM` and validates month 01..12; end may be null. Status is distinct from Post publication status. Badge registry/UI deferred.

## Additional administrator/navigation routes (2026-09-27)
- `GET /api/v1/admin/projects?page=0&size=20` and `GET /api/v1/admin/projects/{id}`: all project metadata including `id,homePostId,updatedAt` for project picker and HOME editor base snapshot; ADMIN only, no-store. The detail includes home Post admin detail for editing.
- `DELETE /api/v1/admin/projects/{id}`: atomic project deletion (all HOME/DOC Posts and their DB links; OCI objects remain), ADMIN/CSRF; related TECH project FK becomes null. Existing editor drafts keep immutable snapshots but later publish conflicts.
- `DELETE /api/v1/admin/projects/{projectId}/documents/{postId}`: delete one DOC under locked parent; no generic post-delete bypass.
- `PUT /api/v1/admin/projects/{projectId}/documents/order` body `{postIds:[all current DOC IDs in desired order]}`: whole-list permutation, positions 1..N, parent-locked transaction, 409 stale list. No direct generic Post order mutation.
- `GET /api/v1/projects/{slug}/related-posts?page=0&size=5`: current readable TECH links page, max size 20; `{items,page,size,totalElements,totalPages}` body-free. Project private guest 404, private TECH filtered for guest.
- Project summary/detail documents include `visibility` only after project itself is readable. Document summaries include `visibility` and `locked` so PUBLIC project can show member-only documents without body. All project DTOs indicate `homePostId` and project `updatedAt` for ADMIN; guest access to public project may also include these non-sensitive IDs/timestamps.
