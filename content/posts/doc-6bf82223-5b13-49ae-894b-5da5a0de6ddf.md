인증·글 메타데이터·분류·시리즈 관리와 정적 빌드용 공개 데이터 계약. Markdown 본문은 Git에서 관리.

## 공통 계약

| 항목 | 계약 |
| --- | --- |
| 경로 기준 | 아래 경로는 Spring Boot API 서버 기준. 공개 블로그의 `/ken-blog/post/.../` 화면 주소와 구분 |
| 정상 JSON | 요청·응답은 `application/json`. 생성·변경 결과 DTO를 그대로 반환하며 공통 `data` 래퍼 없음 |
| 이미지 | 첨부는 JPEG·PNG, 기술 아이콘은 PNG 바이너리 응답 |
| 인증 | `KENBLOGSESSION` 쿠키를 사용하는 서버 세션. 관리자 경로는 ADMIN 필요 |
| 변경 요청 | 세션 쿠키와 현재 CSRF 토큰 필요. 로그인 POST에도 CSRF 적용 |
| 글 상태 | `DRAFT`, `PUBLISHED`. 공개 범위는 `PUBLIC`, `PRIVATE` 호환 값이 있으나 출간 API는 공개 출간 여부를 받음 |
| 날짜·시각 | 글 메타데이터 시각은 서버에서 UTC로 만든 `LocalDateTime`. JSON에 `Z`가 붙은 값으로 가정하지 않음. 공개 `publishedDate`는 한국 시간 기준 날짜 |
| 본문과 주소 | 본문은 API로 읽거나 수정하지 않음. 글 `slug`는 생성 시 지정할 수 있으나 메타데이터 수정 대상에서 제외 |

입력 JSON의 ID·제목·시각은 예시. `seriesId=7`은 해당 PROJECT 시리즈가 존재하는 조건. 호출 경로는 Spring 서버 기준.

## 인증과 CSRF

1. 쿠키를 보존하며 `GET /api/v1/auth/csrf` 호출. 응답의 `headerName`·`token` 사용.
2. 같은 쿠키와 CSRF 헤더로 로그인 요청. `password` 필수, `rememberMe` 생략 시 false.
3. 성공 후 변경된 세션 쿠키 저장. CSRF 토큰도 폐기되므로 다시 발급.
4. 관리자 변경 요청에 새 토큰과 쿠키 전송. 교차 출처 브라우저 요청은 허용 origin과 `credentials: "include"` 필요.
5. 로그아웃 성공은 본문 없는 204. 다음 로그인도 CSRF 발급부터 시작.

계정명은 서버의 단일 관리자 설정 사용. 호환용 요청 `username`은 무시. 로그인·현재 사용자 응답은 `{ "username": 문자열, "role": "ADMIN" }`.

일반 세션의 비활동 한도 8시간, 유지 로그인 30일. CSRF 거부는 403, 세션 부재는 인증 경로에서 401. CORS 거부 시 브라우저가 오류 본문을 읽지 못할 수 있음.

## 글 생성

`POST /api/v1/admin/posts` 요청:

```json
{
  "title": "ken-blog 프로젝트 소개",
  "slug": "ken-blog-overview",
  "summary": "개발 기록과 프로젝트 문서를 정리하는 개인 블로그",
  "categoryId": null,
  "tags": ["Kotlin", "Spring Boot"],
  "seriesId": 7,
  "order": 1,
  "relatedSeriesId": null,
  "attachmentIds": [],
  "wikiTargets": []
}
```

성공은 `201 Created`, `Location: /api/v1/admin/posts/101`, `Cache-Control: no-store`. 원고는 반환된 slug로 별도 작성.

```json
{
  "id": 101,
  "title": "ken-blog 프로젝트 소개",
  "slug": "ken-blog-overview",
  "createdAt": "2026-10-04T18:00:00",
  "updatedAt": "2026-10-04T18:00:00",
  "status": "DRAFT",
  "visibility": "PUBLIC",
  "publishedAt": null,
  "category": null,
  "tags": ["Kotlin", "Spring Boot"],
  "attachmentIds": [],
  "wikiTargets": [],
  "series": {
    "id": 7,
    "slug": "ken-blog",
    "name": "ken-blog",
    "kind": "PROJECT"
  },
  "seriesOrder": 1,
  "relatedSeriesId": null,
  "summary": "개발 기록과 프로젝트 문서를 정리하는 개인 블로그",
  "editVersion": 0,
  "section": "PROJECT"
}
```

분류 지정 시 `category`는 `id, path, name, depth, sortOrder` 포함. `section`은 소속 시리즈 종류에서 계산하며 미소속은 TECH. `visibility=PUBLIC`이어도 DRAFT이면 공개 대상에서 제외.

| 생성 필드 | 허용 값과 생략 의미 |
| --- | --- |
| `title` | 필수 문자열. 앞뒤 공백 제거 후 1~200 Unicode 코드 포인트 |
| `slug` | 선택 문자열. 생략·null이면 서버에서 `post-UUID` 생성. 소문자화 후 160자 이하, 영소문자·숫자와 단어 사이 하이픈 |
| `summary` | 생략·null이면 빈 문자열. 공백 제거 후 최대 120 코드 포인트 |
| `categoryId` | 양수 정수 또는 null. 지정 시 존재하는 분류 필요 |
| `tags` | 생략하면 빈 배열, null 불가. 태그는 공백 제거 후 1~40 코드 포인트, 제어 문자 금지. 대소문자 무관 중복 제거 후 최대 16개, 첫 표시 철자·입력 순서 유지. 생성 JSON 배열 자체는 최대 100개 |
| `seriesId` | 존재하는 시리즈의 양수 ID 또는 null |
| `order` | 양수 정수 또는 null. 순서를 지정하려면 시리즈 또는 분류 소속 필요 |
| `relatedSeriesId` | PROJECT 시리즈 ID 또는 null |
| `attachmentIds` | 생략·null이면 빈 배열. 입력 최대 100개 양수 ID, 중복 제거·정렬 후 READY 첨부 연결 |
| `wikiTargets` | 생략·null이면 빈 배열. 최대 128개 제목, 각각 1~200 코드 포인트. 입력 순서로 중복 제거 |

`body`, `bodySha256` 등 알 수 없는 키는 거부. 위키 제목의 `[`, `]`, `|`와 제어 문자 금지.

## 글 편집과 충돌

`PATCH /api/v1/admin/posts/101/metadata`는 다음 8개 키 모두 필수. 일부 필드만 전송하는 PATCH는 미지원.

```json
{
  "baseVersion": 0,
  "title": "ken-blog 프로젝트 소개",
  "summary": "Git 원고와 관리 API를 연결해 프로젝트 문서를 발행하는 개인 블로그",
  "categoryId": null,
  "tags": ["Kotlin", "Spring Boot", "MySQL"],
  "seriesId": 7,
  "order": 1,
  "relatedSeriesId": null
}
```

글 잠금 안에서 `baseVersion`과 현재 `editVersion` 비교. 일치하면 메타데이터와 관계를 한 트랜잭션으로 저장하고 버전 증가. 응답은 200과 전체 상세 DTO.

`baseVersion`은 0~9,007,199,254,740,991의 JSON 정수. 누락·null·문자열·음수 거부. 다음 편집에는 서버 응답의 새 버전 사용.

서버 버전이 1인데 `baseVersion=0`으로 요청하면 409. 오류 주요 필드:

```json
{
  "title": "Conflict",
  "status": 409,
  "detail": "다른 변경이 저장되었습니다. 입력을 복사한 뒤 글을 다시 열어 확인하세요."
}
```

사용자 입력을 보존한 뒤 최신 상세와 비교. 버전만 바꿔 자동 재전송하지 않음.

| 변경 경로 | 충돌 기준 | 글 `editVersion` 증가 |
| --- | --- | --- |
| 글 `metadata`, `series`, `order` | 필수 `baseVersion` 비교 | 증가 |
| 글 `publication` | `baseVersion` 입력 없음, 명시 상태 저장 | 증가 |
| 글 `attachments`, `wiki-links` | 버전 비교 없이 선언 전체 교체 | 해당 서비스에서 증가시키지 않음 |
| 시리즈 `metadata` | 조회한 `updatedAt`을 `baseUpdatedAt`으로 비교 | 글 버전과 별도 계약 |

## 발행 상태

`PUT /api/v1/admin/posts/101/publication`은 `{ "published": true }` 또는 false 한 필드만 허용. 성공 200과 상세 DTO. true는 `PUBLISHED + PUBLIC`, false는 `DRAFT`로 전환. 최초 발행 시각은 취소 후에도 보존.

같은 상태 요청도 편집 버전 증가. 원고 파일 존재 검사와 Pages 배포는 이 API의 처리 범위 밖.

## null·생략·빈 값

| 요청 위치 | 생략 | null | 빈 배열·빈 문자열 |
| --- | --- | --- | --- |
| 글 생성 `tags` | 빈 목록 | 400 | `[]`로 태그 없이 생성 |
| 글 생성 `attachmentIds`, `wikiTargets` | 빈 목록 | 빈 목록 | `[]`로 선언 없이 생성 |
| 글 편집 8개 키 | 하나라도 누락하면 400 | `categoryId`, `seriesId`, `order`, `relatedSeriesId`에만 허용 | `tags: []`로 전체 해제, `summary: ""`로 요약 비움 |
| 첨부 교체 `attachmentIds` | 400 | 400 | `[]`로 전체 연결 해제 |
| 위키 교체 `wikiTargets` | 400 | 400 | `[]`로 전체 선언 해제 |
| 분류 전체 정렬 `parentId` | 400 | 최상위 분류의 형제 집합 | `ids: []`는 해당 형제가 실제로 없는 경우에만 집합 일치 |
| 시리즈 수정 `baseUpdatedAt` | 409 | 409 | 빈 문자열은 시각 파싱 실패로 400 |

생성의 선택 선언과 교체 요청의 필수 선언을 구분. 첨부·위키 교체는 빈 배열로 전체 해제.

## 목록·분류·시리즈

관리자 글 목록은 `page=0`, `size=20` 기본. `page >= 0`, `1 <= size <= 100`, `page × size <= 2,147,483,647`. 정렬은 `updatedAt DESC, id DESC` 고정. 초안 포함.

```json
{
  "items": [],
  "page": 0,
  "size": 20,
  "totalElements": 0,
  "totalPages": 0
}
```

`items`는 상세 DTO에서 `attachmentIds`, `wikiTargets`를 제외한 요약 정보. 관리자 전체 스냅샷은 페이지 래퍼 없는 배열이며 10,000건·8,000,000바이트 상한 초과 시 실패.

| 조회 | 응답·정렬 계약 |
| --- | --- |
| 시리즈 목록 | `sortOrder ASC, id ASC`. 각 원소는 `id, slug, name, kind, description, visibility, projectStatus, startPeriod, endPeriod, sortOrder, updatedAt, cover, postCount, stackBadges` |
| 시리즈 상세 | `{ series, posts }`. `posts` 원소는 `id, title, slug, order, published`. 저장 순서 오름차순(null 마지막), 출간 시각 오름차순(null 마지막), ID 오름차순 |
| 분류 트리 | 분류 참조에 `directCount`, `totalCount`, `children` 추가. 초안·빈 분류 포함. 형제는 숫자 순서·ID 기준 |
| 태그 사용량 | `{ name, count }` 배열. 사용량 내림차순, 이름 오름차순 |
| 기술 목록 | `{ id, name, imageUrl }` 배열 |
| 위키 제목 검색 | `q`는 정확히 한 번, 공백 제거 후 1~200 코드 포인트. `{ items, exact }`, 부분 제목 후보는 최대 7개. `exact.status`는 `READABLE` 또는 `MISSING` |

### 시리즈 생성·변경

```json
{
  "slug": "ken-blog",
  "kind": "PROJECT",
  "metadata": {
    "name": "ken-blog",
    "description": "개발 기록과 프로젝트 문서를 발행하는 개인 블로그",
    "projectStatus": "DEV",
    "startPeriod": "2026.09",
    "endPeriod": null,
    "stackBadgeNames": []
  }
}
```

종류는 TECH 또는 PROJECT. PROJECT의 상태·시작 기간 필수. 상태는 `PLAN / DEV / MAINT / DONE`, 기간은 `YYYY.MM`, 종료는 시작 이후 또는 같은 월. TECH는 프로젝트 상태·기간·기술 선택 미지원.

수정은 `PUT /api/v1/admin/series/{id}/metadata`로 metadata 객체 자체 전송. 조회한 `updatedAt`을 `baseUpdatedAt`으로 추가. 필드 생략은 기존 값 유지가 아닌 기본값·null 대체. 생성에는 `baseUpdatedAt` 제외.

이름 1~200, 설명 최대 1,000 코드 포인트. 기술 이름 최대 30개. 종류와 slug 변경 미지원.

### 분류 생성·정렬

생성 입력 `{ "path": "Backend/Spring" }`. 각 단계 1~60 코드 포인트, 전체 1~2단계. 이름 변경은 path를 유지.

전체 정렬은 `{ "parentId": null, "ids": [12, 4, 9] }`처럼 현재 전체 형제 ID를 원하는 순서로 전송. 일부만 보내거나 집합이 바뀌면 충돌. 분류·시리즈의 개별 order는 부호 있는 32비트 정수, 글 order는 양수 또는 null.

## 프로젝트 관련 Posts 설정

일반 글 생성·편집의 `seriesId`는 null 또는 TECH 시리즈 ID, `relatedSeriesId`는 연결할 PROJECT 시리즈 ID. 프로젝트 상세 문서는 `seriesId`에 PROJECT ID 지정.

소속만 변경하는 `/series` 요청도 `baseVersion`, `seriesId`, `order`, `relatedSeriesId` 네 키 필수. 관련 연결을 해제하려면 `relatedSeriesId: null`. 실제 ID는 관리자 시리즈 목록에서 조회.

## 공개 스냅샷·이미지

스냅샷 최상위 필드는 `version: 3`, `posts`, `navigation`, `series`, `categories`, `revision`. 글은 `id, title, slug, summary, publishedDate, section, category, tags, series, relatedSeries, legacyPath, publishedAt` 포함. Markdown 본문은 제외.

글의 시리즈 참조는 `id, slug, name, kind, position, navigationKey`. 문서 목록은 `navigation[navigationKey]`에 한 번 저장하고 각 항목은 `id, slug, title, order`로 표현. position·탐색 order는 1부터 시작하는 화면 위치.

공개 조건은 `PUBLISHED + PUBLIC`, 내부 호환 `section=TECH`, 소속 시리즈 공개 여부. categories는 공개 글이 사용하는 분류와 부모만 포함. 응답 `Cache-Control: no-store`. revision 추가 전 JSON 상한 7,999,800바이트.

revision은 메타데이터·첨부 상태의 SHA-256. Git 원고 해시와 별개.

| 이미지 경로 | 조건 | 응답 |
| --- | --- | --- |
| 글 첨부 | 공개 글·공개 시리즈·연결·READY | PNG/JPEG, inline, nosniff, private/no-store, Content-Length |
| 기술 아이콘 | 등록한 아이콘 파일 | PNG, public/max-age=300 |

공개 첨부의 미존재·접근 불가는 동일한 404. 저장소 문제·실제 파일 크기 불일치는 503. 현재 파일 업로드 경로 없음.

## 오류 계약

MVC와 인증·권한 오류는 `application/problem+json`. 주요 필드 `title`, `status`, `detail`; MVC 응답에는 `instance`가 추가될 수 있음. 일부 서버 오류는 로그 대조용 `eventId` 포함. 별도 업무 오류 code 필드는 없음.

| 상태 | 대표 조건 | 호출자 처리 |
| --- | --- | --- |
| 400 | 필수 키·타입·정수 범위·태그·위키 제목 등 입력 위반 | 입력·본문 형식 수정 |
| 401 | 로그인 자격 증명 실패, 인증 필요한 요청의 세션 부재 | 로그인 상태 재확인 |
| 403 | ADMIN 권한 부족, CSRF 거부 | 권한·세션·CSRF 발급 순서 확인 |
| 404 | 글·분류·시리즈 미존재, 공개 첨부 조건 불충족 | 오래된 참조 여부 확인 |
| 409 | 글 주소 중복, 오래된 편집 버전, 시리즈 수정 충돌, 참조가 남은 시리즈 삭제, 분류 집합 충돌 | 원인별로 주소 변경 또는 최신 자료 재조회 |
| 405 / 406 / 415 | 미지원 메서드 / 응답 형식 / 요청 미디어 타입 | 메서드·Accept·Content-Type 수정 |
| 429 | 로그인 시도 제한 | 재시도 중단 후 나중에 다시 시도 |
| 500 | 예상하지 못한 오류·일부 스냅샷 상한 검사 실패 | `eventId`가 있으면 운영 기록과 대조 |
| 503 | DB 연결 실패·이미지 저장소 문제 등 | 서비스 상태 확인 후 재시도 판단 |

CORS 거부와 이미 전송을 시작한 이미지 오류는 동일한 JSON 응답을 보장하지 않음.
