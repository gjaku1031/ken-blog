관리 화면이 쓰는 관리 API와 사이트 빌더가 쓰는 공개 API의 계약. 본문은 API에 두지 않고 Git 원고로만 다루며(P1), 공개 스냅샷 API가 정적 사이트의 유일한 DB 입력(P3). 구성 요소와 일관성 보장 범위는 [아키텍처](/ken-blog/post/doc-340352c9-5fde-4bae-bc0b-4ecd744719a8/), 작업별 충돌 정책은 [기능과 사용자 흐름](/ken-blog/post/doc-4cfccbd2-1972-4ad8-893a-6a8bf45744e1/)에서 다룸.

## API 설계 원칙

| 결정 | 내용 | 이유·대가 |
| --- | --- | --- |
| 본문 경로 없음 | 글 API는 제목·분류·소속 등 메타데이터만 다루고, 본문을 읽거나 저장하는 경로를 두지 않음. 본문이 담긴 키를 보내면 400 | 본문 변경을 Git 커밋으로만 남김(P1). 웹에서 본문을 고칠 수 없음 |
| 세션 쿠키와 CSRF | 로그인하면 서버 세션을 만들고, 변경 요청마다 CSRF 토큰을 확인함 | 관리자 한 명이 브라우저로만 쓰는 API라, 서버에서 즉시 폐기할 수 있는 세션을 선택함. 대가는 CSRF 처리와 교차 출처 쿠키 설정 |
| 편집은 전체 교체 | 글 정보 편집은 `PUT`으로 `baseVersion`과 편집 필드 7개를 모두 받음. 일부 필드만 보내는 요청은 400 | 생략과 null을 구분하지 않아도 되는 단순한 계약. 화면은 바꾸지 않은 필드도 함께 보내야 함 |
| 발행은 별도 경로 | 발행·발행 취소는 `{ "published": 불리언 }` 하나만 받는 경로로 분리 | 글 정보 저장이 공개 상태를 바꾸지 않음 |
| 낙관적 동시성 제어 | 편집 요청에 조회한 편집 버전을 담고, 서버 버전과 다르면 409 | 앞선 저장을 덮어쓰지 않음. 화면이 버전을 들고 있어야 함 |
| 표준 오류 형식 | 모든 오류를 `application/problem+json`(RFC 9457)으로 반환. 별도 업무 오류 코드 없음 | 호출자는 상태 코드로 분기 |
| 빌드용 공개 스냅샷 | 공개 글 정보·탐색 목록·revision을 한 트랜잭션에서 읽어 한 번에 반환 | 빌더가 한 시점의 자료로 페이지를 만들고 revision으로 변경을 감지함(P3). 응답이 커서 크기 상한을 둠 |

> 관리 API는 글 정보와 발행 상태만 바꾸고, 공개 사이트는 공개 스냅샷 한 번의 응답으로 만들어짐.

## 편집 계약과 충돌

```json
{
  "baseVersion": 3,
  "title": "아키텍처",
  "summary": "Git 원고와 DB 글 정보를 결합해 발행하는 구조",
  "categoryId": null,
  "tags": ["Architecture"],
  "seriesId": 16,
  "order": 2,
  "relatedSeriesId": null
}
```

`PUT /api/v1/admin/posts/{id}/metadata`의 요청. 서버는 글 행을 잠근 뒤 `baseVersion`과 현재 편집 버전을 비교하고, 같으면 글 정보·소속·순서·태그를 한 트랜잭션으로 저장한 뒤 버전을 올림. 다르면 아래 응답으로 거부함.

```json
{
  "title": "Conflict",
  "status": 409,
  "detail": "다른 변경이 저장되었습니다. 입력을 복사한 뒤 글을 다시 열어 확인하세요."
}
```

소속 시리즈와 관련 프로젝트를 함께 바꿀 때는 두 시리즈 행을 ID 오름차순으로 잠근 뒤 글 행을 잠금. 두 요청이 같은 시리즈 쌍을 반대 순서로 잠가 생기는 교착 상태를 막기 위함. 관련 프로젝트에는 PROJECT 시리즈만 지정할 수 있음.[* 프로젝트 문서는 `seriesId`에 PROJECT 시리즈를, 트러블슈팅·실험 글은 `relatedSeriesId`에 PROJECT 시리즈를 지정하는 것이 사용 관례. `seriesId`의 시리즈 종류는 서버가 검사하지 않음]

시리즈 정보는 편집 버전 대신 조회한 수정 시각을 `baseUpdatedAt`으로 보내 비교함. 작업별 충돌 정책은 [기능과 사용자 흐름](/ken-blog/post/doc-4cfccbd2-1972-4ad8-893a-6a8bf45744e1/), 버전 비교와 행 잠금의 원리는 [아키텍처](/ken-blog/post/doc-340352c9-5fde-4bae-bc0b-4ecd744719a8/)에서 다룸. ## 공개 스냅샷과 이미지

공개 스냅샷은 빌더와 관리 화면의 배포 대기 비교가 함께 쓰는 계약. 최상위 필드는 `version`, `posts`, `navigation`, `series`, `categories`, `revision`이고 본문은 없음.

- 글마다 같은 시리즈의 문서 목록을 반복하지 않고, `navigation`에 시리즈별로 한 번만 담은 뒤 글은 키로 참조함. 문서 수에 비례해 응답이 제곱으로 커지는 것을 막기 위함.
- `categories`에는 공개 글이 쓰는 분류와 그 부모만 담음.
- `revision`은 공개 글 정보와 첨부 상태로 계산한 SHA-256. 빌더는 이 값을 두 번 받아 비교함([아키텍처](/ken-blog/post/doc-340352c9-5fde-4bae-bc0b-4ecd744719a8/) 참조).
- Pages 출처의 교차 출처 GET은 자격 증명 없이 허용함. 빌드 요청에 쿠키가 실리지 않음.
- 응답은 `no-store`이며, JSON이 약 8MB를 넘거나 글이 10,000건을 넘으면 실패함.

| 이미지 | 제공 조건 | 응답 |
| --- | --- | --- |
| 글 첨부 | 발행·공개된 글에 연결된 READY 첨부 | PNG·JPEG, `private, no-store`, `nosniff` |
| 기술 아이콘 | 등록한 아이콘 파일 | PNG, `public, max-age=300`, `nosniff` |

공개 조건을 만족하지 않는 첨부는 존재하지 않는 첨부와 같은 404로 응답해 비공개 첨부의 존재를 드러내지 않음. 파일 업로드 경로는 없고 이미지 원본은 운영자가 서버 디스크에 둠. [스냅샷 서비스](https://github.com/gjaku1031/ken-blog/blob/3074d80/src/main/java/io/github/gjaku1031/kenblog/pages/PagesSnapshotService.java) · [HTTP 통합 테스트](https://github.com/gjaku1031/ken-blog/blob/3074d80/src/test/java/io/github/gjaku1031/kenblog/HttpApiIntegrationTest.java)

## 오류 계약

오류 본문은 `title`, `status`, `detail`을 담고, 예상하지 못한 서버 오류에는 운영 기록과 대조할 `eventId`를 더함.

| 상태 | 대표 조건 |
| --- | --- |
| 400 | 필수 키 누락, 타입·범위 위반, 알 수 없는 키 |
| 401 | 로그인 실패, 인증이 필요한 요청의 세션 없음 |
| 403 | ADMIN 권한 없음, CSRF 거부 |
| 404 | 글·분류·시리즈 없음, 공개 조건을 만족하지 않는 첨부 |
| 409 | 글 주소 중복, 오래된 편집 버전, 시리즈 수정 충돌, 참조가 남은 시리즈 삭제, 분류 형제 집합 불일치 |
| 405 / 406 / 415 | 지원하지 않는 메서드 / 응답 형식 / 요청 미디어 타입 |
| 429 | 로그인 시도 제한 |
| 500 | 예상하지 못한 오류, 스냅샷 크기 상한 초과 |
| 503 | DB 연결 실패, 이미지 저장소 문제 |

CORS 거부와 전송을 시작한 뒤의 이미지 오류는 JSON 본문을 보장하지 않음.

편집 요청은 `baseVersion`과 편집 필드 7개를 모두 보내야 하며, null은 `categoryId`, `seriesId`, `order`, `relatedSeriesId`에만 허용함.
