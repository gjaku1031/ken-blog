# 문서 작성 결정 기록

ken-blog 문서를 사용자와 검토하며 확정한 결정. 새 결정은 다음 번호로 추가하고, 바뀐 결정은 지우지 않고 '대체됨'으로 표시한 뒤 새 번호를 붙인다. 적용 범위가 '공통'인 결정은 다른 프로젝트 문서에도 그대로 적용한다.

| 번호 | 날짜 | 결정 | 이유 | 적용 범위 |
| --- | --- | --- | --- | --- |
| D-001 | 2026-10-07 | 독자는 CS 교수·시니어 개발자. 문서는 문제 정의 → 대안 비교 → 결정 → 검증으로 읽혀야 함 | 대학원 진학용 포트폴리오 | 공통 |
| D-002 | 2026-10-07 | 개발 배경에서 설계 제약과 핵심 문제 P1~Pn을 정의하고, 모든 문서가 P 번호로 연결 | 문서마다 "왜"가 흩어지지 않게 함 | 공통 |
| D-003 | 2026-10-07 | 대문은 흥미를 주고 상세 문서로 보내는 입구. P마다 문제·결정·대가·검증 요약, 대표 수치 표 1개, 핵심 결론 인용 1개 | 대문만 읽어도 흥미가 생겨 상세 문서로 넘어가게 함 | 공통 |
| D-004 | 2026-10-07 | 의사결정 문서가 P1~Pn 상세의 원본(검토한 대안 표·대가·검증). 대문은 요약과 링크 | 같은 내용을 두 곳에서 관리하지 않음 | 공통 |
| D-005 | 2026-10-07 | 상세 내용의 원본은 한 문서에만 두고 다른 문서는 요약과 링크 | 수정 시 불일치 방지 | 공통 |
| D-006 | 2026-10-07 | 문서 첫머리는 핵심 주장 한 줄. 요약 반복·메타 문장("~를 다룸") 금지. 대제목 바로 아래 중제목이 오지 않게 한 줄은 둠 | 목차가 구성을 대신하고, 첫 줄은 결론을 줌. 한 줄도 없으면 제목 아래가 어색함 | 공통 |
| D-007 | 2026-10-07 | 판단 기록은 목록으로, 대안·이유·조건은 들여쓴 하위 목록으로 | 굵은 머리말 문단 나열은 위계가 없어 안 읽힘 | 공통 |
| D-008 | 2026-10-07 | 범례·그림 설명은 캡션, 인용은 문서당 1~2회, 세부 수치·조건은 주석, 원자료는 접기 | 본문 흐름을 유지하면서 근거는 남김 | 공통 |
| D-009 | 2026-10-07 | 스크린샷은 페이지와 반대 테마로, 모의 데이터는 캡션에 명시 | 같은 테마면 페이지 안에 페이지가 겹쳐 오류처럼 보임 | 공통 |
| D-010 | 2026-10-07 | 사용자가 직접 정하지 않은 설계는 선택 이유를 쓰지 않고 사실만 씀. 본인 결정만 이유·대안 비교 | 포트폴리오의 기여를 과장하지 않음 | 공통 |
| D-011 | 2026-10-07 | 개요 표는 소개·목적·개발 형태·담당 범위·주요 기능·링크 6항목. 담당 범위는 표 아래 역할별 목록(본인을 판단 중심으로 맨 앞). 링크는 저장소만, 로고+이름 | 프로젝트 간 같은 형식, 본인 기여를 분명히 | 공통 |
| D-012 | 2026-10-07 | 아키텍처 문서: 품질 요구사항(P에 연결된 행만), 인프라 구성도, 시스템 구조(논리 계층), 데이터 정본, 일관성 보장 범위. 장애 영향 표·영속 계층 절은 넣지 않음 | 당연한 장애 서술과 별도 글로 다룰 기술 선택은 관심도가 낮음 | 공통 |
| D-013 | 2026-10-07 | 3계층과 다른 구조면 시스템 구조 절에서 경로별(열람·관리·빌드) 계층도로 차이를 보여 줌 | 일반 구조와의 차이가 설계 포인트 | 공통 |
| D-014 | 2026-10-07 | 기능 문서의 주요 흐름은 유저 플로우(flowchart TD). 시스템 간 호출 순서(시퀀스)는 아키텍처 문서에 둠 | 사용자 관점과 시스템 관점 분리 | 공통 |
| D-015 | 2026-10-07 | 도식은 원래 크기 이상 확대하지 않음(기준 14px, ERD 0.85배). 넓은 가로 흐름도는 TD로 | 작은 도식이 본문 폭으로 커지거나 넓은 도식 글자가 7px로 줄어드는 문제 | 공통 |
| D-016 | 2026-10-07 | 실험·트러블슈팅·개별 ADR은 Posts 글로 쓰고 관련 프로젝트로 연결. 프로젝트 문서 묶음에 넣지 않음 | 프로젝트 문서는 설계 설명, Posts는 개별 기록 | 공통 |
| D-017 | 2026-10-07 | 게시 전 코드·운영 DB와 대조하고, 다른 곳이 있으면 배포하지 않음 | 확인한 사실만 공개 | 공통 |
| D-018 | 2026-10-07 | 언어 전환 이력, 리전 선택 사정, 폐기 기능(MCP·RAG·위키 선언)은 쓰지 않음 | 현재 설계 판단과 무관 | ken-blog |
| D-019 | 2026-10-07 | 합의한 수정은 매번 Pages 배포와 공개 화면 확인까지 | 사용자가 블로그에서 직접 확인 | ken-blog |
| D-020 | 2026-10-07 | 정적 생성 측정 글은 사용자와 함께 공부하며 인터뷰·학습형으로 다룸 | 사용자가 내용을 직접 이해하고 설명할 수 있어야 함 | ken-blog |
